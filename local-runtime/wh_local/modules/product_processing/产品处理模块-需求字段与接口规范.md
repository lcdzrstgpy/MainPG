# 产品处理模块：需求字段、存储字段与接口规范

版本：`product-processing-contract-v2`  
上游合同：`data_collection` 当前正式模型  
适用目录：`local-runtime/wh_local/modules/product_processing/`

## 1. 文档目的

本文统一“每日选品/数据采集 → 产品处理”的字段、接口和存储规则。字段优先级如下：

1. `wh_local/data_collection/contracts.py` 与交接构造代码是上游正式合同；
2. 产品处理通过正式 handoff 接口消费数据，不直接修改数据采集表；
3. 项目早期提供的扁平 JSON 仅作为兼容输入，不作为新模块继续扩展的依据；
4. 尚未形成跨模块共识的字段必须保存在 `raw_payload`，不能擅自变更语义。

## 2. 模块边界

产品处理负责：

- 消费每日选品正式交接记录；
- 接收浏览器采集、人工单品和 Excel/CSV；
- 维护工作区隔离的草稿池；
- 草稿编辑、预检、批量处理和删除；
- 来源图片登记；
- 任务历史、恢复、重试、清除页面进度与结果下载；
- 生成店小秘 Excel、失败原因 CSV 和可选视频清单。

产品处理不负责：

- 搜索、去重、选品评分和风险判断；
- 覆盖上游 `criteria`、`selection_score`、`risk_tags` 或证据；
- 直接写入 `data_collection` 拥有的六张 SQLite 表；
- 在没有上游 ACK 接口时伪造 `handoff.status=consumed`。

## 3. 工作区和请求头

正式跨模块请求必须携带：

```http
X-Workspace-ID: <workspace_id>
```

- `workspace_id` 是租户/工作台隔离键，不得为空。
- 请求头、run 和 handoff 中的 `workspace_id` 必须一致，否则返回 `400`。
- 为兼容现有本地页面，未传请求头时暂时使用 `local`；跨模块正式联调不得依赖该默认值。
- 草稿唯一性为 `(workspace_id, candidate_id)`；任务幂等性为 `(workspace_id, Idempotency-Key)`。

## 5. 正式 handoff 交接

### 5.1 上游交接信封

`data_collection` 的确认接口返回 `DailySelectionHandoff[]`，单条字段如下：

| 字段 | 类型 | 说明 |
|---|---|---|
| `handoff_id` | string | 交接记录唯一标识 |
| `run_id` | string | 上游运行 ID |
| `candidate_id` | string | 候选商品 ID |
| `workspace_id` | string | 工作区 |
| `payload_json` | JSON string | 嵌套交接快照 |
| `status` | enum | `pending/consumed/failed` |
| `idempotency_key` | string | 上游交接幂等键 |
| `created_at` | ISO-8601 string | 创建时间 |

`payload_json` 的正式嵌套结构：

```json
{
  "candidate": {},
  "images": {
    "main": null,
    "gallery": [],
    "detail": [],
    "sku": []
  },
  "skus": [],
  "attributes": {},
  "source_evidence": [],
  "selection_metadata": {}
}
```

产品处理会解析上述结构，建立草稿，并将原始交接 JSON 与 SHA-256 摘要保存在 `raw_payload`，便于审计。

### 5.2 正式消费接口

```http
POST /product-processing/intake/daily-selection/handoffs
X-Workspace-ID: workspace-demo
Content-Type: application/json
```

请求：

```json
{
  "handoffs": [
    {
      "handoff_id": "handoff-id",
      "run_id": "run-uuid",
      "candidate_id": "1688:123456789",
      "workspace_id": "workspace-demo",
      "payload_json": "{...}",
      "status": "pending",
      "idempotency_key": "handoff-key",
      "created_at": "2026-08-03T12:00:00+00:00"
    }
  ]
}
```

响应关键字段：

| 字段 | 说明 |
|---|---|
| `contract_version` | `daily-selection-handoff-consumer-v1` |
| `consumer_status` | 本模块消费结果，当前成功值为 `consumed` |
| `received` | 收到的交接数量 |
| `created` | 新建草稿数量 |
| `replayed` | 幂等重放数量 |
| `receipts` | 本地消费回执 |
| `drafts` | 创建或复用的草稿 |
| `upstream_ack_required` | 固定为 `true`，表示仍需上游 ACK |

相同 `handoff_id` 或 `idempotency_key` 重放不会重复建草稿；相同工作区和候选 ID 也不会重复建草稿。

### 5.3 ACK 状态回写争议（待团队统一）

上游 README 约定：下游成功建草稿后，应把 handoff 标记为 `consumed`。但当前 `data_collection` 路由/仓储没有提供可调用的“列出待消费、认领、ACK consumed/failed”接口。

当前裁决：

- 产品处理只落本地 `product_processing_handoff_receipts` 回执；
- 响应返回 `upstream_ack_required=true`；
- 产品处理禁止越过模块边界直接更新上游 SQLite 表；
- 后续应由 `data_collection` 增加 ACK API，或由统一编排层完成状态回写；
- ACK API 未确定前，不能把本地 `consumer_status` 当成上游真实 `handoff.status`。

建议上游后续接口：

```http
POST /desktop/daily-selection/handoffs/{handoff_id}/ack
```

建议请求字段：`workspace_id`、`status=consumed|failed`、`consumer`、`consumer_receipt_id`、`error?`。

## 6. 字段差异、兼容规则与裁决

| 早期示例/争议字段 | 正式字段或裁决 | 当前兼容行为 |
|---|---|---|
| `run_id: integer` | `run_id: string` | 整数输入会转成字符串；输出和落库统一为 string |
| 缺少 `workspace_id` | 正式合同必须有 `workspace_id` | 旧本地调用默认 `local`；正式联调必须显式传入 |
| 顶层 `counts` | 调用计数属于 `metadata` | 读取后合并到 `metadata`，原 counts 保留为 `legacy_counts` |
| 顶层 `errors` | 错误属于 `metadata.errors` | 自动迁移到 `metadata.errors` |
| `reference_image_url: ""` | 正式未知值为 `null` | 旧值可接收，但新调用应传 `null` |
| `source_attributes: [{name,value,source}]` | 正式为 `{name:value}` | 自动转为映射；来源说明保存到 `raw_payload.legacy_attribute_sources` |
| `source_sku_id` | 正式为 `sku_id` | 作为校验别名接收；输出使用 `sku_id` |
| `min_order_quantity: "2"` | 正式为 integer | 纯数字字符串转为整数；非法值返回 `422` |
| SKU `stock` | 正式 SKU 合同未定义 | 作为额外字段保留，不作为跨模块必需字段 |
| `captured_fields: object` | 正式为 string[] | 转成对象键名列表，原对象保存到 `raw_payload.legacy_captured_fields` |
| `selection_filtered: boolean` | 正式使用 `status=filtered` | `true` 且 status 为 candidate 时映射为 filtered |
| `main_image_url: ""` | 正式为 string/null | 新数据应传 `null`；空串只作为旧输入处理 |
| `counts.employee_duplicate_count` | 上游正式 metadata 暂无固定键 | 作为 metadata 扩展保留，不建立专用列 |

以下字段存在于早期示例，但不属于当前 `data_collection` 正式跨模块合同：

- `source_product_id`
- `price_text`
- `selection_keyword`
- `selection_query`
- `selection_collection_mode`
- `selection_scope`
- `selection_result_type`
- `search_rank`
- `selection_level`
- `source_sku_capture_complete`
- `captured_at`
- `selection_filtered`
- SKU 的 `stock`

裁决：这些字段允许作为向前兼容扩展进入 `raw_payload`，不得设为正式接口必填字段。若团队以后需要筛选、唯一约束或跨表关联，必须先更新 `data_collection` 正式合同，再升级本规范版本。

### 9.3 处理任务

`POST /drafts/process` 主要请求字段：

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `draft_ids` | integer[] | 必填 | 本工作区待处理草稿 |

快捷入口：

- `POST /engine/batch`、`/engine/quick`、`/import`：multipart 文件直接处理；
- `POST /engine/single`：单商品字段和可选图片；
- `GET /tasks/history`：历史任务；
- `GET /tasks/{id}/outputs`、`/summary`：结果；

- `GET /tasks/{id}/download?kind=dxm|errors|video_manifest`：下载；
- `POST /tasks/{id}/download-form`：表单下载兼容接口。

任务状态：`queued -> running -> completed|partial_failure|failed`，并支持 `paused`。清除进度只设置页面恢复标记，不删除历史或输出文件。

## 10. SQLite 存储字段

默认数据库：`real-workbench/employee_workbench/product_processing/product_processing.sqlite3`。连接启用 WAL、外键、`synchronous=NORMAL` 和 busy timeout。

### 10.1 `product_processing_drafts`

草稿索引字段与第 8 节一致；大体积和扩展来源字段进入 `raw_payload_json`。唯一约束：

- `(workspace_id, candidate_id)`
- `handoff_id`
- `handoff_idempotency_key`

### 10.2 `product_processing_handoff_receipts`

| 字段 | 说明 |
|---|---|
| `handoff_id` | 上游交接 ID，唯一 |
| `idempotency_key` | 上游幂等键，唯一 |
| `workspace_id`, `run_id`, `candidate_id` | 交接身份 |
| `product_draft_id` | 本地草稿外键 |
| `source_status` | 接收时的上游状态 |
| `consumer_status` | 本地消费状态 |
| `payload_sha256` | 原始 payload 摘要 |
| `created_at` | 本地回执时间 |

### 10.3 `product_processing_daily_selection_intakes`

旧整批 run 接口的接收快照：`workspace_id`、`run_id`、`status`、`criteria_json`、`counts_json`、`errors_json`、候选/创建/跳过数量和时间。唯一约束为 `(workspace_id, run_id)`。

### 10.4 任务与资源表

- `product_processing_tasks`：工作区、状态、数量、设置、幂等键、输出文件、清除标记和时间；唯一约束 `(workspace_id, idempotency_key)`。
- `product_processing_task_items`：任务项、草稿引用、SKC/SPU、状态、原因和结果 JSON。
- `product_processing_source_images`：草稿、任务、图片类型、URL、本地路径；唯一约束 `(product_draft_id, url)`。
- `product_processing_prompts`：提示词 key、自定义值和更新时间。

## 11. 依赖和运行环境

- Python 3.12+
- FastAPI
- SQLAlchemy 2.x
- Pydantic 2.x
- SQLite WAL
- `openpyxl`（Excel）
- `python-multipart`（上传）
- `tzdata`（Windows 上为 `ZoneInfo("Asia/Shanghai")` 提供时区数据）

`tzdata` 是与 `data_collection` 正式合同联调时发现并补充的依赖；Windows Python 环境缺少它时，导入上游模块会抛出 `ZoneInfoNotFoundError`。

## 12. 错误约定

- `400`：工作区冲突、非法文件/参数、无效下载类型或提示词 key；
- `404`：当前工作区中草稿、任务、接收记录或文件不存在；
- `409`：为后续并发状态冲突保留；
- `422`：Pydantic 请求结构校验失败。

错误使用 FastAPI 标准 `{"detail":"..."}`。调用方应依据 HTTP 状态码和稳定字段判断，不依赖中文错误文本。

## 13. 合并与演进规则

1. `data_collection` 拥有采集和选品事实，产品处理只消费快照。
2. `workspace_id`、`run_id`、`handoff_id`、`candidate_id` 的类型和语义不得由下游重新定义。

5. 跨模块字段变更应先更新上游合同和本规范，再修改代码与测试。
6. 正式联调必须用上游 `build_handoff_payload` 构造的 payload 做契约测试。
7. 在 ACK API 落地前，禁止直接操作上游表来“补状态”。
