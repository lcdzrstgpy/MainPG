# 智能电商平台前端演示框架协作说明

## 当前范围

当前已实现的是纯前端演示外壳，不调用 FastAPI，也不保存任何账号、表单或业务数据。

| 功能 | 演示行为 | 后续接入位置 |
| --- | --- | --- |
| 登录 / 注册 | 任意输入后点击按钮进入工作台 | `src/modules/customer/` |
| 主界面 | 展示欢迎区和快捷入口 | `src/modules/dashboard/` |
| 侧边栏 | 切换每日选品、产品处理、利润活动、核价及货源、系统配置 | `src/app/layout/Sidebar.tsx` 与 `src/app/navigation/modules.ts` |
| 顶部栏 | 收起侧边栏、标签页切换和关闭、个人中心弹层 | `src/app/layout/TopNavigation.tsx` |
| 内容页 | 仅展示模块名称和空白占位 | `src/shared/components/EmptyModulePage.tsx` |

## 本地运行

```powershell
cd E:\MainPG\MainPG\web-frontend
npm install
npm run dev
```

浏览器打开命令输出的本地地址。该项目目前不要求 FastAPI 服务启动。

`node_modules/`、`dist/` 和本地环境文件已经由 `web-frontend/.gitignore` 排除，不应提交。

## 成员协作规则

1. 新业务代码只放入 `src/modules/{module}/`；不要把页面、接口和状态直接新增到 `src/`。
2. 每个模块的 API 请求只能放在该模块 `api/`，通过 `src/transport/` 的统一请求能力访问后端。
3. 可跨模块复用的无业务组件才放到 `src/shared/components/`；业务组件留在本模块 `components/`。
4. 后端新增/变更接口字段时，先更新 `src/contracts/{module}/` 的 DTO，再更新模块 `api/` 适配层。
5. 新页面通过 `src/app/navigation/modules.ts` 注册导航元数据；不要在侧边栏组件中硬编码业务分支。
6. 页面级样式在本模块 `styles/`；仅全局 token、重置样式可放入 `src/shared/styles/`。

## 首批嵌入建议

| 优先级 | 模块 | 原因 |
| --- | --- | --- |
| P0 | `customer` | 先明确真实登录、会话和工作区数据来源。 |
| P0 | `daily_selection` | 是产品处理草稿池的数据上游。 |
| P0 | `product_processing` | 可直接对接已完成的产品处理接口。 |
| P0 | `profit_activity` | 可直接对接利润计算、资料导入与活动过滤接口。 |
| P1 | `price_verification`、`basic_settings` | 在核心流程可用后按接口完成度接入。 |

## 不在当前演示中实现的内容

- 真实登录、注册、令牌保存和权限拦截。
- 后端 API、文件上传下载、轮询、错误重试。
- 路由持久化、刷新恢复、多标签持久化。
- 产品、利润、核价等具体业务表单和数据表格。

这些能力应在后续对应模块内实现，并配套补充模块字段文档和测试。
