W-H 浏览器采集插件 v0.1.144

安装方法（Edge）：
1. 将本 ZIP 完整解压到一个固定文件夹，不要直接在压缩包内打开。
2. 在 Edge 地址栏输入 edge://extensions/ 并回车。
3. 打开页面左侧的“开发人员模式”。
4. 点击“加载解压缩的扩展”，选择包含 manifest.json 的解压文件夹。
5. 先启动体验版工作台，并用浏览器打开 http://127.0.0.1:8010 登录一次（保持登录后的页面开着）。
6. 打开插件弹窗，工作台地址固定为 http://127.0.0.1:8010。
7. 点击插件弹窗里的“连接插件”完成连接，不需要填写连接码。

说明：
- 工作台地址固定为 http://127.0.0.1:8010，不需要每次修改。
- 连接不需要连接码：插件会自动读取工作台当前的登录状态完成连接。若提示“连接失败：请先用浏览器打开并登录工作台”，说明没找到已登录的工作台页面，登录后再点一次“连接插件”即可；工作台重启后若连接失效，同样重新点击“连接插件”。
- 插件只读取当前支持页面并把采集结果发送到本机 W-H 工作台。
- 1688 列表页左下角显示“整页采集”：扩展更新、重载或重新连接后会自动修复已打开页面的采集入口，不需要手动刷新。扫描直接读取每个商品卡外层 `detail.m.1688.com/page/index.html?offerId=...` 标签，并兼容商品详情链接和“找相似”链接。插件只把链接交给后台登记与查重；随后在工作台“每日选品 → 插件采集”选中批次并点击“启动采集”。启动失败的批次可以再次点击启动，成功后才写入产品处理并计入新建或刷新。
- 淘宝/天猫列表页同样支持“整页采集”：读取商品卡锚点 `id="item_id_<商品ID>"`（兼容 `data-spm-anchor-id="aItem_id_<商品ID>_..."` 与 `item.htm?id=`/`num_iid=` 链接），统一规范为 `https://item.taobao.com/item.htm?id=<商品ID>` 交给后台登记查重；后续同样在工作台“每日选品 → 插件采集”启动采集，后端自动走淘宝接口（`api-gw.onebound.cn/taobao` 的 `item_get`）。
- 淘宝/天猫商品详情页（单品页）支持“采集到工作台”：从地址栏 `id=<商品ID>`（兼容 `item.taobao.com/item.htm`、`detail.tmall.com/item.htm`）识别商品，采集标题、主图、售价与规格后，直接进入工作台“产品处理 → 待处理池”，与 1688 单品采集一致；缺失的逐 SKU 货源价由后端走淘宝接口自动补齐。
- Temu 商品采集新增页面结构兜底：读取商品主轮播中 `img` 与 CSS `background-image` 图片（包括暂时移出可视区的轮播项），最多保留 24 张；读取“颜色、尺寸、容量、规格、款式、型号、包装”等规格标题及相邻选项文字和规格图。多维规格会按页面真实维度生成组合（例如颜色 × 尺码），同一颜色的规格图会复用到该颜色的各尺码 SKU；数量超出 200 时仍保留每条 SKU 的完整属性维度。促销商品从 `#goods_price` 语义区域读取当前成交价，排除划线原价和“今天支付”等分期金额，并保留 USD/CAD/CNY 币种，工作台不再将美元显示为人民币。SKU 通过 `role="radio"`、`aria-label` 及其子节点图片 URL 识别，重复的页面/接口 SKU 会合并。动态 class 不作为固定识别条件，推荐位、评价图、视频封面和售后服务图会被排除。
- 扩展重载或升级后会自动修复已经打开的 Temu、1688、Alibaba、拼多多、Amazon、淘宝和天猫页面采集按钮；后台运行异常会直接显示具体原因，不再只显示笼统的“采集失败”。
- 新增「订单利润采集」：在 Temu 订单列表页（订单列表 / 全部订单）右下角 AI 浮窗会出现紫色「采集订单利润」按钮，插件读取当前页已加载的订单接口响应，并解析父订单号、子订单号、SKC/SKU、商品名、件数、GMV、申报价、尾程运费、运单号、订单状态、站点和时间；接口取不到时用页面表格/文本兜底。采集结果在浮窗显示摘要，可复制 JSON，也会保存最近一次快照到插件本地存储。申报价和尾程运费如果在订单接口中不存在，会标为待补，后续由工作台按 SKU 匹配「货源与利润」台账和站点费率补齐；插件不会提交、发货或修改平台订单。
- 订单利润采集识别的是 Temu 订单列表接口 `/kirogi/bg/mms/recentOrderList`（响应里的 `result.pageItems[].parentOrderMap` 与 `orderList[]`）。如果列表接口本身不带金额，可先展开订单详情/订单导出，再点采集，插件会从最近 60 分钟的订单相关响应里合并 GMV、申报价等字段。安装或更新插件后必须刷新一次订单页，否则页面加载前的接口响应不会被记录。
- 订单详情页同样可以点「采集订单利润」：插件会从详情页文本读取申报价格(CNY)、销售回款、订单货款(GMV)、运费回款、销售冲回、运费冲回、预计收入、运单号和子订单号；尾程运费仍来自订单列表接口的 `waybillInfoList[].callLabelExtension.estimatedText`（美元，需按汇率换算）。列表按父订单/包裹预估的尾程费用会按件数分摊到子订单，避免重复计费。一个父订单有多个子订单时，建议在列表页采集全部行，再逐个打开详情页补充金额。
- 列表页采集前会自动切到状态「全部(N)」并点一次「查询」：旧页面已经加载过订单时不会再发请求，主动查询后插件才能抓到完整的 `recentOrderList` 接口响应；如果只想采当前状态，可在工作台指令 payload 里传 `all_statuses: false`。采集结果会分别保存列表和详情两份快照，供后台合并。
- 采集不再要求先手动切到对应页面：插件弹窗默认勾选「自动跳转页面采集」，点「采集订单 / 采集财务流水 / 采集店铺首页 / 采集结算数据 / 采集流量数据」时，插件会自己打开（已打开则直接复用）Temu 订单列表、对账中心、Seller Central 首页、结算数据页、经营分析流量页，在后台标签页完成采集后自动关闭自己打开的临时标签页，不影响你当前正在看的页面。工作台下发采集指令时同理：list 模式自动打开订单列表，detail 模式先从订单列表里取第一条详情链接再打开采集。取消勾选即恢复“只采当前页”。
- 新增「结算数据」采集（账户资金 → 结算数据，`https://agentseller-us.temu.com/labor/settle`）：按表头文字定位「PO单号 / 币种 / 销售回款 / 销售冲回 / 运费回款 / 运费冲回」列，逐行读取每个 PO 单的回款与冲回金额，并读取页面顶部的待处理/已到账总额；采集结果按 PO 单写入工作台，并按申报价×件数分摊回填到订单行，订单利润改用实际回款口径。当前打开的是「待处理款项」就记 pending，是「已到账款项」就记 settled。
- 新增「流量数据」采集（经营分析 → 商品流量/店铺流量，`https://agentseller-us.temu.com/main/flux-analysis`）：自动识别当前选中的周期（实时 / 近1日 / 近7日 / 近30日 / 本周 / 本月）和统计日期，读取汇总分析的指标卡（商品曝光量、商品点击量、支付订单数、支付件数、点击率、点击订单转化率、曝光订单转化率）及其环比；按「范围 + 周期 + 统计日期」保存快照，重复采集同一周期只更新不新增。当前停在「店铺流量」子页时会记为店铺流量。
- 已移除「销量分析」采集与工作台板块（页面结构变动频繁、口径不稳定）：插件弹窗不再显示该按钮，一键全量采集也不再包含这一步，工作台左侧的「销量分析」入口已删除。
- 对账中心（`https://seller.kuajingmaihuo.com/labor/bill`，账务明细）采集修复：优先按表格行（`<tr><td>` 或 `role=row/role=cell`）读取「账务时间 / 账务类型 / 收支金额 / 币种 / 备注」，表格结构不识别时再按正文逐行解析；页面若把表格套在 iframe 里，会连子 frame 一起读。首屏是骨架屏时最多重试 5 次；逐页读取直到没有新数据。金额方向按「账务类型」判断（支出/退款/扣款/罚款记为负数，结算/调整记为正数），因为页面上支出也可能显示成 `+¥12.40`。若仍读不到，弹窗与工作台会显示「表格行 x / 时间行 y」的排查信息。
- 新增「一键全量采集」：插件弹窗点「一键全量采集（自动切页，不用停留）」后，插件会在后台标签页依次打开并采集 店铺首页指标 → 商品流量 → 对账中心 → 结算数据 → 订单列表，每步采完自动关闭临时标签页，并直接写入工作台；弹窗里会实时显示每一步的「采集中 / 完成 / 跳过 / 失败」和明细。整个过程不需要你停在任何 Temu 页面，也不会打断当前正在看的页面；某一页没有数据时记为“跳过”，不影响后续步骤。店铺首页指标与商品流量两步会并行执行（各自后台标签页），其余步骤需要页面可见渲染，按顺序执行。
- 为了速度，一键采集**不再包含「订单详情」**（每单要单独开一个标签页，136 单要多花好几分钟）。需要补 GMV / 申报价 / 尾程运费时，用插件弹窗的「采集当前详情页」单独采当前这一单。
- 「订单列表」步骤会先把订单页的区域切到「美国」，再切「欧区」，并在每个区域内点「全部(N)」后逐页采集（Temu 分页是 beast-core：`data-testid="beast-core-pagination-next"`，末页带 `disabled`），两区结果按 PO 单号合并去重后一次性入库；进度里显示「美国 第 3/7 页 · 累计 48 行」。订单页必须在前台才会渲染表格，所以采集这几步时浏览器会短暂切到订单页，结束后自动切回。
- 工作台「店铺数据 → 数据采集」里也有「一键全量采集」按钮：通过插件命令队列下发 `temu_capture_all`，插件收到后执行同一套自动切页采集，并回报每一步结果（完成后可在同一页看到 完成/跳过/失败 明细）。同一页还有「增量更新（只补最新）」：订单/财务只读第一页、其余单页，几十秒即可完成；以及「终止采集」，会结束当前指令（已完成的数据保留）。若提示「当前插件会话不支持…」，说明浏览器里加载的还是旧插件：到扩展管理页点一次「重新加载」再重连即可。
- 新增「Temu 登录态检测」：Temu 账号密码只在浏览器里输入，插件不保存任何 Temu 凭据，也不会把账号密码写进工作台。弹窗里点「检测 Temu 登录态」会复用（没有则后台新开）一个 Temu 卖家页，判断当前浏览器的登录 Cookie 是否还有效；结果会缓存在插件本地并显示为「有效 / 未登录」。一键全量采集与各个自动采集按钮在开始前都会先做这一步检测，未登录时不会空跑采集，而是直接把 Temu 登录页切到前台，提示「登录完成后再点一次」。登录态有效期内（默认缓存 60 秒）重复采集不会重复探测。Cookie 过期后必须手动重新登录一次，插件不能代替登录。
- Temu 与 Alibaba 列表页仍使用原“批量采集本页”流程；单品采集入口和后端入池协议不变。
