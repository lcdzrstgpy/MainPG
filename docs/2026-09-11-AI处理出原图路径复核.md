## 二、A 类：生图失败回退（设计如此，闭环完整）

`service.py:6769-6788`——轮播图未凑满 4 张时不再拦截整条商品：

```python
if not grid_image_paths:
    fallback_carousel = provider_original_image_paths or source_image_urls
    grid_image_paths = fallback_carousel
    provider_status_classes["four_grid"] = "source_fallback"
```

- 优先用 `provider_original_image_paths`（AI 产出但未过本地质检的原图），为空才退 `source_image_urls`（采集源图）。

## 三、B 类：静默回填源图（真正需要关注的）

### 触发条件
导出时该商品的 `preview_overrides.carousel_images` 为空（用户把图片全删了），或该商品压根没有预检覆盖。

### 根因链
1. 任务结果里的 `carousel_image_paths` **始终是相对路径**：
   ```
   /api/product-processing/preview/assets/d62081d1-.../content?workspace_id=default&expires=...
   ```
   本地库 53 条实测：`local` 50 条 / `empty` 3 条，**0 条是 `http(s)` 公网地址**。原因是 `_persist_media_for_preview` 返回的 `preview_url` 在发布到 COS 之前不含 `public_url`。

2. `workbooks._dxm_single_export_row` 的图片列分支顺序（`domain/workbooks.py:380-404`）：

   ```
   if slot_overrides:      ...
   elif override_carousel: ...          # 空数组属性为假 → 跳过
   elif generated_images:  ...          # _http_urls() 只收公网 https → 恒为空
   else:                   carousel = "\n".join(_http_urls(source_image_urls))   # ← 掉这里
   ```

   `generated_images` 由 `_http_urls(carousel_image_paths + summary)` 得到，而 `_http_urls` 只保留 `is_safe_external_url` 通过的地址，相对路径全被过滤 → **恒为空** → 必然落到 `else`，三列全部回填源图。

### 探针复现
`outputs/probe_export_carousel_fallback.py`（纯函数，不碰数据库），结果：

| 用例 | `*轮播图` 列 | 判定 |
|---|---|---|
| A 用户清空全部轮播图（显式空数组） | `https://cbu01.alicdn.com/original-a.jpg` + `original-b.jpg` | ❌ 出现来源原图 |
| B 用户保留 1 张轮播图 | `https://wh-media-...cos.../published.png` | ✅ 正常 |
| C 无预检覆盖 | `https://cbu01.alicdn.com/original-a.jpg` | ❌ 出现来源原图 |

用例 A 同时污染 `*产品素材图`（回填 `source_detail_image_urls`）。

### 语义冲突（关键判据）
同一个函数里，**详情图有显式保护，轮播图没有**：

```python
# 详情图：显式空数组 = 运营删光了，绝不允许复活历史值
detail_sources = (
    override_detail if "detail_images" in preview_overrides
    else _http_urls(detail_image_paths)
)
```
轮播图用的是 `elif override_carousel:`——只看「有没有值」，看不出「显式置空」，于是否则就兜回源图。这不是同一种语义。

### 已披露程度
预检卡片有 inline 小字提示：`· 未选主图（导出回退来源图）`（`ProductProcessingPrecheckPage.tsx:1132`），但：
- 只提「主图」，实际连带 `轮播图` / `素材图` 三列；
- 是灰色小字，非阻断性提示。

### 本地数据现状
47 条草稿的 `preview_overrides_json` **全部是 `{}`** → 一旦现在走导出，图片三列就是源图。（该库为开发测试数据，不代表线上。）

## 四、C 类：上一轮判断的更正

**上一轮我判断「COS 未配置 → 导出静默回退源图」为活路径缺口，此判断需要更正——活路径是 fail-closed 的。**

`service.py:2152-2157` `publish_preview_media`：

```python
if not cos_configured:
    base = _media_public_base_url()
    if not base or not base.lower().startswith("https://") or not is_safe_external_url(base):
        raise MediaUnavailableError("未配置可导出的图床：请配置 COS 或公共媒体地址（public_base_url）")
```

预检最终化先发布、发布有错即 `mark_finalize_failed`；`_export_rows` 再经 `require_final_public_image_urls()` 二次 fail-closed。所以配置缺失时用户看到的是**明确报错**，不会拿到源图。

**真正的静默回退只存在于两个「已停用」入口**：
- `export_final_workbook()`（定义 `service.py:4868`）——**生产/UI 无调用方**（原先写的「全仓零调用方」不准确：测试 `tests/test_product_processing_preview_overrides.py` 会调用它）；
- `download_path(kind="dxm_final")`——显式抛错停用（"旧版固定路径已停用"）。

另外，处理阶段写出的原始表格 `assets.write_task_outputs` 确实是源图（carousel 全为相对路径），但其下载入口 `kind=dxm` 只挂在 `ProductProcessingTestPage.tsx`，而该页面**没有任何地方 import，是孤儿页** → UI 不可达（API 层可达）。

> **更正（2026-10-08 复核）**：`_note_media_unconfigured()` **不是死代码**。它定义在 `service.py:8040`，并已在 `service.py:7890` 被调用
> （「生成轮播图但整组产物均非公开 http(s)」分支里写入 AI 备注）。上一轮「零调用方」的判断**已被后续修复推翻** ——
> 本文档 §五 曾建议「顺手清掉」，**切勿照做，会删掉在用逻辑**。
