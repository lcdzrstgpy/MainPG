# 品类生图提示词库 v16（下游对接版）

> 生成日期：2026-10-19
> 基线：v15（详细审核版）；v15 保留用于对照，v16 为生产入库版。
> 目标：直接注入 `_apply_batch_image_guidelines`，单行、短小精悍、不重复下游已有的硬约束。
> 生产中只使用本文件的英文提示词；中文仅供审核，不参与下发。
> 渲染参数（光位、阴影、对比度、饱和度、亮度、色温、镜头、主体占比等）请从 `摄影渲染卡片库-v1.md` 选卡组装；按 **构图 → 光影 → 色彩 → 细节 → 风格** 五层拼成 `Compose / Light / Color / Detail / Style`，替换本文件的 `Light:` 段。

## 一、下游对接规则（从代码反推）

| 下游事实 | 对应做法 |
|---|---|
| `_apply_batch_image_guidelines` 以 `- {prompt}` 把品类提示词追加到图片模板末尾 | 每条写成**单行**，不要换行、不要 markdown、不要小标题 |
| 下游 wrapper 已固定四宫格、分界线、拆分、产品保真、图中文字禁令、道具从属、主图白底 | 品类提示词**不重复**这些规则，只写非主图画面差异 |
| wrapper 明确禁止 full people / faces / pets | 宠物类**不写宠物出镜**；服装只写局部身体 |
| `format_prompt` 在追加品类提示词之后执行 | 禁止使用 `{}` 占位符，避免被渲染为空串 |
| Ark 链路对长提示词内容审核敏感，长指令可能直接 400 | 单条控制在 **≤110 词**，实际目标 60-95 词 |
| 图片模型消费英文指令 | 只写英文；中文不进库 |
| 同一批次可有多个品类 | 按标题逐条分类，分品类注入；同品类共用一条 |

## 四、与 v15 的差异

1. **去掉所有小标题**：`VISUAL SIGNATURE / BUYER PRIORITIES / SUB-TYPE FOCUS / PHYSICS` 合并进 `Scene / Focus / Light / Show / Avoid` 五段，直接给图片模型读。
2. **去掉重复的全局规则**：四宫格、分界线、产品保真、文字禁令、道具从属、主图白底全部由下游 wrapper 承担。
3. **去掉宠物出镜**：下游 wrapper 明确禁止 pets，宠物类改为纯产品 + 地面场景。
4. **去掉关键词表**：匹配词只属于分类器元数据，不进入生图 prompt。
5. **长度从 170-239 词压到 52-71 词**：适配 Ark 内容审核与图片模型注意力。
6. **保留品类差异**：每条仍有独立场景、光位、侧重点与规避项，不是同一段换产品名。

## 五、分类元数据（不进入生图 prompt）

以下内容只给分类器用，不拼进图片提示词：

- 品类中文名、英文名、`category_id`。
- 中英文匹配关键词、同义词、负向词。
- 歧义词优先级（bowl / mat / bag / brush / case / glove / tray / rack / cover / sleeve / pouch / holder 等）。
- 置信度阈值与回退规则。

分类器规则继续沿用 v15 第五节，不需要重复进 prompt。

---

## 六、接入建议

1. 代码里新增 `CATEGORY_IMAGE_PROMPTS: dict[str, str]`，value 就是上面每条单行英文。
2. `classify_title_to_category(title)` 命中品类后，直接返回对应单行 prompt。
3. `generate_batch_image_prompt` 命中品类时不再调用 AI；未命中才走现有 AI 兜底。
4. 同一批次多品类：按标题分组，每组取各自 prompt，不要整批共用。
5. 前端保留最终 prompt 可编辑，便于分类错误时人工修正。
6. 回归测试用 mock/dry-run，不消耗真实付费额度。

---

## 七、审核清单

1. 每条是否保持单行，没有被编辑器自动换行。
2. 每条是否 ≤110 词。
3. 是否没有 `{}`、markdown、小标题、编号列表。
4. 是否没有重复下游已有的全局规则。
5. 是否没有要求宠物、完整人脸或全身。
6. 是否仍有本品类独有的场景、光位、侧重点与规避项。
7. 中文对照是否与英文语义一致。
8. 分类关键词是否只留在元数据，没有混进 prompt。
