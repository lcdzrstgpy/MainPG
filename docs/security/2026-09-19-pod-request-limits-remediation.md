# POD 请求边界修复记录

日期：2026-09-19

## 修复范围

| 问题 | 风险 | 修复 |
| --- | --- | --- |
| 模板上传在 multipart 解析后才检查文件大小 | 分块请求可占满临时磁盘 | 新增 POD 流式 ASGI 请求上限：模板上传 21 MiB，其余 POD 请求 1 MiB；超过上限返回 413。 |
| 规格卡空行/空列绕过限制 | 可消耗内存和 CPU | 空行、空列也计入 101 行、6 列、606 单元格上限。 |
| 业务字段与手工标题无大小上限 | 可膨胀提示词、数据库和日志 | 业务文本限制为 500 字符，列表最多 100 项且每项 200 字符，文案限制 2,000 字符，手工标题限制 300 字符。 |

## 回归验证

命令：

```sh
cd local-runtime
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m unittest discover -s tests -p 'test_pod_request_limits.py' -v
```

结果：5 项通过，覆盖分块 JSON 请求在下游读取前返回 413、模板上传尾斜杠重定向的 21 MiB 预算、空规格卡填充拒绝、超大业务字段/关键词列表/手工标题拒绝及各项合法边界。

## 影响与兼容性

合法 POD 请求的路由、权限、计费和响应格式不变。超限请求不进入业务处理，也不会写入 POD 数据库或业务日志。
