## 一、需求原文（用户原话）

> 功能就是做一个小智能体，用户可以遇到操作问题可以问小智能体，这个智能体就会回答。

| # | 需求 | 说明 |
|---|---|---|
| 1 | **操作答疑智能体** | 用户在系统里遇到「这个按钮干嘛的、这步该怎么做」这类操作问题，可以直接问，智能体回答 |

## 三、后端约定（照抄现有模块的写法）

### 3.1 模块目录结构（参照 `ai_service`）

```
local-runtime/wh_local/modules/<你的模块>/
├── __init__.py          # 导出 create_router
├── router.py            # create_router(...) 工厂，返回 APIRouter
├── service.py           # 业务逻辑
├── migrations/
│   └── 001_xxx.sql      # CREATE TABLE IF NOT EXISTS ...
└── tests/
    └── test_*.py
```

### 3.2 路由注册（`local-runtime/wh_local/app/main.py`）

现有写法（第 63–93 行 import 区，第 416–703 行注册区）：

```python
from ..modules.ai_service import create_router as create_ai_service_router
...
# 注意：前缀定义在 router 内部（APIRouter(prefix="/api/ai-service", ...)），
# include_router 时 不需要 再传 prefix。
app.include_router(
    create_ai_service_router(db_path, ai_service_assets, legacy_pod_enabled=False)

```

### 3.3 SQL 迁移加载机制

**不是自动扫描**，是**显式登记**在 `local-runtime/wh_local/db.py`：

- `_module_migrations()`（第 790 行起）返回 `list[tuple[migration_id, sql_path]]`
- 每个模块的 SQL 要**手工加进这个函数**，格式参照：

```python
data_collection_migrations = [
    ("data_collection:001_daily_selection", root / "data_collection" / "migrations" / "001_daily_selection.sql"),
    ...
]
for migration_id, sql_path in data_collection_migrations:
    if <exists>:
        migrations.append(...)
```

- 建表统一用 `CREATE TABLE IF NOT EXISTS`。
- `ai_service` 已有的表名：`ai_service_model_profiles`、`ai_service_templates`、`ai_service_conversations`、`ai_service_assets`、`ai_service_messages`、`ai_service_creations`、`ai_service_pod_groups`。

### 3.4 前端 API 层写法

```ts
// web-frontend/src/modules/xxx/api/xxxApi.ts
import { httpJson } from "../../../transport/http/client";
```
用统一封装 `httpJson`，类型定义写在同文件或 `modules/xxx/types/index.ts`。

## 四、环境与踩坑（**必读，否则会卡住**）

### 4.1 本机 git 是坏的 ⚠️

`which git` → `/mingw64/bin/git`（WorkBuddy 内置 PortableGit `C:/Users/jj/.workbuddy-ai/binaries/PortableGit/versions/1.2.0/`）
**缺 `git-remote-https.exe` 和 libcurl**，导致任何 HTTPS 操作**静默卡死数分钟 + 退出码 127**，日志为空。

**解法**：用系统完整版 git：

```bash
/d/Git/cmd/git.exe -c credential.helper=manager push -u neworigin <branch>
```

判定推送成功**只看** `git ls-remote --heads <remote> <branch>`。
（本地 `git branch -r` 不显示新推分支、`git status` 标 `[gone]`，都是缓存假象，已确认不代表失败。）

远程：`neworigin` = `https://github.com/lcdzrstgpy/MainPG.git`（另有 `origin` = `Alon237925/MainPG.git`）。

### 4.2 Windows bash 缺 `COMPUTERNAME`

密钥派生是 `sha256(f"{COMPUTERNAME}:{USERNAME}:wh-local-runtime")`，bash 里没有这个变量会导致
`secret_values` AES-GCM 解密失败（`InvalidTag`）。真实机器名 **`LAPTOP-L75S7LIA`**，跑后端命令必须加前缀：

```bash
cd /d/syq/MainPG/local-runtime && COMPUTERNAME=LAPTOP-L75S7LIA /d/syq/MainPG/.venv/Scripts/python.exe -m pytest ...
```

### 4.3 虚拟环境位置

`d:/syq/MainPG/.venv/Scripts/python.exe`（Python 3.11），**不是** `local-runtime/.venv`。

### 4.4 启动开发服务

```bash

cd /d/syq/MainPG/local-runtime && COMPUTERNAME=LAPTOP-L75S7LIA /d/syq/MainPG/.venv/Scripts/python.exe -m uvicorn wh_local.app.main:app --host 127.0.0.1 --port 8010
```

### 4.5 本会话 PowerShell 工具的坑

PowerShell 工具输出**无法被捕获**（exit 0 但 stdout 为空，`Write-Host`/`Format-Table`/`Out-String` 都试过）。
绕过办法：`Set-Content` 写到临时 json，再用 Read 工具读。
`wmic.exe` 被安全策略**拉黑**（PROGRAM BLOCKED）；`Get-CimInstance` 因内部调 cmd.exe 被拒；
查进程用 `Get-Process` 的 `Path`/`StartTime` 即可。

## 五、开工建议（供新会话参考）

### 5.1 分支

从 `syq-sku-availability-0912` 切新分支，建议命名 `syq-help-agent-0914` 之类。
（注意：昨天那批 SKU 改动**还没合并**进主分支，它在 `syq-sku-availability-0912` 上。）

### 5.2 建议先跟用户确认的 4 件事

1. **FAQ 数据从哪来**：是维护一份静态 JSON/`docs` 里的问答对，还是建表由后台维护？
   （用户说「问题我们尽可能进行总结」→ 倾向**人工沉淀 FAQ 库**）
2. **智能体的作用域**：只答系统操作，还是也能答业务/商品相关？（决定 prompt 与检索范围）
3. **交互形态**：右侧悬浮窗 / 独立页面 / 侧边抽屉？（`ai_service` 已有成熟对话 UI 可参考样式）
4. **是否计费**：建议不计费（帮助功能），但需产品确认。

### 5.3 推荐实现路径（最小闭环）

```
FAQ 命中（关键词/向量检索，人工沉淀的问答对）
   ↓ 命中 → 直接返回标准答案
   ↓ 未命中 → 走 StationGateway.chat_stream()（带 FAQ 上下文 + 系统操作手册做 RAG）
   ↓ 仍不满意 → 引导到 FeedbackPanel，预填用户原话
```

- **检索优先**：先用轻量关键词/BM25 命中 FAQ，命中就**不调模型**（省钱、答案可控）。
- **兜底再调模型**：把 FAQ 全量 + 系统模块说明（可复用 `modules.ts` 里的 `description`）作为上下文。
- **最后兜底反馈**：`FeedbackPanel` 已现成，只需支持「预填内容」参数。

### 5.4 落点建议

- 后端：新建 `local-runtime/wh_local/modules/help_agent/`（不要塞进 `ai_service`，保持职责清晰）
- 前端：新建 `web-frontend/src/modules/help_agent/`，在 `modules.ts` + `WorkspaceShell.tsx` 注册入口
- FAQ 数据：初期可放 `docs/faq/` 的 md/json，后续再考虑建表
- 复用：`StationGateway`（模型调用）、`FeedbackPanel`（反馈兜底）
