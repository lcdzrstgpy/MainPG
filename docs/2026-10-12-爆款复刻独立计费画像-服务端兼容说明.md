# 爆款复刻独立计费画像 · 服务端兼容说明

> 状态：**客户端已改，等待服务端兼容**
> 日期：2026-10-12
> 面向：服务端（控制面计费）接手同学

---

## 1. 一句话结论

客户端把**爆款复刻**的计费画像从 `pod_random_v1` 独立为 **`pod_replica_v1`**，以便服务端把「复刻」与「全定制」分开归类统计。

服务端要做的事只有一件：

> **把 `pod_replica_v1` 当成「和 `pod_random_v1` 同一类 POD 交易」来处理。**

除「不参与半定制的 32/组逻辑」外，复刻应与全定制**同价、同结算、同权限**。

---

## 2. 客户端上报契约（现状）

### 2.1 复刻冻结请求

```json
{
  "idempotency_key": "pod:batch:<batch_id>:initial",
  "link_count": 3,
  "scope": ["title", "four_grid"],
  "billing_profile": "pod_replica_v1"
}
```

要点：

- 复刻按「**款**」计价：**1 款 = 1 个 link**，`link_count` 就是款数（不折叠、不除 4）。
- **带 `billing_profile = "pod_replica_v1"`**。
- **不带 `item_count`**（`item_count` 是半定制专用字段）。
- `scope` 为 `["title", "four_grid"]`（初始/重试），续跑可能只有 `["four_grid"]`。

### 2.2 三条冻结路径都上报新画像

| 场景 | 端点 | `link_count` | `billing_profile` |
| --- | --- | --- | --- |
| 初始批次 | `POST /api/customer/billing/batch/freeze` | 款数 | `pod_replica_v1` |
| 暂停后续跑 | `POST /api/customer/billing/batch/freeze` | 剩余款数 | `pod_replica_v1` |
| 失败重试（单款/批量） | `POST /api/customer/billing/batch/freeze` | 重试款数 | `pod_replica_v1` |
| 崩溃恢复 regrant | `POST /api/customer/billing/batch/freeze` | 取自 status | `pod_replica_v1` |

> 复刻走的是**通用 batch 端点**（不是 `/pod-semi/*`），续跑/重试与全定制共用同一套调用 ID（`:style:{款}:image:{尝试}`）。

### 2.3 画像取值一览

| 画像 | 用途 | 计价口径 |
| --- | --- | --- |
| `product_processing` | 商品处理 | 按子项定价 |
| `pod_random_v1` | POD **全定制** | 40–50 随机 / 款 |
| `pod_semi_v1` | POD **半定制** | 默认 32 / 组（4 款 = 1 link） |
| **`pod_replica_v1`（新增）** | POD **爆款复刻** | **40–50 随机 / 款（与全定制同）** |
| `ai` 相关 | AI 服务 | 独立 |

## 3. 兼容原则

> **凡是代码里出现 `{BATCH_BILLING_PROFILE_POD, BATCH_BILLING_PROFILE_POD_SEMI}` 的地方，把 `BATCH_BILLING_PROFILE_POD_REPLICA` 也加进去。**

自检命令：

```bash
grep -rn "BATCH_BILLING_PROFILE_POD_SEMI" wh_local/ wh-admin/
```

每一处与 `BATCH_BILLING_PROFILE_POD` 并列的集合，都补上复刻值即可。

## 4. 需要改的点（按符号名，行号以贵方仓库为准）

### 4.1 `wh_local/billing.py`

**① 常量区新增**

```python
BATCH_BILLING_PROFILE_POD_REPLICA = "pod_replica_v1"
```

**② `freeze_batch_points()` — 画像白名单**

```python
# before
if profile not in {
    BATCH_BILLING_PROFILE_PRODUCT,
    BATCH_BILLING_PROFILE_POD,
    BATCH_BILLING_PROFILE_POD_SEMI,
}:
    raise HTTPException(status_code=400, detail="invalid batch billing profile")

# after
if profile not in {
    BATCH_BILLING_PROFILE_PRODUCT,
    BATCH_BILLING_PROFILE_POD,
    BATCH_BILLING_PROFILE_POD_SEMI,
    BATCH_BILLING_PROFILE_POD_REPLICA,   # 新增
}:
    raise HTTPException(status_code=400, detail="invalid batch billing profile")
```

**③ `freeze_batch_points()` — POD 定价分支（最关键）**

```python
# before
if profile in {BATCH_BILLING_PROFILE_POD, BATCH_BILLING_PROFILE_POD_SEMI}:

# after
if profile in {
    BATCH_BILLING_PROFILE_POD,
    BATCH_BILLING_PROFILE_POD_SEMI,
    BATCH_BILLING_PROFILE_POD_REPLICA,   # 新增
}:
```

> ⚠️ 漏了这一处，复刻会掉进 `else`（商品处理）分支，按「商品处理」单价错算。
> 分支内已有 `semi = profile == BATCH_BILLING_PROFILE_POD_SEMI`，复刻自然走 `40–50 随机 × 倍率`，**无需再动**。

**④ `settle_batch_points()` — 4 处同类集合**

快照校验、`rule_version` 取值、逐 link 校验、逐 item 计费，共 4 处 `if profile in {POD, POD_SEMI}`，全部补 `BATCH_BILLING_PROFILE_POD_REPLICA`。

**⑤ `usage_history()` — 展示归类**

```python
# before
is_pod = billing_profile in {BATCH_BILLING_PROFILE_POD, BATCH_BILLING_PROFILE_POD_SEMI}

# after
is_pod = billing_profile in {
    BATCH_BILLING_PROFILE_POD,
    BATCH_BILLING_PROFILE_POD_SEMI,
    BATCH_BILLING_PROFILE_POD_REPLICA,   # 新增
}
```

> `is_semi = billing_profile == BATCH_BILLING_PROFILE_POD_SEMI` **保持不变**（复刻不是按组）。

### 4.2 `wh_local/customer/auth_server.py`

**⑥ `customer_billing_batch_freeze` 路由 — 白名单**

```python
if billing_profile not in {
    BATCH_BILLING_PROFILE_PRODUCT,
    BATCH_BILLING_PROFILE_POD,
    BATCH_BILLING_PROFILE_POD_SEMI,
    BATCH_BILLING_PROFILE_POD_REPLICA,   # 新增
}:
    raise HTTPException(status_code=400, detail="invalid batch billing profile")
```

**⑦ 同路由 — 权限门槛**

```python
# before
if billing_profile in {BATCH_BILLING_PROFILE_POD, BATCH_BILLING_PROFILE_POD_SEMI}:
    _require_pod_create_permission(db_path, account)

# after
if billing_profile in {
    BATCH_BILLING_PROFILE_POD,
    BATCH_BILLING_PROFILE_POD_SEMI,
    BATCH_BILLING_PROFILE_POD_REPLICA,   # 新增
}:
    _require_pod_create_permission(db_path, account)
```

> 别让复刻绕过 POD 创建权限。

## 5. 不需要改的地方（避免过度改动）

| 项 | 说明 |
| --- | --- |
| `_multiplier_category()` | 按 `startswith("pod")` 归类，`pod_replica_v1` **自动**落入 `pod` 倍率分类。**不用**新增分类。 |
| 数据库 `billing_batch_freezes.billing_profile` | 自由 TEXT、**无 CHECK**，**不需要迁移**。 |
| 数据库 `billing_multiplier_rules.category` CHECK | 仍是 `('ai','pod')`，复刻共用 `pod`，**不需要改**。 |
| `compute_batch_charge()` | 通用子项定价，无 profile 分支，**不用动**。 |
| `/pod-semi/*` 路由与半定制 32/组逻辑 | 复刻不走这条，**不受影响**。 |

---

## 6. 兼容与灰度

- **老客户端 / 全定制 / 商品处理**：仍发 `pod_random_v1` / `product_processing`，行为完全不变。
- **新客户端 + 未升级的服务端**：复刻冻结会 **400**（`invalid batch billing profile`）→ 冻结失败 → 复刻批次不落库、**不扣费**（安全失败，但功能不可用）。
- **发布顺序**：**服务端先上 ①~⑦ → 客户端再发版**。
- **半定制 `item_count` 校验（若已实现）**：请**只对 `pod_semi_v1` 生效**；复刻不发 `item_count`，不要纳入该 4 倍关系校验。

---

## 7. 服务端自测清单

1. `billing_profile="pod_replica_v1"`、`link_count=3`、`scope=["title","four_grid"]` 调 `/api/customer/billing/batch/freeze` → 成功，`link_prices` 为 3 个 40–50 的值。
2. 同一请求分别用 `pod_random_v1` 与 `pod_replica_v1` 发一次 → 单价分布一致（同倍率、同区间）。
3. `settle` 回 3 条 item（`title`/`four_grid` 子项）→ 按冻结快照扣费，行为与全定制一致。
4. `pod_semi_v1` 的分组 / `item_count` / 32 定价逻辑**不受影响**。
5. 用错画像（如 `pod_replica_v2`）→ 仍 400。
