# 摄影渲染卡片库 v1（五层组装：构图 / 光影 / 色彩 / 细节 / 风格）

> 生成日期：2026-10-19
> 用途：把光影、阴影、对比度、饱和度、亮度、色温、镜头、主体占比、材质、后期、氛围拆成可复用卡片；品类提示词只保留 `Scene / Focus / Show / Avoid`，渲染部分从这里选卡组装。
> 五层：**构图搭骨架 → 光影塑体积 → 色彩定情绪 → 细节撑质感 → 风格统全局**。
> 对接：与 `品类生图提示词库 v16（下游对接版）` 配合使用；组装后仍是**单行英文 prompt**，≤110 词，直接进入 `_apply_batch_image_guidelines`。
> 原则：卡片只写画面参数，不写四宫格、分界线、产品保真、文字禁令等全局规则。

## 零、五层组装法（本库主骨架）

| 层 | 作用 | 卡片组 | 组装顺序 | 先回答 |
|---|---|---|---|---|
| L1 构图搭骨架 | 决定主体位置、画面重心、呼吸感 | `FRAME` 预设 + CM / SC / CP | 先定 | 主体占多大？机位在哪？视线往哪走？ |
| L2 光影塑体积 | 决定立体感、空间层次、表面起伏 | `LIGHT` 预设 + LD / LM / SH / CT | 第二 | 主光从哪来？硬还是软？影子落在哪？ |
| L3 色彩定情绪 | 决定冷暖、浓淡、情绪与品类识别 | `TONE` 预设 + TM / ST | 第三 | 暖还是冷？浓还是淡？背景怎么退？ |
| L4 细节撑质感 | 决定材质可信度与"真不真" | `DETAIL` 预设 + MT / PS | 第四 | 最值钱的细节是什么？哪里要有微光、纹理或边缘？ |
| L5 风格统全局 | 决定四格是否像同一套图 | `STYLE` 预设 + MD / PS | 最后 | 目录干净、编辑感、生活感还是工业感？ |

**组装口诀**：先搭骨架，再打光，再定色，再补细节，最后统一风格。

**顺序不能反**：

- 先定构图，光影才知道往哪打；先定光影，色彩才知道冷暖怎么压；先定色彩，细节才知道高光与纹理怎么显；最后用风格统一四格。
- 如果先写材质再写构图，模型容易把细节放大成主体，导致画面失衡。
- 同一批次四格必须共享 `STYLE`，但可以换 `FRAME` 或 `LIGHT` 制造差异；这正是"风格统全局"的含义。

## 一、设计原则

1. **一卡一职责**：每张卡只描述一个摄影属性，例如"光位"或"阴影"，不混写。
2. **短句化**：每张卡 3-12 个英文词，直接可拼。
3. **五层槽位**：`Compose / Light / Color / Detail / Style` 各选 1 个预设；需要细调时再用原子卡替换其中 1-2 张。
4. **预设优先**：日常组装优先用 `FRAME / LIGHT / TONE / DETAIL / STYLE` 组合卡；需要细调时才拆成原子卡。
5. **不重复全局规则**：结构、分界线、产品保真、文字禁令、主图白底由下游 wrapper 负责。
6. **预算控制**：组装后目标 99-109 词，硬上限 110 词；超预算按第六节的压缩顺序删卡。
7. **互斥显式化**：每张卡带 `conflicts`，避免同时选到高对比+低对比、暖光+冷日光等冲突组合。

## 二、卡片数据结构

```json
{
  "id": "LD-06",
  "group": "light_direction",
  "slot": "light",
  "label_zh": "柔和窗侧光",
  "prompt_en": "soft window light from one side",
  "optional": false,
  "conflicts": ["LD-13"],
  "compatible_categories": ["home_kitchen", "pet_supplies", "general"],
  "notes": "常与 TONE-01 或 TONE-06 搭配"
}
```

字段说明：

| 字段 | 含义 |
|---|---|
| `id` | 唯一编号，组装时只引用 ID |
| `group` | 所属分组：light_direction / light_modifier / shadow / contrast / saturation / brightness / temperature / camera / scale / composition / material / finish / mood / tone_preset / frame_preset |
| `slot` | 组装槽位：light / shadow / tone / frame / material / finish / mood |
| `label_zh` | 中文名，仅供审核 |
| `prompt_en` | 英文片段，唯一进入下游的内容 |
| `optional` | 是否可被压缩删除 |
| `conflicts` | 互斥卡片 ID |
| `compatible_categories` | 适用品类；`["*"]` 表示全品类 |
| `notes` | 使用提示，不进入 prompt |

## 六、组装协议

### 6.1 组装模板（五层顺序）

```text
<CATEGORY>: Scene: <v16 Scene> | Focus: <v16 Focus/Route> | Compose: <FRAME> | Light: <LIGHT> | Color: <TONE> | Detail: <DETAIL> | Style: <STYLE> | Show: <v16 Show> | Avoid: <v16 Avoid>
```

- `Scene / Focus / Show / Avoid` 来自 v16 品类提示词，保持品类身份。
- v16 里的 `Light:` 段删除，由五层卡片替代。
- 顺序固定：**Compose → Light → Color → Detail → Style**，对应"构图搭骨架、光影塑体积、色彩定情绪、细节撑质感、风格统全局"。
- 需要细调时，只展开其中一层，例如把 `LIGHT-01` 换成 `LD-06 + LM-01 + SH-01 + CT-02`。
- 输出仍为单行英文，目标 99-109 词，硬上限 110 词。

### 6.2 五层槽位

| 槽位 | 预设 | 可展开为 | 数量 |
|---|---|---|---|
| Compose | `FRAME-*` | CM + SC + CP | 1 |
| Light | `LIGHT-*` | LD + LM + SH + CT | 1 |
| Color | `TONE-*` | ST + BR + TM | 1 |
| Detail | `DETAIL-*` | MT + PS | 1 |
| Style | `STYLE-*` | MD + PS | 1 |

### 6.3 压缩顺序（超过 110 词时）

1. `Style` 只保留 MD，删掉附加 PS。
2. `Detail` 只保留一张 MT，删掉第二张。
3. `Light` 删掉 LM 修饰卡。
4. `Compose` 从预设换成更短的手写组合。
5. 最后才删 `Show` 中的次要证明点。

### 6.4 互斥规则

- **层内不重复**：`LIGHT-*` 已包含 CT，不要再加 CT 原子卡；`TONE-*` 只含 ST/BR/TM，不再加 CT；`FRAME-*` 已含 CM/SC/CP，不再加原子卡。
- **光位**：`LD-04` 逆光不能单独作主光，需配 `LD-01` 或 `LD-02`。
- **色温**：`LD-10` 暖钨丝 不与 `TM-05` 冷日光同用；需要混合时用 `LM-05`。
- **阴影**：`LD-08` 阴天 不与 `SH-04` 清晰硬影同用；改用 `SH-02`。
- **阴影**：`LD-09` 斑驳叶影 不与 `SH-07` 窗格投影同用；只保留一种投影。
- **对比**：`CT-01` 低对比 与 `CT-03` 高对比 互斥。
- **饱和**：`ST-01` 低饱和 与 `ST-03` 浓郁 互斥。
- **亮度**：`BR-01` 明亮通透 与 `BR-03` 低调 互斥。
- **构图**：`CM-06` 正俯拍 与 `CP-05` 三层背景 互斥。
- **尺度**：`SC-04` 环境 18-38% 与 `SC-05` 微距 60-75% 互斥。
- **风格**：同一批次四格共享同一个 `STYLE`，差异靠 `FRAME` 或 `LIGHT` 制造。

### 6.5 组装字数实测（默认五层包）

| 品类 | 词数 | 状态 |
|---|---|---|
| 家居与厨房 | 105 | OK |
| 服装与配饰 | 106 | OK |

| 办公与文具 | 106 | OK |
| 运动户外 | 106 | OK |
| 汽车用品 | 99 | OK |

**口径**：按空格分词，标点不计；`Compose / Light / Color / Detail / Style` 等标签计入词数。

**结论**：12 类全部 99-109 词，硬上限 110。游戏 109 最接近上限，追加要求时优先删 `Style` 的 PS 或 `Detail` 的第二张 MT。

## 八、与 v16 的对接

1. v16 每条保留 `Scene / Focus / Show / Avoid` 四段。
2. 删除 v16 的 `Light:` 段，不再写死光位与色温。
3. 按第五节默认包，为五层各选一个预设：`FRAME / LIGHT / TONE / DETAIL / STYLE`。
4. 按第六节模板，按 `Compose → Light → Color → Detail → Style` 顺序拼成单行。
5. 组装后检查 ≤110 词、无 `{}`、无 markdown、无换行。
6. 分类仍按标题逐条进行；同品类共用同一套五层包。

## 九、校验清单

1. 五层是否各有 1 个预设：Compose / Light / Color / Detail / Style。
2. 如果展开原子卡，是否只用了该层的组（例如 Light 只用 LD/LM/SH/CT）。
3. 是否把 CT 又放进了 Color 层（`LIGHT-*` 已包含对比度，不要重复）。
4. 是否同时用了 `FRAME-*` 和 CM/SC/CP 原子卡。
5. 是否命中第六节的互斥组合。
6. 组装后是否 ≤110 词。
7. 是否仍是单行，没有换行、markdown、`{}`。
8. 是否没有重复下游已有的全局规则。
9. 是否没有要求宠物出镜。
10. 中文卡片名是否只用于审核，没有进入 prompt。
11. 换 SKU 时是否只需要替换 1-2 个预设或原子卡，而不是重写整段。
