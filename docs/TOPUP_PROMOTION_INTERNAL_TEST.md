# 常驻充值赠送 25%：内测与发布说明

本规则由账号服务决定，无需配置支付宝密钥，也不需要日常启停命令或重启服务。

## 当前规则

- 固定套餐只有 49、99、499、4999 元，基础兑换比例仍为 1 元 = 100 积分。
- 每个固定套餐固定赠送基础积分的 25%，订单在创建时写入基础、赠送、合计和规则说明快照：

| 金额 | 基础积分 | 赠送积分 | 合计积分 |
| --- | ---: | ---: | ---: |
| 49 元 | 4,900 | 1,225 | 6,125 |
| 99 元 | 9,900 | 2,475 | 12,375 |
| 499 元 | 49,900 | 12,475 | 62,375 |
| 4999 元 | 499,900 | 124,975 | 624,875 |

- 自定义金额保留原有整数金额范围，按原价到账，赠送积分为 0。
- 50 / 199 / 999 元等旧套餐不能再创建新订单；99 / 499 元虽然仍在售，但按本规则重新计算 25% 赠送。
- 已支付订单不补发、不扣回。此前翻倍活动期间创建的待支付订单保留其历史快照；在有效期内完成支付仍按翻倍结果入账。

## 内测验收

1. 打开账单摘要或个人中心，确认只显示四档固定套餐及“固定套餐赠送 25%”说明。
2. 分别创建四档固定订单，确认订单响应的 `base_points`、`promotion_bonus_points` 和 `total_points` 与上表一致。
3. 创建一笔合法整数自定义金额订单并调用报价接口，确认奖励为 `0`、合计等于基础积分。
4. 尝试以 `points_50`、`points_199`、`points_999` 创建订单，确认服务端拒绝为未知套餐。
5. 对任一新固定订单模拟或完成一次成功支付；确认积分账本只新增一条基础 `payment_alipay` 流水和一条 `topup_promotion_bonus` 流水，金额合计等于订单快照。
6. 重复同一支付宝通知、刷新或重复回跳，确认不会重复写入钱包或任一账本流水。
7. 使用历史 pending 翻倍订单验证：即使当前已切换为常驻 25% 规则，结算仍采用该订单保存的基础、赠送和合计快照。

## 发布边界

- 本规则替代原“充值积分翻倍活动”，不再使用 `manage_topup_promotion.py enable` / `disable` 进行日常操作；生产部署时应关闭旧翻倍配置，仅用于历史审计。
- 支付金额、支付宝验签、订单金额校验和 30 分钟订单有效期不因本规则改变。
- 正式部署前应运行后端测试、SQLite 旧库升级验证和前端构建；本次代码改动阶段不执行这些操作。
- 不得把支付宝私钥、公钥、生产数据库、账户信息或服务器环境文件放入仓库或内测文档。
