# 采集批次侧抽屉「只占半屏」修复

- 日期：2026-09-10
- 改动文件：`web-frontend/src/modules/product_processing/styles/ProductProcessingVerifyPage.css`（2 处，+12 −4，含注释）
- 影响范围：顶部「采集批次」入口触发的右侧抽屉（`.verify-batch-popover`）

---

## 一、现象

点开草稿池工具栏的「采集批次（N）」，右侧抽屉高度是全屏的，但**列表区域只占上方约 320px**，批次多时只能在这一小块里滚轮滚动，下方留出大片空白。

headless 实测（视口 808px）：

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 抽屉高度 | 808 | 808 |
| 列表可视高度 | **320** | **711** |
| 列表底部位置 | 384 | 775 |
| 列表以下空白 | **424** | 33（吸底提示条） |

截图：`outputs/repro/shot_before.png` / `shot_after.png`

---

## 二、根因：同选择器重复定义，早期 `max-height` 被继承

`.verify-batch-list` 在同一个 CSS 文件里被定义了两次，分属两代 UI：

```css
/* L4620 旧「内嵌面板」区块（已废弃） */
.verify-batch-list { max-height: 320px; overflow-y: auto; }

/* L4649 现行「侧抽屉」区块 */
.verify-batch-list { flex: 1; min-height: 0; overflow-y: auto; }   /* 没写 max-height */
```

两条选择器**特异性完全相同**，后者只覆盖它声明过的属性；`max-height: 320px` 不在其中，于是**继续生效**。抽屉版是 `flex-direction: column`，列表 `flex: 1` 想撑开却被 `max-height` 钳在 320px —— 表现就是「只占半屏 + 半屏内滚动」。

旧区块对应类 `verify-batch-panel` / `verify-batch-toggle` 在全部 TSX 中**零引用**，属遗留死代码。

线上构建产物同样带病：

```css
.verify-batch-list{max-height:320px;overflow-y:auto}
.verify-batch-list{flex:1;min-height:0;overflow-y:auto}
```

---

## 三、修复

```diff
 /* ── 采集批次管理面板 ── */
+/* 注意：旧内嵌面板已废弃（TSX 中 verify-batch-panel/-toggle 零引用）。
+   此处不要保留 max-height，否则会被下方弹窗版的 .verify-batch-list 继承，
+   把侧抽屉列表钉在 320px、只占半屏并在此范围内滚动。 */
-.verify-batch-list { max-height: 320px; overflow-y: auto; }
+.verify-batch-list { overflow-y: auto; }

 /* ── 采集批次弹窗（顶部工具栏「采集批次」入口触发）── */
-.verify-batch-list { flex: 1; min-height: 0; overflow-y: auto; }
+/* 侧抽屉列表：撑满抽屉剩余高度（head 之外的可用空间），仅在列表内部滚动。
+   max-height:none 显式清除同选择器在其他区块的遗留上限，避免被再次钉死。 */
+.verify-batch-list { flex: 1; min-height: 0; max-height: none; overflow-y: auto; }
```

两处一起改：前者删掉污染源，后者显式兜底，防止日后有人再往旧块里加属性又泄漏过来。

## 四、牵连排查

| 牵连点 | 结论 |
|---|---|
| 抽屉头部 / 操作按钮 | 无影响（`flex` 第一项，高度由内容决定） |
| 底部「当前只显示 XX 批次」提示 | **位置变化**：原紧跟列表、现被 `flex: 1` 顶到抽屉底部（吸底状态条），无功能影响 |
| 媒体查询 | 7 个 `@media` 块内 **0 条** batch/drawer 尺寸规则，无二次覆盖 |
| SKU 管理抽屉 `.verify-drawer` | 类名唯一、无重名冲突；`body{flex:1;overflow-y:auto}` 本来就撑满（其 `flex:1` 缺 `min-height:0`，本次未动，非本次问题） |
| 其它重复选择器 | 用脚本扫全表（跨区块间隔 > 40 行 + 尺寸属性泄漏），命中项全部位于 `@media` 内属正常响应式覆盖；**真正的跨组件泄漏仅 `.verify-batch-list` 一处** |
| 逻辑 / 接口 | 完全无涉及（纯 CSS 层叠修复，js/ts 未改） |

## 五、验证

1. **真实渲染实测**：临时 HTML 加载**真实 CSS 文件** + 与 TSX 一致的 DOM 结构，headless Edge 取 `getBoundingClientRect()`：
   - 修复前 `listH = 320`，下方空白 424

2. **构建产物核对**：`vite build --outDir dist-verify-tmp` → 产物 CSS 输出为 `{overflow-y:auto}` + `{flex:1;min-height:0;max-height:none;overflow-y:auto}`，构建成功（仅既有的 chunk 体积警告），临时目录已清理。
3. **截图对照**：`outputs/repro/shot_before.png`（半屏 + 空白）、`shot_after.png`（撑满 + 吸底提示）。
