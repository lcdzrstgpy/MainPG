# 打包目录清单与发布自检

> 目的：把「包里必须有什么」固化成清单，每次打包前后照着核对，避免再出现 `004_plugin_devices.sql` 这类运行期缺文件导致的崩溃。

## 1. 产物位置

| 产物 | 路径 |
|---|---|
| 免安装目录（唯一权威内容） | `local-runtime/dist/MainPG/` |
| 安装包 | `local-runtime/dist/MainPG-Setup-<版本>.exe` |
| 便携包 | `local-runtime/dist/MainPG-portable-<版本>.zip` |
| 增量包（基于已保留的旧版本自动生成） | `local-runtime/dist/patch-<旧版本>-to-<新版本>/` |

打包命令（在 `local-runtime/` 下）：

```powershell
powershell -ExecutionPolicy Bypass -File .\build_installer.ps1 -Version 1.6.10
```

脚本会依次：构建前端 → PyInstaller 冻结后端 → 校验资产 → 生成 patch → 调 Inno Setup 出 exe → 打 zip。

## 2. 包内必需目录（以 `dist/MainPG/` 为根）


## 3. 打包后自检（必须全绿）

```powershell
$dist = "local-runtime/dist/MainPG"
$src  = "local-runtime"

# 1) 迁移 SQL 数量一致
(Get-ChildItem "$src/wh_local" -Recurse -Filter *.sql |
  Where-Object FullName -like "*\migrations\*").Count          # 期望 87
(Get-ChildItem "$dist/_internal/wh_local" -Recurse -Filter *.sql).Count

# 2) 模块数据文件（scene_props.json 必须在内）
Test-Path "$dist/_internal/wh_local/modules/product_processing/domain/scene_props.json"

# 3) 关键资产
Test-Path "$dist/_internal/web-frontend/dist/index.html"
Test-Path "$dist/_internal/browser-extension/manifest.json"
Test-Path "$dist/_internal/tools/presets"
(Get-Content "$dist/version.json" -Raw)

# 4) 不该出现的文件
Get-ChildItem $dist -Recurse -Filter "*.local.json"            # 期望空
```

`build_installer.ps1` 已把 1)-3) 做成硬校验：缺任何一项直接 `throw`，不会产出安装包。

## 4. 历史事故与防线

| 版本 | 现象 | 根因 | 现在怎么防 |
|---|---|---|---|
| 1.6.x | 启动即 `FileNotFoundError: ...004_plugin_devices.sql` | spec 里迁移目录是手写白名单，新模块没登记 | 自动扫描 `wh_local/**/migrations`，构建期逐个校验 |
| 1.6.7 | 「没有找到已解压的浏览器插件目录」 | 扩展源码未打进包 | spec 自动取最新 `W-H-browser-extension-v*`，构建期校验 `manifest.json` |
| 1.6.9 | `/themes` 为空 | `wh_local/data` 未整目录打包 | 整目录收 `wh_local/data` |
| ≤1.6.9 | 品类场景 / 牌面素材缺失 | 模块目录内 `*.json` 与 `tools/` 未打包 | 已加入 spec 自动收集 + 构建期校验 |

## 5. 禁止打进包里的东西

- `*.local.json`（`cos.local.json`、`ai_keys.local.json`、`onebound.local.json` 等本地凭据）
- `*.localbak*` / `.bak` 备份文件
- 运行期数据库（`*.db` / `*.sqlite`）、`logs/`、`__pycache__/`
- 仓库根的扩展版本目录合集（只打最新的那一个）
