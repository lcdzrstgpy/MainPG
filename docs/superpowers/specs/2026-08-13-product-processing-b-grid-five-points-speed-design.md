# 产品处理 B 模板四宫格、五点描述与时长修复设计

- 日期：2026-08-13
- 状态：用户已批准
- 目标分支：`codex/product-processing-duration-optimization`
- 验证边界：只使用本地假模型、合成图片和测试；不调用真实付费模型，不写入店小秘

## 1. 真实故障基线

安装版实际任务 6 使用 B 模板处理 1 条链接，从 `2026-08-13T03:24:41Z` 到
`03:35:16Z`，共 635 秒。任务记录同时包含：

- `text:ai-failed` 与 `details:ai-failed`：中转返回 HTTP 400，API Key 没有可路由商家；
- 最终描述退化为“标题 + Source information preserved for operator review”，却仍标记成功；
- `four_grid:chinese_unresolved`，但旧安装版仍拆图、上传并标记成功；
- 四张拆后图出现内部纵向或横向白色长分隔线、邻格残片和非独立构图。

当前运行环境还有版本错配：`5173` 是源码 Vite，`8010` 是安装目录中的
`MainPG.exe`。修复验收必须明确使用源码后端或新安装包，不能把旧安装版当成新源码。

## 2. 目标与约束

1. 保留每件商品一次 2K 四宫格生成，不改为四张独立付费生成。
2. B 模板以固定坐标骨架为主路径，同时强化区域提示词。
3. 自动寻找分隔线只作为小偏移保底，禁止远距离猜线或对任意拼贴强行裁剪。
4. 子图存在内部长分隔线、邻格残片或多重拼贴时不得上传或进入成功结果。
5. 明确的配置/参数 4xx 不重试；B 模板质量失败不自动发起第二次付费重绘。
6. 产品描述必须是事实可追溯的英文 Amazon 风格五点；失败不得用模板废话冒充成功。
7. 保存阶段耗时和尝试次数，能够解释单链接慢在哪里。
8. 不降低 `gpt-image-2-2k`、2048×2048、商品身份真实性或公开图片发布要求。

## 3. 四宫格生成合同

### 3.1 固定坐标骨架

本地媒体层从第一张已验证来源图构建 2048×2048 RGB 骨架：

- 中心分隔带固定为 16 像素；垂直和水平分隔带均为 `[1016, 1032)`；
- 四个 panel 的边界分别为左上、右上、左下、右下；
- 来源商品按比例缩放后放入每个 panel 的 10% 安全区，不拉伸，不裁掉商品；
- 骨架不包含文字、编号、箭头、logo 或尺寸，只使用中性背景和中心分隔带；
- 调用图片编辑接口时，骨架作为第一张结构参考，原始商品图继续作为商品身份参考。

媒体接口显式接收 `layout_scaffold`，不能把骨架伪装成普通商品来源图，也不能让它进入
来源图库、商品证据或最终导出。

### 3.2 强化提示词

B 模板最终运行合同明确写入：

- 画布为 2048×2048；中心分隔带坐标固定；四个 panel 各自的像素范围固定；
- 骨架是结构约束，必须保留中心分隔带，不得新增内部全高/全宽分隔线；
- 每格商品、人物、桌面、阴影、道具和背景均不得跨越区域；
- 允许创造不同的模特、场景、光影和构图，但商品本体必须完整、准确；
- Panel 2 的细节必须融入同一画面，禁止带长边框的嵌套拼贴；
- 输出仍为一张图，不在画面中渲染任何坐标、数字、说明或文字。

自定义提示词可以改变风格，不能覆盖以上运行合同。

## 4. 分隔线与裁剪

### 4.1 主路径

先验证固定中心分隔带。符合合同时直接使用固定区域裁剪，移除中心 gutter 后得到四格。

### 4.2 保底路径

固定中心验证失败时，只在中心上下左右各 2.5% 的窄走廊中寻找一条垂直线和一条水平线。
候选必须同时满足：

- 近似直线、颜色稳定、贯穿至少 95% 画布；
- 线宽在 0.2%–1.2% 画布范围；
- 每个候选方向只有一个高置信分隔带；
- 分隔线相对中心的偏移不超过画布 2.5%；对应两侧 panel 的宽度或高度差不超过画布 5%，
  每格裁去 gutter 后的宽高比必须在 0.90–1.10。

裁剪非等宽 panel 时，取区域内最大居中正方形后缩放到 800×800，禁止直接非等比拉伸。
固定和保底路径均不得重新调用图片模型。

### 4.3 拆后独立性门

四个 panel 在发布前逐张检查：

- panel 内部 8%–92% 范围不得存在宽 2–20 像素、贯穿 80% 以上、沿线颜色低方差且与
  两侧持续高对比的纵线或横线；
- 不得在边缘保留中心 gutter；
- 不得出现第二套网格、连续海报边框或明显邻格残片；
- 尺寸、格式、解码和最小清晰度继续使用原质量门。

检测结果不确定或存在多个候选时 fail closed，返回 `attention_required`，不发布坏图。

## 5. 时间与重试

图片请求按错误类型处理：

| 结果 | 行为 |
| --- | --- |
| HTTP 400/401/403/404 | 立即停止，同一请求 1 次 |
| HTTP 429 | 尊重 `Retry-After`，最多一次有界重试 |
| 连接建立失败、明确 5xx | 在 150 秒图片阶段总预算内最多一次重试 |
| 已发送后超时、结果未知 | 不盲目重放，避免重复计费 |
| B 模板结构/OCR/独立性失败 | 不付费重绘，直接待重试 |

B 模板单次图片阶段总预算为 150 秒，单次请求最多 120 秒；正常路径只有一次图片请求，只有
首个连接失败或 5xx 在较早时间返回、且剩余预算足够时才允许第二次请求。来源图准备、OCR、拆分和
COS 发布不占用图片模型 semaphore。四格和详情图继续在内存中传递，避免上传后再下载。

每个 item 保存至少以下本地观测数据：

- `subject_identity_ms`
- `combined_text_ms`
- `description_repair_ms`
- `variant_translation_ms`
- `grid_generation_ms`
- `grid_validation_ms`
- `local_detail_ms`
- `publish_ms`
- `total_processing_ms`
- 每个 provider 阶段的 `attempt_count` 与安全错误分类

不得记录密钥、Authorization、完整提示词、图片字节或供应商完整响应。

## 6. 产品描述合同

组合文本仍以一次调用同时生成标题、描述和规格翻译，但最终 prompt 必须包含当前实际生效的
`desc` 提示词。自定义 `desc` 变化必须进入缓存键，不能继续只使用独立的
`combined_text` 默认描述规则。

描述规范化和验证要求：

- 恰好 5 个 bullet；
- 每点以 2–5 个英文大写词的短标题开头，随后为 `: ` 或 ` - `；
- 五点分别覆盖不同的已验证事实，不重复堆词；
- 全英文，无平台名、品牌臆造、绝对化宣传或来源不支持的材质/尺寸/功能；
- 总长度 80–150 个英文词，允许至多 1000 个字符；
- 禁止 `Source information preserved` 等内部兜底语进入成功结果。

组合返回的描述仅格式轻微不规范时可以本地规范化；缺点、少于五点或事实合同失败时，最多进行
一次便宜的描述专用调用。仍失败则整个 item 为 `attention_required`。组合调用遇到明确配置 4xx
时直接停止，不能继续串行调用标题、描述和规格翻译制造额外等待。

## 7. 测试与验收

所有测试使用 fake client、合成 PNG/JPEG 和临时 SQLite/COS publisher：

1. 骨架尺寸、gutter 和四格商品安全区精确。
2. 最终 B prompt 同时包含坐标合同和无文字/不跨格规则。
3. 固定中心合成图正确拆为四张 800×800。
4. 中心小偏移只走一次本地保底并正确裁剪。
5. 远偏移、多候选、连续海报和子图内部额外长分隔线全部被拒绝。
6. 图片 HTTP 400 只调用一次；质量失败不触发 repair provider 调用。
7. 自定义 `desc` 确实进入组合 prompt 和缓存摘要。
8. 合法五点通过；四点、重复点、模板废话和配置 4xx 不得产生 completed item。
9. 阶段耗时字段存在且为非负数，不包含敏感数据。
10. 产品处理聚焦测试、完整后端测试与前端构建通过。

验收不调用真实 provider，不上传真实 COS，不触发店小秘写入。源码运行验收时必须证明请求命中
源码后端路径，不能继续连接旧 `MainPG.exe`。

## 8. 非目标

- 不做四张独立图片付费并行生成。
- 不为提高成功率而关闭 OCR、结构门或描述验证。
- 不自动部署、替换安装包或发布到生产。
- 不修改尺寸画布当前未提交的并行工作。
