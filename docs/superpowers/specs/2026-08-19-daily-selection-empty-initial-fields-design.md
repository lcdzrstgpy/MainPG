# 每日选品采集表单初始空置设计

## 目标

每日选品的 OneBound API 采集表单首次打开时，不再自动带入默认采集方向的字段值。关键词采集与参考图采集两个模式共享同一套空白初始状态。用户主动选择采集方向后，仍按现有模板规则自动回填。

## 范围

- 首次打开时，采集平台、站点和选品范围显示“请选择”。
- 采集数量、采集关键词、参考图 URL、最低/最高价格、起订量上限及全部 SKU 筛选字段保持空值。
- 自动排除高风险候选默认关闭。
- 采集并行数无法表达空值，按已确认的安全默认值设为 1 线程。
- 关键词采集与参考图采集的切换不触发默认值回填。
- 用户主动选择采集方向后，继续使用现有模板回填行为。

## 不在范围内

- 不调整采集模式标签、表单布局、占位提示文字和高级设置的展开方式。
- 不修改模板的创建、编辑、删除或持久化结构。
- 不修改其他页面的默认值。

## 状态与数据流

组件初始化时使用空字符串表示尚未人工选择或输入的下拉字段、文本字段和数字字段。下拉框增加不可提交的“请选择”选项。模板入口继续调用现有方向选择逻辑，由该逻辑写入模板包含的站点、关键词、价格和目标数量等字段。

提交时，采集平台、站点、选品范围、采集数量及当前模式要求的关键词或参考图 URL 必须通过前端校验；可选的高级筛选字段保持空值时不进入请求条件。这样页面显示与实际提交参数一致，不会在空白界面下暗中沿用旧预设。

## 验证

- 自动化测试先证明当前代码会错误地渲染预设值，再验证修改后首次状态为空。
- 测试切换关键词采集与参考图采集，确认两个模式都不会恢复默认预设。
- 测试主动选择模板后，确认模板字段仍能正确回填。
- 运行前端构建，验证 TypeScript 类型与打包无回归。
