# POD 批次差异化：元素关键词随机分配 + 批内统一字段设计

状态：v4（2026-09-07，**输入模型由用户重新定义**；评审修订完成；**已进入实现**）
目标读者：POD 生图链路开发与协作方

> 历次修订：

## 一、背景与问题

最近批次（如 `eccfebdf…` 西南复古牛仔托特包，10 款）同质化严重：
10 款成品共享同一套元素（牛仔靴 + 仙人掌 + 马蹄铁 + 野花 + 绿松石首饰 + 沙漠远山）、
同一色系与同一种"满版散点平铺"，肉眼差异仅剩疏密和大小。

已确认的根因：

1. `build_direct_listing_prompt` 把整条风格关键词清单原样放进**每一款**的 base prompt，
   而 DIVERSITY CONTRACT 要求 "Design theme / Style keywords / Creative direction 优先级最高、
   绝不能被违背"，且"motif 只是变化想法，冲突时按主题重新解释"。
   结果：模型把清单当成**每款强制全量元素**，批内差异只能靠构图/配色/密度。
2. 元素清单混入了"无缝满版平铺（Seamless Pattern）"这类**批内统一要求**，
   与配方中的 off-center focal / radial / cascading / layered 等构图直接冲突，
   模型以平铺优先 → 构图配方失效。
3. 用户给足 4 个精确配色时，配方输出 "the brief's specified colors"，每款同色 → 批内配色只余权重差异。
4. 主题池仅 8 个 desert 元素，10 款中第 9、10 款与第 1、2 款同主题变体；
   且该主题尚无 Doubao 学习池，用户元素（牛仔靴/绿松石/马蹄铁）不在池内，完全不参与主题变化。
5. 渲染（剪纸/丝网印/干笔/马克笔）在成品中几乎不可见，因为契约把它们定义为 "diversity guidance only"。
6. 查重只防像素级重复（40 张指纹全不同、无重试），防不住"元素组相同"的同质化。

## 二、v4 输入模型（用户定义）

**业务信息编辑**字段变为：

| 字段 | 必填 | 语义 | 每款如何注入 |
|---|---|---|---|
| **主题整批统一风格**（新，取代"设计主题"的语义） | 是 | 整批统一的创意主题与风格基调，如"美式西南复古牛仔荒野风、复古手绘插画风" | 原样注入**每一款**（优先级最高） |
| **样式规划**（新，"设计主题"槽位替换） | 是 | 整批统一的排布/覆盖要求，如"花卉铺满包身、提手处留白""全铺满 / 铺满一半" | 原样注入**每一款**，作为批内硬性要求；配方仅可在其允许范围内变化 |
| **元素关键词**（原"风格关键词"改名） | 是 | 要变化的素材清单，如"复古牛仔靴插画、沙漠仙人掌、绿松石配饰、马蹄铁与野花" | 按分隔符切分数组，**每款随机选取下标**注入该款，其余元素不出现在该款 |

| 目标市场 / 目标人群 / 核心卖点 / 偏好配色 / 禁用元素 | 维持现状 | 不变 | 原样注入**每一款** |

用户提示（**字段标签旁 ⓘ 感叹号，鼠标 hover 显示**，非检测器）：

- **主题整批统一风格**："整批统一的创意主题与风格基调，例如：美式西南复古牛仔荒野风、复古手绘插画风"
- **样式规划**："整批统一的排布与覆盖要求，例如：花纹铺满包身、提手处留白；全铺满 / 铺满一半。留空请写'无特殊要求'"
- **元素关键词**："元素之间用顿号或逗号分隔；建议写 **10 种以上**不同元素；系统将按款式随机分配主打/辅主/点缀，其余元素不在该款出现；素材可跨款复用"

原则：
- **零分类**：系统不做任何"这个词是素材还是风格"的判断；语义由**字段位置**决定。
- **批内统一 vs 款间变化**：统一字段（主题整批统一风格/样式规划/其他）整表进每款；
  变化字段（元素关键词）只进被选中的款式——**这是避免同质化的关键：元素清单绝不能再整表进每款**。
- **素材可复用**：同一元素允许在多款出现；款间花样差异由
  （主打元素身份、尺度关系、排布逻辑、色彩重心、渲染工艺，至少 2 维不同）保证。

## 三、设计

### 3.1 元素关键词数组化与随机选取

- 切分：**元素关键词使用独立切分器**（仅顿号/逗号/分号/换行，**不含空格**），去空、去重、保序。
  **不修改公共 `splitBusinessField`**（它被核心卖点/偏好配色等共用，含空格会拆散
  "奶油燕麦色（Cream Oat）""Seamless Pattern" 等英文复词）。
- 选取策略（**建议：种子随机 + 批内不重复 + 结果持久化**，命中用户"随机选取下标"意图，
  同时解决纯随机的三个坑）：
  1. **批内不重复**（无放回抽样）：主打元素在一个"轮换周期"内不重复，
     相邻款式主打不同 → 避免"相邻两款撞脸"；
  2. **可复现**：以 `batch_id` 为随机种子生成打乱序列 → 同一批次的
     单款重试 / 整款重生成 / 失败重试，分配的仍是同一元素（后端按 `style_index` 重放即可）；
  3. **跨批有变化**：不同批次（或同素材清单不同批）随机种子不同 → 分配不同，
     避免"同清单两批出图一模一样"（确定性轮换做不到这点，这是选随机的收益）。
- 每款结构（沿用已确认决策）：1 **主打** + 1 **辅主** + ≤2 **点缀**：
  - 从打乱序列依次取：主打、辅主、点缀 ×2；
  - 主打为视觉主角（尺度 1.0），辅主第二大（0.6），点缀小尺度（0.25）；
  - 剩余元素**禁止出现在该款**（写入契约）。
- 持久化：批次创建时分配，随 `style_grid_results`（或批次快照）落库字段
  `style_elements`（JSON 数组），重试/重生成直接读取，不重新随机。
- 回退（**池已彻底弃用，无池可兜**）：
  - 元素数组为空 → 每款主语 = 主题整批统一风格 + 契约"在主题内自创一个新元素"；
    款间差异仅剩配方四维（构图/配色/渲染/密度）。仅旧数据会出现。
  - 仅 1 个元素 → 每款都以该元素为素材（等同现状，记 `element_rotation_singleton` 日志）。

### 3.2 批内统一字段注入

- 每款 base prompt 顺序与措辞（`build_direct_listing_prompt` 调整）：
  - `Batch-wide theme & style: {主题整批统一风格}`（原 Design theme 语义位，标签体现新语义）
  - `Style planning (batch-wide hard requirements): {样式规划}`
  - `Element keywords` **从 base prompt 移除**（该行不再全表出现）；
    `Creative direction`（前端 builtInPrompt，见 3.3）同理移除元素清单。
  - 其余字段原样。
- **优先级规则**（取代 v3 的"构图池裁剪"词表判断——系统不做任何识别）：
  "样式规划是用户批内硬性要求，优先级高于配方建议；若配方构图与样式规划冲突
   （例如样式规划要求满版平铺时，焦点/放射/层叠构图即不再适用），必须以样式规划为准；
   配方只提供可在样式规划允许范围内实现的变化方式（尺度节奏、色块分割、带状/网格/散点律动等）。"
- 契约措辞补充（每款）：
  ```
  本款素材主语：{主打}（视觉主角）、{辅主}、{点缀 ×N}。
  主题整批统一风格与样式规划必须保持；本款其余元素不得出现。
  素材可在批次内复用，但每款必须拥有不同的视觉主角与花样：
  主打元素身份、尺度关系、排布逻辑、色彩重心、渲染工艺至少两项不同。
  禁止输出"把所有元素等权复制粘贴"的通用大杂烩图案。
  ```

### 3.3 前端 `buildPromptV1`（创意提示词）同步调整

- 字段标签改名：设计主题 → 主题整批统一风格；风格关键词 → 元素关键词；
  新增"样式规划：…"行（原样）。
- **必须从 builtInPrompt 中移除元素关键词整表**——否则后端每款 base prompt
  还会经由 Creative direction 收到全量清单，前功尽弃。
- 该提示词本身作为"每款都注入的 Creative direction"内容不再含元素清单。
- 页面右上"当前批次模板图"摘要卡的"设计主题"标签同步改为"主题整批统一风格"。
- 三个新/改名字段的标签旁均加 **ⓘ 感叹号**（hover 显示提示文案，见二节"用户提示"块）。

### 3.4 后端字段与兼容策略

- **保留 wire/DB key**：`design_theme`（存"主题整批统一风格"）、`style_keywords`（存"元素关键词"），
  只改前端标签与 prompt 文案 → 旧批次数据不迁移、不破坏。
  新增 `style_planning: str = ""`（可选字段，旧数据为空）。
- **池方案彻底弃用（已确认）**：删除 `_THEME_MOTIFS` / `_GENERIC_MOTIFS` / `_THEME_KEYWORDS` /
  `_detect_theme` / `_STYLE_BIAS_THEMES` / `_motif_for_style`，删除 `theme_registry` 模块及其在
  worker 的集成（`_theme_pools()` / `ensure_theme_pool` / `_maybe_enrich_theme`）。
  `design_theme` 只作为普通批内字段透传，不再做任何主题检测。
- **每款主语**：分配的素材词（主打/辅主/点缀）；元素数组为空时 = 主题整批统一风格 +
  契约"在主题内自创一个新元素"（无池兜底）。
- 其他字段整个填每款：目标市场/人群/卖点/配色/禁用元素/Creative direction（现有行为不变）。

### 3.5 花样配方升级（沿用 v3 已确认项）

- **尺度节奏**：显式给出主打/辅主/点缀尺度倍率。
- **色彩强调轮换**：用户配色 ≥2 时每款指定 1-2 个强调色，其余为辅助色。
- **渲染强制**：整幅图案必须采用本款渲染工艺。
- **相邻无冲突**：主打元素（随机序列保证）+ 构图模式（偏移量 3）+ 强调色（偏移量 7）至少两项不同。

## 五、验收标准

1. 单元测试全绿（新增 >= 8 个用例）。
2. 牛仔案例重跑 10 款：10 款主打覆盖全部元素词；相邻款主打/构图/强调色至少一项不同；
   每款 prompt 中元素只出现分配的 2-4 个（无全表）；样式规划每款原文出现。
3. 同素材二次开批：元素分配与首批不同（跨批随机）；同批重试款式：元素分配与首次一致（可复现）。
4. 人工 AB：旧 10 款 vs 新 10 款并排，同质化程度肉眼可辨下降；
   素材允许复用，但视觉主角/排布/色彩重心不同。
5. 指纹查重仍通过，不触发额外重试；旧数据/回退路径（无样式规划、元素为空/单元素）不报错。
