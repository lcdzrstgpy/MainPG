## 0. 一句话

第 4 张图 = `hero` = 四宫格左上角。用户在**空白表格**里自己填内容，生图完成后本地把这张表**原样印到图上**的指定角落。系统不做任何加工：不换算单位、不翻译、不猜语义、不加固定文案 —— **我们只负责把用户填的东西印上去**。

**录入入口（用户指定）**：「SKU 预设」区块下方新增按钮 **「批量添加尺寸（必填）」** → 点击打开**右侧抽屉弹窗**，表格编辑、风格/位置、预览全部在抽屉内完成（§10）。

## 1. 目标与非目标

**目标**

| 编号 | 目标 |
| --- | --- |
| R1 | 第 4 张仍保留**该款式自己的图案** |
| R2 | 图上原样呈现用户表格内容（一个字符都不改写） |
| R3 | 位置固定在四宫格左上角（即 `hero`） |
| R4 | 渲染失败**不能**拖垮单款或整批 |
| R5 | 提交前可预览；提交后终态可重新合成，无需重新生图 |
| R6 | 表格必填：未配置不允许发起批次（提交时硬拦截） |

**非目标（明确不做，2026-09-10 用户决策）**

- ❌ 不做单位处理：无 cm/inch 开关、无换算、不格式化成 `54 cm (21.3 in)` —— 用户想印什么就印什么。
- ❌ 不做翻译：中文/英文由用户自己决定，系统不介入。
- ❌ 不做占位符/变量：表格内容与 SKU 字段**没有绑定**。
- ❌ 不做带箭头尺寸线（参考产品处理链路开销太大）。
- ❌ 不让 AI 在图上写文字/数字。
- ❌ 不承诺"图上比例与数字一致"（AI 生成的正视图比例≠真实尺寸，属另一条确定性贴图路线）。
- ❌ 不做自动选角（位置用户四选一，接受轻微压到产品）。

## 4. 数据模型

放在批次冻结快照里（建议挂在 `listing_fields_json` 下的 `spec_card` 键，**零 DB 迁移**）。

```jsonc
"spec_card": {
  "enabled": true,
  "style": "light",            // light | dark          （D2）
  "corner": "bottom-right",    // 四选一                 （D3）
  "cells": [                   // 自由表格 m×n，纯字符串，原样印出
    ["长", "54 cm"],
    ["宽", "22 cm"],
    ["高", "15 cm"],
    ["重量", "300 g"]
  ],
  "per_style": {}              // 款式级覆盖：结构保留，UI 放 P1（§15）
}
```

- **单元格 = 原样文本**：不做单位换算、不做翻译、不做变量替换。
- 空行自动跳过；整张表无任何非空单元格视为"未配置"（触发必填拦截）。
- 提交时随批次冻结；在途批次按冻结版本出图。

## 5. 渲染规格（本地 Pillow，确定性）

**输入**：干净 `hero` 母版（800×800）+ 冻结配置
**输出**：800×800 JPEG（q92），与其它三格一致

| 项 | 规格 |
| --- | --- |
| 外边距 | 画布边长 × 3.25% |
| 圆角 / 描边 | 2% / 0.25% |
| 内边距 / 行高 | 0.72 × 字号 / 1.72 × 字号 |
| 字号自适应 | 0.0375 × 边长（≈30px）→ 0.0225 × 边长（≈18px）递减，取第一个放得下的 |
| 卡片上限 | 宽 ≤ 46%、高 ≤ 42% 画布 |
| 配色（浅） | 底 `#FFF @80%`、描边 `#E2E2E2`、正文 `#222`、标签 `#565656`、分隔线 `#E8E8E8` |
| 配色（深） | 底 `#1A2233 @84%`、描边 `白 @24%`、正文 `白`、标签 `#CED8E8`、分隔线 `白 @22%` |
| 列 | m×n 通用；首列与其后列为标签色，**末列右对齐**；单列行用正文色（可当标题用） |
| 超宽 / 超高 | 列宽按比例压缩 → 仍超则单元格截断加 `…`；行放不下则丢尾行（**不改用户输入本身**） |
| 文本处理 | **不换行、不翻译、不改写**；仅渲染期做截断以适配卡片 |
| 返回值 | `font_px / cell_count / dropped_rows / truncated_cells`（供日志与 UI 提示） |
| 字体 | **上线前必须随包分发**；未打包前退回系统候选路径；全找不到 → `SpecCardRenderError` |
| 失败回退 | 任何异常 → 发布干净图（R4） |

## 6. 时序与接入点

```
速创（1 次/款）→ 本地拆分（4× 800×800，含校验）
   → 【新增】hero 面板合成规格卡（本地）
   → COS 发布 + 落库（干净母版 + 派生卡片图）
   → 导出（role 名不变，导出代码不改）
```

| 项 | 设计 |
| --- | --- |
| 接入位置 | `worker.py:1409-1441` 发布循环内，**仅 `role == "hero"`** |
| 母版与派生分离 | `pattern_asset_id` / `composite_asset_id` 继续指向干净母版；卡片图作为新资产入库（`kind='direct_listing_panel_card'`），只更新 `publications.public_url` |
| 幂等 | 同母版 + 同配置 → 内容相同 → 内容寻址命中同一 URL，重启/重试不产生重复对象 |
| 必须覆盖的路径 | ① 正常批次 ② 整款/单款重生成 ③ 重启恢复 —— 统一走同一个"发布前 hook" |
| 不受影响 | 标题用 `lifestyle` 面板；导出读 `publications.public_url`；四宫格拆分校验在合成**之前** |
| 并发 | 合成在"款式后处理池"（8 线程）内执行，毫秒级，无 provider 排队 |

### 6.1 时机：伴随式（每款立刻印） vs 批次收尾统一印

**已定（用户 2026-09-10）：走伴随式**——每款拆分后立即合成，不等到批次结束；同时**保留终态「全批一次性重印」**作为用户改配置后的补印路径（§8）。理由与代价：

| 对比项 | **伴随式（采用）** | 批次收尾统一印（不采用） |
| --- | --- | --- |
| 实现 | 直接挂在既有发布路径上，不新增批次阶段 | 需新增"收尾合成阶段"：找待印款式、逐款合成、发布、更新指针 |
| 恢复/补偿 | 重启恢复、整款重生成天然复用同一 hook | 三条路径都要各加一遍收尾补偿扫描；进程被杀后需新的续做逻辑 |
| 过程可见性 | 中途每款生成完立刻是最终形态（用户不会以为没生效） | 批次结束前第 4 张一直是干净图，进度语义模糊（"图片 400/400"但卡片还没印） |
| 失败隔离 | 单款失败只回退该款干净图，其它款不受影响 | 收尾阶段出错会牵连整批的第 4 张 |
| 一致性 | 配置在**提交时冻结**、全批一份 → 100 款印出来必然一致 | 同样一致（但需要额外保证导出不被"尚未印完"的窗口穿透） |
| 导出时序 | 无需改动（发布即最终图） | 需保证"卡片印完"先于批次可导出，否则可能导出干净图 |
| 单款开销 | 800×800 合成 + JPEG 编码，约数十毫秒（估算，8 线程池内分摊） | 同样量级，但要集中占用一段时间 |

**改配置后的补印不靠"收尾必经阶段"，而靠 §8 的两个终态动作**：单款「重新合成」（改一款）与**「全批一次性重印」**（改完整批一次印完）——都是 0 provider 调用、秒级。二者都是**用户触发的可选动作**，批次流水线本身保持伴随式，不引入收尾阶段与补偿扫描。

## 7. 提交前预览（同源渲染）

- **同一个渲染函数**两个调用点：预览接口 + 发布路径 → 不存在前端复刻排版的双实现风险。
- 底图：优先用该批次模板白底图；后续批次可用上一批同款成品。
- 触发：点「预览」或编辑时 debounce 自动刷新（渲染毫秒级）。
- 预览**不落库、不计费**，标注"示意效果，最终以生成结果为准"。

## 8. 终态「重新合成标注」

| 用户动作 | 技术动作 | provider 调用 | 耗时 |
| --- | --- | --- | --- |
| **改表格 → 全批一次性重印**（主路径） | 遍历该批全部已完成款式：读母版 → 渲染 → 新资产 + 新 COS URL → `UPDATE publications.public_url` | **0** | 100 款秒级 |
| 单款「重新合成标注」（P1 可选入口） | 只对某一款重跑上面四步 | 0 | 毫秒级 |
| 取消标注（回干净图） | 无需渲染，指针指回母版已发布的 URL | 0 | 一次 UPDATE |
| 回到上一版（P1） | 用历史配置重渲染（内容寻址：内容相同即命中同一 URL） | 0 | 秒级 |
| 整款重生成 | 母版换新 → 对新母版按伴随式重做卡片 | 1 次速创/款 | 分钟级 |

**全批一次性重印的行为约定**（P0 必须实现）：

- 适用范围：批次处于 `completed` / `partial_failure` / `failed` 且已冻结配置；生成中不可用（只读冻结）。
- 逐款独立：某款渲染失败 → 该款保持现状（不回退、不清空）并计入结果汇总，其余款继续，**不整批失败**。
- 进度反馈：前端显示"重印中 n/总数"，可关闭弹窗后台继续；完成后给出"成功 n 款 / 失败 m 款"。
- 幂等：内容相同 → 内容寻址命中同一 URL，不会产生重复对象；重复点击安全。
- 与导出：完成后提示**该批次需重新导出**（D7）。

- 开放时机：批次 `completed` / `partial_failure`；**生成中只读冻结**（避免与 worker 并发写不一致）。
- 审计：P0 写业务日志（谁、何时、改了什么）；P1 加版本表支持回滚。
- 提示：重新合成后 UI 明确提示**该批次需重新导出**（D7）。

## 9. 兜底规则（渲染期，不阻断批次）

| 情况 | 处理 |
| --- | --- |
| 单元格文字过长 | 列宽压缩 → 截断加 `…` |
| 行数过多 / 卡片过高 | 字号递减到下限 → 仍超高则丢尾行 |
| 卡片压到产品/图案 | 半透明底卡保证可读；图案极花时建议用户选深色风格 |
| 表格为空 / `enabled=false` | 出干净图，不报错（提交前另有必填拦截，见 §10.4） |
| 字体缺失 / 底图不可读 | 回退干净图，记日志 |

### 10.2 抽屉信息架构

外壳沿用现有抽屉模式（`.pod-template-drawer-layer` / `.pod-template-drawer`，`role="dialog"` + `aria-modal` + 遮罩 + `pod-drawer-in` 动画），宽度建议 `min(760px, 94vw)`。

| 区块 | 内容 |
| --- | --- |
| 头部 | 「批量添加尺寸」+ 副标题（"表格内容会原样印到第 4 张图上"）+ 关闭 |

| 外观区 | 卡片风格：浅色 / 深色（D2）；位置：**四角可视化选择器**（D3） |
| 预览区 | 服务端同源渲染预览（debounce 刷新），标注"示意效果" |
| 底部操作 | 「保存到本批次」/「恢复默认」/「清空」；批次终态时额外显示**「保存并全批重印」**（= 保存配置 + 遍历整批重新合成，§8） |

**抽屉里刻意没有的东西**：单位切换、翻译、占位符/变量插入、字体与颜色自定义。

### 10.3 与冻结规则的状态对应（D6）

| 批次状态 | 抽屉行为 |
| --- | --- |
| 草稿（未开始生成） | 可自由编辑；保存写入批次配置，提交时冻结 |
| 生成中（含暂停） | **只读**，提示"配置已冻结；改动将在下一批次生效" |
| 终态（`completed` / `partial_failure` / `failed`） | 可编辑 + 「保存并重新合成标注」（§8）；提示"该批次需重新导出" |

### 10.4 必填落地（D12）

沿用页面既有校验模式（`PodCustomizationPage.tsx:522-526`）：点「开始生成 N 款」时若 `spec_card` 未配置（无任何非空单元格）→ `setError("请先点击「批量添加尺寸（必填）」完成表格配置。")` 并 **return，不发起批次**。

- 判定口径宽松：**只要有一个非空单元格**就算已配置；不校验行数、不要求填满两列。
- 与 D8 不冲突：D8 是渲染期容错（自动兜底/回退干净图），这里是提交前的配置完整性校验。

## 13. 测试计划

**渲染单测**（`tests/test_spec_card.py`）

- **原样性**：单元格文本渲染后与输入完全一致（不做任何单位/翻译/大小写加工）；
- 浅/深风格输出不同；四角落点落在对应象限；
- 空表格 / `enabled=false` → 返回原因而非崩溃；
- 超长文本截断并报告 `truncated_cells`；行数过多丢尾行并报告 `dropped_rows`；
- 字号自适应落在 [18, 30]；字体缺失 → `SpecCardRenderError`；非方形/损坏底图 → `SpecCardRenderError`；
- 中英混排不抛错。

**链路测试**（扩展 `tests/test_worker.py`）

- 仅 `hero` 面板被合成（其它三格字节不变）；
- 合成失败 → 发布干净母版且批次状态正常；
- 母版资产未被改写；重新合成只更新 `publications.public_url`、无 provider 调用；
- 整款重生成路径同样合成。

**接口测试**（扩展 `tests/test_router.py`）：预览不落库不计费；重新合成仅允许终态批次、写审计、越权被拒。

**前端测试**：入口按钮文案与摘要；未配置时提交被拦（不调用创建批次接口，且"未配置"判定 = 无任何非空单元格）；抽屉开关；表格行列增删与单元格编辑后的提交载荷结构。

## 附录 B：已评估并否决的路线（留档）

| 路线 | 结论 | 理由 |
| --- | --- | --- |
| AI 在 prompt 里直接画尺寸线/数字 | ❌ | 模型画不准数字与箭头；与"禁止文字"硬规则冲突 |
| 复用产品处理链路的 `DimensionRenderer` + 尺寸画布 | ❌（用户决定） | 该链路对 POD 批量定制开销太大 |
| 本地分割 + 自动几何对齐画尺寸线（B1/B2/B3） | ❌ | 需解决轮廓分割与跨款漂移，收益不如规格卡 |
| 用户上传"带标注白底图"当速创参考 | ❌ | 标注线/数字会被学进四格图；压在产品上的标注擦不掉 |
| 纯文字白描边卡片 | ❌ | 样张验证：花纹底图上不可读 |
| **单位换算与 cm/inch 开关** | ❌（用户决定） | "我们只负责把东西印到图上" |
| **中文 → 英文自动翻译** | ❌（用户决定） | 同上，不做任何加工 |
| **表格 ↔ SKU 字段绑定（占位符/变量）** | ❌（用户决定） | 同上，不做任何加工 |
| 确定性贴图（保比例真实） | 暂缓 | 工作量最大，仅在需要工程级比例时才做 |
