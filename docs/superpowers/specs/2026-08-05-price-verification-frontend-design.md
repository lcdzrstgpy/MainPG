# 核价及货源前端设计

## 目标

在 `web-frontend/src/modules/price_verification` 实现可操作的“核价及货源”首版页面。页面沿用现有工作台的浅色卡片、青蓝强调色与左侧导航框架，并将核价和货源的后端业务链路明确呈现为三阶段流程。

## 范围与原则

- 首页入口直接渲染 `PriceVerificationPage`，不再使用通用空模块页。
- 页面只展示和调用现有的只读采集、人工决定、图搜及查询接口；不添加任何第三方平台写操作。
- 货源任务只能使用人工标记为“保留”的核价报价；前端也要在没有保留项时禁用并说明原因。
- 前端不捏造报价、货源候选或插件连接状态。请求未返回数据时显示可执行的空状态。
- 保留报价卡片与货源候选之间的来源报价键关联，方便审核每个候选的来源。

## 页面结构

页面采用选定的三阶段工作流布局。

1. 顶部模块区：标题“核价及货源”、说明、刷新按钮和三段步骤条。步骤条根据当前数据自动高亮：没有报价批次时为采集；有报价批次但没有保留决定时为人工确认；存在保留项或货源批次时为货源匹配。
2. 插件与报价采集区：显示共享数据采集插件会话；用户选择具备核价能力的在线会话，填写可选采集范围，发起报价采集，并轮询该命令状态。已完成的命令可物化为报价批次。
3. 报价人工确认区：选择或载入报价批次，显示报价主图、标题、SKC/SKU、报价、置信度、官方链接和证据状态。每条报价可保留或拒绝，决定会附带可选备注并立即回写服务端。提供批次导出入口。
4. 货源匹配区：汇总已保留条目数量，选择具备图搜能力的会话后创建货源命令。页面展示命令进度、已物化的货源批次及其候选结果；每个候选都显示来源报价键、平台、标题、价格、链接和匹配信息。失败批次提供重试。
5. 历史与状态区：展示近期报价/货源命令和批次，供用户切回结果，而不干扰当前的主操作路径。

## 前端模块边界

- `api/priceVerificationApi.ts`：HTTP 请求、响应解包和错误转换；不保存 UI 状态。
- `types/index.ts`：插件会话、命令、报价、人工决定、货源批次与候选 DTO 类型。
- `state/usePriceVerificationWorkflow.ts`：加载、选中批次、轮询命令和调用后的刷新策略。
- `components/`：步骤条、插件会话选择器、报价卡片、货源候选卡、状态提示等可组合展示组件。
- `pages/PriceVerificationPage.tsx`：页面级组合、用户交互和错误展示。
- `styles/priceVerification.css`：模块限定的响应式样式；不污染其他模块。

## 接口映射

| 用户动作 | 现有接口 |
| --- | --- |
| 读取可用插件会话 | `GET /api/v1/price-verification/plugin/sessions` |
| 创建或物化核价批次 | `POST /api/v1/price-verification/quote-runs` |
| 查看报价批次与条目 | `GET /api/v1/price-verification/quote-runs/{runId}`、`GET /api/v1/price-verification/quote-runs/{runId}/items` |
| 写入或读取人工决定 | `POST`、`GET /api/v1/price-verification/quote-runs/{runId}/decisions` |
| 导出报价 | `POST /api/v1/price-verification/quote-runs/{runId}/exports` |
| 创建货源图搜任务 | `POST /api/v1/price-verification/sourcing-runs` |
| 查看/重试货源批次 | `GET`、`POST /retry` `/api/v1/price-verification/sourcing-runs/{runId}` |
| 读取命令状态与近期命令 | `GET /plugin/commands/{commandId}`、`GET /plugin/recent-commands` |

## 数据流与异常处理

启动时并行读取插件会话及近期命令。用户发起采集或图搜后，页面保留命令 ID 并对命令查询接口做有限轮询；命令完成时刷新对应批次，命令失败时保留错误详情和重试入口。所有请求错误都展示为模块内提示，不影响已经加载的批次内容。

服务端返回 409 时，页面提示需要先完成前置阶段或等待插件连接；422 时显示后端给出的缺失字段/不可操作原因；404 时清除失效的本地选择并提示用户从历史列表重新选择。网络错误提供刷新按钮。

## 验收

- 点击左侧“核价及货源”能打开真实页面。
- 无插件、无报价、无人工决定、无保留项和无货源结果均有明确的下一步提示。
- 页面请求与上表中的既有接口一致，决定、创建图搜、重试和导出均可触发真实请求。
- 已保留条目以外的报价不能从 UI 发起货源图搜。
- 组件测试覆盖 API 适配、决定动作、前置禁用条件和命令状态转换；构建与现有前端检查通过。
