# POD「爆款裂变」模块设计

状态：**已确认方案**（2026-10-15）

目标读者：POD 前后端实现者、能力库维护者、计费与验收人员

## 1. 一句话

新增与「全定制」「半定制」「爆款复刻」同级的 POD「爆款裂变」模块：用户上传一张爆款样图 A 和一张白底产品图 B，系统分析 A 的可迁移风格与元素、分析 B 的产品事实，再自动生成指定数量的受控风格变体。每款输出一张四宫格商品图，并生成标题、规格卡和批量上架导出。

裂变是独立业务领域，复用 POD 公共批次、worker、图片拆分、标题、规格卡、导出、ONNX 超分和结算底座。裂变不复用复刻的 `replica_targets` 业务语义。

## 2. 已确认决策

| 编号 | 决策 |
|---|---|
| D1 | 裂变与全定制、半定制、爆款复刻同级，新增独立入口和独立后端领域。 |
| D2 | 输入固定为一张样图 A + 一张白底产品图 B。 |
| D3 | 一次豆包调用联合分析 A/B；同时返回风格/元素候选和结构化能力/规则候选。 |
| D4 | 用户只确认「产品/图案识别摘要 + 数量」，不编辑识别摘要；识别不合适时重传或取消。 |
| D5 | 数量由用户输入，范围为 1–52 款。 |
| D6 | 词表、权重、层级、组合过程不向用户展示，全部由系统自动完成。 |
| D7 | 允许风格受控变体和元素受控变体，例如金属风格的星星可扩展为金属风格的月亮、太阳、地球，也可切换为机械风格。 |
| D8 | 批内不重复完整的风格/元素/配色组合；允许主题相近。 |
| D9 | 构图模板独立建池，scope 为 `fission`；模板生成/编辑是独立能力，生成后可反复复用。没有用户模板时使用系统默认模板。 |
| D10 | 批次生图固定为一款一次四宫格 `grid` 调用，之后本地拆四格；不按款重复调用豆包生成构图参数。 |
| D11 | 复用全定制的元素 Tier、配色权重、美术指导和商品化提示词结构；复用爆款复刻的产品能力库与规则引擎。 |
| D12 | 超分复用现有 ONNX 超分，失败时沿用现有锐化回退。 |
| D13 | 上架信息整批共用，参考全定制；每款单独保存图片、标题和规格卡。 |
| D14 | 按款计费；新增独立 billing profile，价格区间沿用全定制。 |
| D15 | 批次允许部分成功：成功款可先查看和导出，失败款单独重试；最终按成功款结算，失败款退款。 |
| D16 | 能力库运行时自动学习，全系统共享；新产品映射和新能力规则都可立即生效。 |
| D17 | 能力库冲突时追加新版本并令最新版本生效；历史批次冻结旧版本。 |
| D18 | 同一能力/规则版本连续 3 款生成失败时自动回滚到上一版本。 |
| D19 | 新能力在本次 A/B 分析后立即学习、发布并用于当前批次。 |
| D20 | 能力候选与规则候选由同一次 A/B 分析返回，不新增学习专用豆包调用。 |

## 3. 总体架构

### 3.1 三方职责

```text
样图 A                         白底产品图 B
  │                                │
  └──────────────┬─────────────────┘
                 ↓
       一次豆包联合分析调用
                 ↓
  A 风格/元素/构图事实 + 候选词表
  B 产品事实 + 能力/规则候选
                 ↓
  动态能力库学习与版本发布（全系统共享）
                 ↓
  能力匹配 + 确定性规则推导
                 ↓
  裂变独立构图模板池 / 默认模板
                 ↓
  全定制元素权重 + 配色权重 + 美术指导
                 ↓
  固定四宫格全局契约 + 模板 + 权重规则
                 ↓
  图片生成模型一款一张四宫格
                 ↓
  本地拆四格 + ONNX 超分
                 ↓
  标题、规格卡、整批上架信息、导出
```

### 3.2 与现有模块的边界

复用以下公共能力：

- POD 批次状态、幂等、暂停/恢复和 worker 调度；
- 图片生成调用、四宫格拆分、资产持久化和 ONNX 超分；
- 标题生成、标题重试、规格卡、批次共用上架字段和店小秘/妙手导出；
- 按款 billing freeze、settlement、失败款退款和款级重试。

裂变独立保存以下数据：

- A/B 上传资产角色；
- A/B 分析快照和原始响应；
- 风格/元素/配色候选池；
- 动态能力学习事件和批次使用的能力/规则版本；
- 每款 `VariantPlan`、组合指纹、最终 Prompt 和生成参数。

不能把裂变建模成复刻的 `source + targets`：复刻是一张来源图对应多个目标产品；裂变是一组 A+B 对同一个产品生成多个款式变体。

## 4. 用户流程

### 4.1 上传和分析

前端提供两个上传位：

- **样图 A**：用于提取爆款风格、视觉元素、构图特征、色彩关系和可迁移图案；A 中的原产品、人物、房间、道具、标签和水印不作为目标产品内容迁移。
- **白底图 B**：用于识别产品类型、部件数量和结构、材质、使用方式、可印区域、不可印区域、内衬、五金和工艺。

后端以一个分析请求把 A/B 传给豆包，响应必须符合严格结构化 schema。响应还可以包含：

- 风格候选：如金属、机械、复古、极简等；
- 元素候选：如星星、月亮、太阳、地球等；
- 配色候选及主次关系；
- 产品到已有能力的映射候选；
- 新能力和新规则候选。

分析失败、JSON 不合法、必需字段缺失或 A/B 角色无法判定时，自动重试一次；仍失败则返回可理解的失败状态，用户选择重传或取消。不能使用模型自行返回的 confidence 分数作为生成门槛。

### 4.2 用户确认门槛

分析成功后，前端只展示：

- 产品识别摘要；
- 图案/风格识别摘要；
- 生成数量输入框（1–52）。

词表、能力库、规则、权重和组合不展示，摘要不可编辑。用户确认后才冻结能力/规则/模板快照、计费和款级方案；用户取消或重传不会创建计费批次。

### 4.3 方案编排

系统先把分析响应中的产品映射、能力和规则候选追加到全局动态能力库，发布新版本，然后使用该版本处理当前批次。

每款 `VariantPlan` 至少包含：

```text
style_index
style_family
primary_elements
secondary_elements
accent_elements
palette_primary
palette_secondary
palette_accent
composition_template_id
composition_template_version
capability_registry_version
rule_registry_version
combination_fingerprint
```

组合分配必须确定性可复现：以批次 ID 和款号作为种子，从候选池抽取；生成前检查 `combination_fingerprint`，避免完整组合重复。候选池不足时允许主题相近，但不得重复完全相同的风格、元素和配色组合。

### 4.4 提示词和图片

每款提示词由本地编译器组合三块：

1. **全局契约**：明确生成一张 2×2 四宫格，四个格子属于同一产品和同一款变体；禁止新增 Logo、水印、文字和无关主体。
2. **构图模板**：说明四个格子的拍摄方式、景别、机位、背景和光线。模板只负责摄影表达，不重新定义产品事实。
3. **权重与规则**：注入 A 的风格/元素变体、全定制的 Tier 权重与 60/30/10 配色关系、B 的产品结构和可印区域、动态能力规则以及禁止项。

图片生成返回四宫格后，沿用现有本地拆分、四格校验、ONNX 超分和失败回退。每款最多按现有 POD 规则进行图片尝试；仍失败则只标记该款失败。

## 5. 动态能力库与自动学习

### 5.1 共享注册内容

能力库至少包含四类版本化记录：

```text
product_mapping
capability_definition
rule_definition
learning_event
```

能力定义必须包含：

```text
capability_id
capability_type
required_facts
optional_facts
activation_conditions
generated_constraints
forbidden_conditions
compatible_templates
incompatible_capabilities
generation_strategy
prompt_slots
version
```

规则定义必须包含：

```text
rule_id
trigger
effect
generation_constraints
forbidden_conditions
source_capability_ids
version
```

### 5.2 运行时学习流程

1. 豆包在 A/B 分析响应中返回结构化候选。
2. 本地 schema 校验字段类型、引用的事实字段和候选 ID；自由文本不能直接成为硬约束。
3. 已有能力映射追加新的产品映射版本；确实不存在的能力追加新的能力定义和规则定义。
4. 在一个事务中写入学习事件、版本记录和当前生效指针。
5. 发布成功后返回新版本号；当前批次使用该版本冻结方案。
6. 对每个版本记录来源分析 ID、输入资产哈希、发布时间、影响批次和生成结果统计。

冲突时采用追加版本策略。最新版本服务新批次和当前正在创建的批次；已经冻结的批次不重新计算。

### 5.3 自动回滚

当同一能力/规则版本导致连续 3 款生成失败时：

- 将当前生效指针回滚到上一版本；
- 写入回滚事件和失败款列表；
- 新批次使用回滚后的版本；
- 已冻结批次继续使用原版本，便于复盘；
- 失败款仍可按款重试，但重试时必须明确使用原批次快照。

连续失败统计只针对图片生成或最终产物校验失败，不把用户取消、余额不足、网络授权失败计为规则质量失败。

## 6. 数据和 API 设计

### 6.1 API 边界

建议在现有 POD 路由下新增独立资源：

```text
POST /api/pod-customization/fission/images
POST /api/pod-customization/fission/analyze
POST /api/pod-customization/fission/batches
GET  /api/pod-customization/fission/batches
GET  /api/pod-customization/fission/batches/{batch_id}
POST /api/pod-customization/fission/batches/{batch_id}/styles/{style_index}/retry
```

构图模板沿用现有模板 API，通过 `scope=fission` 隔离模板池。

### 6.2 批次创建请求

```text
analysis_id
requested_count: 1..52
listing_fields: 批次共用上架字段
client_request_id
```

批次创建前必须检查：分析属于当前用户/工作区、A/B 资产角色正确、分析状态成功、数量在范围内、候选组合能编排出请求数量、当前计费授权可用。

### 6.3 持久化建议

新增裂变专属表，命名遵循现有 `pod_customization_*` 前缀：

- `pod_customization_fission_analyses`：A/B 事实、原始响应、候选池、版本和状态；
- `pod_customization_fission_batches`：批次输入、分析 ID、模板快照、能力/规则版本、幂等哈希；
- `pod_customization_fission_variants`：款级方案、组合指纹、业务字段、最终 Prompt、生成状态和结果引用；
- `pod_customization_capability_versions`：全系统能力和产品映射版本；
- `pod_customization_rule_versions`：全系统规则版本；
- `pod_customization_learning_events`：候选、校验、发布、回滚和影响范围审计。

动态能力记录采用追加写入，当前版本用指针或 `is_active` 表示；禁止更新历史版本内容。裂变批次保存使用到的版本号和 JSON 快照，保证能力库更新后仍能复现。

## 7. 计费、状态和导出

### 7.1 计费

新增独立画像 `pod_fission_v1`，远端计费白名单、定价选择、流水服务映射和前端显示同步增加「POD 爆款裂变」。计价单位为款，价格区间与全定制一致；标题调用不单独增加图片款数。

冻结时按请求款数预留；结算时每款按图片和标题状态投影：成功款扣费，失败款退款。重复提交使用 `client_request_id` 幂等返回，不能重复冻结。

### 7.2 批次状态

批次支持：`queued`、`running`、`partial`、`completed`、`failed`、`cancelled`。只要存在成功款即可进入 `partial` 或 `completed`，成功款可以查看和导出；失败款进入款级重试队列。

### 7.3 商品化输出

每款保存：

- 四宫格原图和四格拆分图；
- 超分后的交付图；
- 标题和英文标题；
- 规格卡；
- 组合摘要和最终 Prompt 快照。

批次级保存共用上架字段，导出时只包含成功款，失败款不阻塞成功款导出。

## 8. 前端范围

- 导航新增「爆款裂变」模块，与全定制、半定制、爆款复刻同级。
- 新建页提供 A/B 双上传、分析状态和只读识别摘要。
- 数量输入限制 1–52；确认按钮在分析成功后可用。
- 不展示词表、能力库、权重和自动学习细节。
- 结果页复用现有 POD 批次画廊、灯箱、标题/规格卡和导出组件。
- 失败款提供单款重试；成功款可先预览和导出。
- 构图模板管理页使用 `fission` scope，展示模板名称、版本和生效状态。

## 9. 测试和验收标准

### 9.1 分析与确认

- A/B 在一次请求中按角色发送，返回严格 schema；
- 无效响应自动重试一次，第二次仍无效时批次不可创建；
- 分析摘要只读，数量边界覆盖 1、52、0、53；
- 未确认分析摘要不能冻结计费；
- A/B 资产越权、角色错配和重复请求均被拒绝或幂等返回。

### 9.2 方案编排

- 风格/元素/配色候选正确保存但不返回给普通用户；
- 组合指纹确定性生成，批内没有完整重复组合；
- 新能力版本在当前批次立即生效；
- 历史批次仍使用冻结版本；
- 连续 3 款生成失败触发回滚，非规则类失败不触发回滚。

### 9.3 生图和商品化

- 每款只有一个四宫格生成任务；
- 四格位置和角色固定，拆图尺寸与现有链路一致；
- ONNX 超分成功和失败回退均有覆盖；
- 标题、规格卡、批次共用上架字段和导出只处理成功款；
- 单款重试只影响指定失败款，其他款结果和 Prompt 不变。

### 9.4 计费和回归

- `pod_fission_v1` 冻结/结算/退款/幂等覆盖；
- 1–52 款按款冻结，部分成功按成功款结算；
- 动态能力版本写入流水和批次快照；
- 全定制、半定制、爆款复刻现有测试全部通过；
- 保留工作区已有的未提交改动，不覆盖或混入裂变实现。

## 10. 实现顺序

1. 先扩展动态能力/规则版本存储、学习事务和回滚统计。
2. 新增裂变领域模型、迁移、分析 runtime schema 和服务层。
3. 接入 `fission` 构图模板池和默认模板。
4. 实现款级方案编排、提示词编译、worker 和公共 POD 输出链路。
5. 接入独立计费画像、远端白名单和结算映射。
6. 新增前端入口、上传/确认/结果/重试页面并复用公共组件。
7. 完成后端、前端、计费和回归验收。

## 11. 非目标

- 不把裂变改造成复刻的多目标产品流程；
- 不按每款调用豆包生成构图参数；
- 不让用户编辑词表、能力、权重或最终 Prompt；
- 不因模型自报 confidence 分数阻止生成；
- 不让单款失败阻塞整批成功款；
- 不让历史批次随能力库新版本自动重算；
- 不修改全定制、半定制和爆款复刻既有业务语义。
