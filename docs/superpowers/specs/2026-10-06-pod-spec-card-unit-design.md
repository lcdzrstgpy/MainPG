# POD 规格卡印图单位设计

## 目标

在「批量添加尺寸」抽屉中，为尺寸卡增加厘米/英寸选择。用户填写和批次管理始终以厘米作为原始数据；图片尺寸卡与店小秘导出根据用户选择输出厘米或英寸。

## 用户交互

- 仅当「是否印到图上」选择「印到图上」时，展示「印图单位」选项。
- 单位选项为「厘米」和「英寸」，默认厘米。
- 切换到「不印」时隐藏单位选项，但保留上一次选择；重新选择「印到图上」时恢复该选择。
- 表格输入含义始终是厘米，切换印图单位不会改写输入框内容。
- 批次管理中的尺寸详情始终展示厘米原值。

## 数据模型与兼容性

- 在 `SpecCardConfig` 中新增 `display_unit`，合法值为 `cm`、`in`。
- `cells` 始终保存用户输入的厘米原值，作为唯一尺寸数据源。
- 草稿、批次冻结快照、预览与重印请求携带 `display_unit`。
- 旧草稿和旧批次缺少 `display_unit` 时默认 `cm`，不需要数据库迁移。
- 后端拒绝未知单位，避免静默生成错误尺寸。

## 换算与格式

- 厘米输出保持原值。
- 英寸输出按 `cm / 2.54` 换算。
- 结果最多保留两位小数，并去掉末尾无意义的零和小数点，例如：
  - `30 cm` → `11.81 in`
  - `25.4 cm` → `10 in`
- 只转换表格中每个 SKU 行的长、宽、高三列；SKU 名称不变。
- 图片尺寸卡表头明确显示单位：`Length (cm/in)`、`Width (cm/in)`、`Height (cm/in)`。
- 店小秘导出只写换算后的数值，不在数值中附加单位文本。
- 非数字、零或负数仍由现有提交校验拦截；转换层不猜测或修正非法输入。

## 数据流

1. 前端表格继续收集厘米数据，同时保存 `display_unit`。
2. 创建批次时，厘米 `cells` 与 `display_unit` 一起冻结进 `listing_fields.spec_card`。
3. 预览、正式生成与重印在渲染前，根据 `display_unit` 从厘米原值派生展示表格。
4. 店小秘导出读取同一冻结配置，根据 `display_unit` 派生导出尺寸。
5. 批次详情直接读取原始 `cells`，因此始终显示厘米。

## 组件边界

- 前端外观控件负责条件展示与单位选择，不执行数值换算。
- 前端配置模型负责默认值、克隆、草稿兼容和 API 序列化。
- 后端规格卡契约负责单位校验与旧数据默认值。
- 后端共享换算函数负责把厘米单元格派生为指定单位，供预览、生成、重印和导出复用，避免多处舍入规则不一致。
- Pillow 渲染器继续只负责绘制传入文本，不自行解释业务单位。

## 错误处理

- 未知 `display_unit` 返回现有规格卡配置错误，不进入渲染或导出。
- 换算遇到非法尺寸时沿用现有尺寸校验错误；不输出部分转换结果。
- 图片渲染失败继续沿用现有干净底图兜底，不阻断整个批次。

## 测试

- 前端：单位选项仅在「印到图上」时显示，默认厘米，切换隐藏后仍保留选择。
- 前端模型：新字段能够克隆、保存草稿、恢复草稿并提交 API；旧草稿默认厘米。
- 后端契约：接受 `cm`/`in`，旧配置默认厘米，拒绝未知单位。
- 换算：厘米不变；英寸除以 `2.54`；最多两位小数并去掉尾零；只转换三列尺寸。
- 规格卡链路：预览、正式生成和重印使用一致的表头与换算值。
- 店小秘导出：厘米保持原值，英寸输出换算值，旧批次保持厘米。
- 批次详情：无论输出单位如何，仍返回并展示原始厘米数据。

## 非目标

- 不允许用户直接以英寸录入尺寸。
- 不修改历史批次的原始尺寸。
- 不修改店小秘模板结构或新增单位列。
- 不改变「不印」时生成干净素材图的现有行为。
