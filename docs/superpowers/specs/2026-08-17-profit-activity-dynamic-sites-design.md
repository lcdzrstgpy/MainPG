# 利润活动动态站点设计

## 目标

管理员可以在利润活动设置弹窗中新建站点。新站点保存后立刻出现在站点切换中，并用于利润计算、产品入库、导入和活动过滤。

## 设计

保留 US、CO、EC 的现有专属计算规则。新建站点使用通用费率公式：

`总成本 = 成本 + 国内操作费 + (重量 × 头程每kg + 头程固定费) + 尾程固定费`

`毛利润 = 售价 + 运费补贴 - 总成本`

`净利润 = 毛利润 × (1 - 退款率) - 总成本 × 退款率`

新增站点的所有费率初始值为 0。站点代码使用 2–12 位大写字母、数字或下划线；名称为用户可读文本。代码、名称和费率由数据库保存并按工作区隔离。

## 数据与接口

新增 `profit_activity_sites` 表，每个工作区一行一个站点。表保存 `site_code`、`display_name`、`calculation_mode`、5 个基础费用及通用尾程固定费、补贴售价上限和退款率。旧站点不迁移到该表：它们继续读既有 `profit_activity_settings`，保证旧数据和历史利润不变。

`GET /api/profit-activity/sites` 返回内置站点与已创建站点；`POST` 创建站点；`PUT /{site_code}` 保存一个站点费率。服务层根据站点是否属于内置集合选择旧算法或通用算法。所有原有接受站点参数的 API 改为字符串参数，并通过服务层校验该站点存在。

## 前端交互

设置弹窗的站点标签由后端列表驱动，标签末尾放置“+ 新增站点”。点击后显示站点代码和名称输入框；提交成功后自动切换到新站点费率面板。关闭按钮改为固定 32px 方形、flex/grid 居中，避免 × 偏移。

## 兼容性与错误处理

站点代码不可与内置/已有站点重复；无效代码、空名称与负数费率返回明确错误。已有数据库运行 003 迁移创建新表并将站点代码字段从 2 位扩至 12 位，因此不会覆盖既有费率或产品记录。
