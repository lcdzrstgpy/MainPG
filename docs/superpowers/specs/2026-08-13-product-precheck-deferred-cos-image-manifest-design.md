# 产品预审统一图片清单与延迟 COS 发布设计

日期：2026-08-13  
状态：方案 A 已口头确认，等待书面设计复核  
适用模块：产品处理预审、尺寸画布、图片生成、店小秘最终版导出

## 1. 背景与已确认决策

产品预审当前以 URL 字符串数组保存主图、轮播图和详情图，图片来源包含来源原图、AI 生成图、尺寸画布成图和用户本地导入图。现有实现存在三个结构性问题：

1. 预审本地上传时立即调用 COS，与“预审完成后统一发布”冲突；失败时还可能回退本地 URL。
2. 前端“上传追加轮播图”实际会替换当前主图所在位置，无法可靠追加。
3. 后端清理覆盖数据时会丢弃空图片列表，用户删除全部图片后再次加载会恢复默认图片。

用户已确认采用方案 A：引入统一图片素材清单。预审期间只编辑本地或已登记素材；现有“导出最终版表格”升级为“完成预审并导出”，在该动作后把最终仍被引用、且尚未发布的图片统一发布到 COS。全部发布成功后才能生成店小秘最终版表格。

这里的“COS 转换”定义为发布到 COS 并取得可信公网 HTTPS 地址，不代表重新压缩或改变图片编码。支持的原始图片应尽量原字节上传，避免质量损失。

## 2. 目标

- AI 生成图、尺寸图、本地导入图和被选入输出的来源图使用统一、稳定的素材身份。
- 主图、轮播图、详情图中的生成图、尺寸图、本地导入图都能可靠添加、删除和排序。
- AI 生图、预审编辑、尺寸画布渲染及尺寸图交回审核期间都不调用 COS。
- 用户完成预审后异步、并发地发布最终图片，避免页面长时间无反馈。
- 已成功发布的内容不重复上传；失败重试只处理未成功图片。
- COS 发布失败、并发修改或进程重启均不能造成草稿丢失、错图或含本地路径的最终表格。
- 最终导出只使用经过服务端验证的公网 HTTPS 图片地址。
- 旧任务无需人工迁移即可继续预审和导出。

## 3. 非目标

- 本次不改变 AI 生图提示词、模型选择或图片生成质量策略。
- 本次不删除用户的来源原图，也不在用户点击“删除”时立即物理删除本地文件或 COS 对象。
- 本次不直接提交店小秘；仍只生成符合现有字段合同的最终版表格。
- 本次不让浏览器直接持有 COS 密钥或直传 COS。
- 本次不把来源素材库本身变成图片管理器；删除仅影响当前商品的输出清单。

## 4. 核心模型

### 4.1 统一素材记录

新增工作区隔离的预审素材记录 `PreviewImageAsset`，至少包含：

- `id`：不可变素材 ID，API 和预审清单只引用该 ID。
- `workspace_id`、`task_id`、`product_draft_id`：所有权边界。
- `origin`：`source`、`generated`、`dimension` 或 `upload`。
- `managed_path`：服务端受管本地文件路径，仅后端内部可见。
- `source_url`：旧任务来源 URL 或需要安全抓取的外部来源；不作为最终发布凭据。
- `content_hash`、`content_type`、`byte_size`、`width`、`height`：验证、去重和发布依据。
- `availability`：`local`、`materializing`、`ready`、`publishing`、`published` 或 `publish_failed`。
- `public_url`：成功发布后由服务端写入的可信 COS HTTPS 地址。
- `publish_claim_token`、`publish_claimed_at`：多进程发布租约。
- `created_at`、`updated_at`。

尺寸画布无需复制图片文件。尺寸图审核接受时，把现有受管渲染资产登记为 `origin=dimension` 的预审素材，并保留来源资产引用和内容哈希。

### 4.2 输出清单

预审覆盖数据新增版本化清单：

```json
{
  "image_manifest_v2": {
    "main_asset_id": "asset-id",
    "carousel_asset_ids": ["asset-id", "asset-id"],
    "detail_asset_ids": ["asset-id"]
  }
}
```

数组顺序就是最终导出顺序，空数组是有效状态，不能在清理或序列化时删除。`main_asset_id` 是引用，不再单独复制 URL。新上传并设为主图的素材默认同时加入轮播清单，避免主图与轮播内容脱节。

删除图片表示从当前清单移除素材 ID。素材记录与受管文件暂时保留，供撤销、失败重试和安全垃圾回收使用。垃圾回收必须是独立、延迟且仅清理无引用素材的任务，不属于本次交互路径。

### 4.3 AI 生成图落地

产品处理的 AI 生图阶段不再调用现有整组 COS 发布路径。模型返回的总览图、拆分轮播图和详情图先按原始支持格式保存到工作区受管目录，完成图片解码验证和内容哈希后登记为 `origin=generated` 的预审素材。任务结果保存素材 ID 和本地预览信息，不把本地绝对路径当成可导出 URL。

旧任务中已经发布到可信 COS 的 AI 图片继续登记为 `published` 并复用；新任务只有进入“完成预审并导出”的不可变快照后才发布最终保留的生成图。这样用户在预审中删除的生成图不会产生无效上传和图床费用。

## 5. 用户流程

### 5.1 打开预审

服务端返回每件商品的统一素材列表与输出清单。每张图片显示来源标签：来源图、AI 生成、尺寸图或本地导入。浏览器使用受控预览 URL 展示本地素材，不接收绝对路径。

旧任务首次读取时，服务端把现有结果字段、旧 `carousel_images`、`detail_images`、`main_image` 和语义槽位投影成稳定素材记录；第一次保存图片变更时写入 `image_manifest_v2`。旧字段只读兼容，后续不再写入。

### 5.2 添加图片

- 主图区提供“添加或更换主图”。新文件先保存为受管本地素材，随后设为主图并在尚未存在时加入轮播。
- 轮播区提供“添加图片”，支持一次选择多张，严格追加到末尾，不替换任何现有位置。
- 详情图区提供“添加图片”，支持一次选择多张并追加。
- 来源素材可执行“设为主图”“加入轮播”或“加入详情”，不会修改来源素材本身。
- 尺寸画布交回并审核接受后，尺寸图作为本地素材加入固定尺寸语义位置；在预审中仍可删除、移动或重新设置为主图。

上传接口只完成文件安全校验、本地保存和素材登记，返回 `asset_id` 与受控 `preview_url`，不调用 COS，也不返回 `managed_path` 或 `local_path`。

### 5.3 删除与排序

- 主图、轮播图和详情图中的每张图片均提供删除操作，包括 AI 生成图、尺寸图和本地导入图。
- 删除当前主图时，自动选择轮播中下一张有效图片；没有剩余图片时显示“待选择主图”，完成预审会被阻止。
- 删除后显示短时“撤销”提示，不弹出逐张确认框。
- 支持拖动或键盘按钮调整轮播、详情图顺序，排序结果直接写入 ID 数组。
- 来源原图区只移除输出引用，不删除来源素材记录。
- 轮播图和详情图允许明确保存为空；最终完成至少需要一张有效主图。

### 5.4 保存预审修改

“保存预审修改”只保存字段、素材引用和排序，不发布 COS。每件商品携带 `expected_preview_revision`；版本冲突时保留浏览器本地编辑并提示刷新或合并，不能用旧请求覆盖新清单。

### 5.5 完成预审并导出

原“导出最终版表格”按钮改为“完成预审并导出”。点击后：

1. 在同一请求中提交当前未保存修改及每件商品的预期版本。
2. 服务端事务内保存修改、验证主图与图片清单，建立不可变的完成快照及幂等键。
3. API 快速返回 `finalize_run_id`，后台发布任务开始，页面显示总数、已完成数、失败数和当前阶段。
4. 任务仅处理快照中仍被引用的素材。已持有有效发布凭据的 COS 图片直接复用。
5. 尚无内容哈希的外部来源图先经 SSRF 防护、大小限制和图片解码验证后保存为受管素材。
6. 使用工作区命名空间和内容哈希生成确定性 COS 对象键，默认最多并行 4 个上传，可配置范围为 1–6。
7. 所有图片发布成功后，再次核对商品预检版本仍与快照一致，然后生成最终版表格。
8. 页面收到完成通知并自动提供下载；用户可以离开当前页面，后台任务继续。

若完成期间发生新修改，旧完成任务不得覆盖新版本，也不得生成标记为最新的表格。已经发布的相同内容保留为可复用资产，下次完成无需重传。

## 6. 发布可靠性

每张素材独立使用数据库发布租约：

1. 原子写入随机 `publish_claim_token` 和 `publish_claimed_at`。
2. 只有持有当前 token 的工作进程可以标记成功或失败。
3. 活跃租约不能因另一服务启动而被释放。
4. 超过明确超时时间的租约才允许被下一次完成任务回收。
5. 上传前按确定性对象键执行存在性检查；上传成功但响应超时后，重试应先确认对象，避免重复 PUT。
6. `public_url` 必须为配置对应 COS 主机下的安全公网 HTTPS URL，验证失败按发布失败处理。

完成任务采用快照哈希作为幂等键。重复点击、浏览器重试或服务重启只能回读或恢复同一完成任务，不得创建重复最终表格或重复收费上传。

COS 配置继续复用图片生成环节的系统配置读取与后端解密逻辑。密钥只在内部发布适配器中使用，不进入素材 API、日志或错误消息。

## 7. 尺寸画布合同调整

当前尺寸画布在“交回审核”时发布 COS，新设计改为：

- 渲染完成：只生成本地受管 JPEG 和内容哈希。
- 交回审核：创建引用本地渲染资产的变更集，不调用 COS。
- 审核预览：使用受控 `/pp-media/` 预览 URL，不暴露绝对路径。
- 审核接受：把渲染资产登记进预审统一素材清单，并更新尺寸语义位置。
- 完成预审：由统一发布任务上传尺寸图，取得 COS URL 后再导出。

尺寸图仍保留原有 revision、目标槽位和冲突保护。变更集接受时可以接收本地素材 ID，但最终导出合同仍严格禁止本地 URL。

## 8. API 合同

建议新增或调整以下接口：

- `POST /tasks/{task_id}/preview/assets`：多文件本地导入，返回素材记录，不发布。
- `PATCH /tasks/{task_id}/preview`：保存文本、字段及 `image_manifest_v2`，要求预期版本。
- `POST /tasks/{task_id}/preview/finalize`：保存当前修改并创建异步完成任务。
- `GET /tasks/{task_id}/preview/finalize/{run_id}`：查询发布及导出进度。
- `POST /tasks/{task_id}/preview/finalize/{run_id}/retry`：仅重试失败或缺失素材。
- 现有 `/preview/export` 在过渡期可返回迁移提示或代理到新完成接口，前端不再直接调用同步导出。

素材 API 对外只返回：

```json
{
  "id": "asset-id",
  "origin": "upload",
  "preview_url": "/pp-media/...",
  "publication_status": "local",
  "public_url": null,
  "width": 2000,
  "height": 2000
}
```

绝不能返回受管绝对路径、COS 密钥、发布租约 token 或内部异常堆栈。

## 9. 安全与图片质量

- 本地导入仅接受 JPEG、PNG、WebP；拒绝伪装 MIME、动画、多帧图片、空文件和无法完整解码的图片。
- 复用现有 25 MiB、40 MP 等图片安全上限；所有路径必须由服务端生成并验证工作区归属。
- 外部图片抓取继续使用公网 URL、DNS/IP 重绑定、重定向、响应体大小和超时防护。
- COS 发布默认上传原字节，不因发布动作缩放、重新压缩或改变色彩空间。
- 最终表格生成前对每个图片地址执行服务端可信公网 HTTPS 校验；任何 `/pp-media/`、绝对路径、私网 URL 或不可信域名都会阻止导出。
- 日志仅记录素材 ID、内容哈希前缀、状态和错误码，不记录密钥或本地绝对路径。

## 10. 失败反馈

页面区分以下状态：待发布、发布中、已发布、发布失败、版本已变化。

- 单张失败时显示对应商品、缩略图和可读原因，但不清空用户编辑。
- 批次有任何必需图片失败时，不生成最终表格。
- “重试失败图片”只处理失败或尚未发布的素材。
- COS 未配置时，在开始完成任务前直接提示去系统设置配置，不能进入假成功状态。
- 服务重启后，未过期租约继续保留；过期任务由后续状态查询或重试安全恢复。

## 11. 性能策略

- 本地添加、删除和排序不等待网络图床，保存体验由本地磁盘与数据库决定。
- 完成接口在建立快照后尽快返回，上传与表格生成走后台任务。
- COS 上传为 I/O 并发，默认并发 4，不增加 AI 调用，也不重新生成图片。
- 按内容哈希跨重复操作复用同一工作区发布结果。
- 进度采用单个任务状态查询，不为每张图片建立前端轮询。
- 失败重试不重新下载、渲染或上传已成功素材。

## 12. 兼容与迁移

- 旧 `carousel_images`、`detail_images`、`main_image` 和 `image_slot_overrides` 保持读取兼容。
- 首次需要变更图片时，服务端在事务中建立素材记录和 `image_manifest_v2`，随后只写新清单。
- 旧 COS URL 只有在 HTTPS、安全 URL、主机匹配当前系统 COS 配置且对象存在时才视为已发布，否则在完成预审时重新物化和发布。
- 旧本地路径仅在后端归属验证通过后登记，永不直接返回浏览器或写入表格。
- 已生成的旧最终版表格不修改；重新完成预审会产生新的最终版文件。

## 13. 验收与测试

后端合同测试至少覆盖：

- 本地导入只保存本地素材，不调用 COS。
- 轮播追加不替换任何现有图片。
- 删除单张、删除全部轮播或详情图后保存并重载仍保持删除结果。
- 删除主图后的自动选择及无主图完成阻断。
- AI 生成图、尺寸图和本地导入图均可从输出清单删除。
- 尺寸图交回及审核接受不调用 COS，只加入本地素材。
- 完成任务忽略已删除素材，仅发布快照中仍被引用的素材。
- 内容相同图片只上传一次，重复完成与失败重试不重复 PUT。
- 单张上传失败阻止表格生成；重试只上传失败图片。
- 进程重启、租约过期、旧 token 迟到和多进程并发不会误标成功。
- 完成期间 revision 改变时不覆盖新清单、不生成旧版本最终表格。
- 旧任务可自动投影并迁移到新清单。
- 最终工作簿中不存在本地路径、`/pp-media/`、HTTP 或私网图片地址。
- 工作区 A 无法读取、删除或发布工作区 B 的素材。

前端测试至少覆盖：

- 主图、轮播和详情区的添加与删除。
- 多文件追加顺序稳定。
- 删除撤销、主图自动切换和空状态。
- 保存冲突时本地编辑不丢失。
- 完成进度、失败缩略图、仅失败重试和完成后下载。
- 页面刷新后可恢复正在运行的完成任务。

浏览器验收流程：导入本地图片 → 接受尺寸图 → 删除一张 AI 图和尺寸图 → 调整顺序 → 保存并刷新 → 完成预审 → 观察 COS 进度 → 下载最终表格 → 验证所有最终图片为可访问 COS HTTPS 地址且图片质量未变化。

## 14. 完成标准

满足以下条件才算本功能完成：

1. 预审图片操作全部基于稳定素材 ID，不再依赖易错的 URL 数组索引。
2. 所有输出图片区可以添加和删除，空列表删除语义能够持久化。
3. 预审阶段和尺寸图交回阶段没有 COS 写操作。
4. “完成预审并导出”统一发布最终保留图片，并提供可恢复的异步进度。
5. 发布幂等、并发、租约、失败续传和 revision 冲突测试通过。
6. 最终工作簿只包含可信公网 COS HTTPS 图片，且发布过程不降低图片质量。
7. 旧任务无需人工操作即可继续使用。
