# 豆包图文联合主体识别设计

## 目标

固定使用原始 1688 主图和原始 1688 标题做一次豆包多模态主体识别，降低仅凭复杂场景主图误判可售主体的概率。

## 数据流

`1688 原始主图 + 原始标题 → 豆包主体 JSON → 豆包文本与 GPT 生图并行`

- 图片是主要视觉证据。
- 标题是辅助身份事实，必须作为不可信数据明确包裹，不能被当成提示词执行。
- 图文一致时正常返回 `high` 或 `medium`。
- 图文明显冲突、标题无法对应可见商品或主体仍不明确时返回 `low`，并在 `uncertainty_reason` 解释冲突。
- 主体 JSON 合同、低置信度阻断和后续并行分支保持不变。

## 缓存和回执

- 豆包识图缓存键和 `vision_identity` 阶段回执哈希同时包含原始主图与原始标题。
- 标题变化必须使旧识图回执失效。
- 热缓存重试不重复调用豆包识图；图片或标题任一变化都执行新的识图调用。

## 验证

- 单测验证同一豆包请求同时包含图片和标题，且标题被标记为不可信辅助证据。
- 单测验证服务层把原始标题传给识图，不传豆包优化标题。
- 重启本地后端后，对同一麻将商品执行一次冷缓存处理和一次热缓存重试。
- 实时监控任务状态、`vision_identity`、`doubao_text`、`images` 阶段回执和供应商尝试次数。
