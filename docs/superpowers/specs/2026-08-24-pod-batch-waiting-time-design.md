# POD 批次累计等待时间设计

## 目标

在 POD 当前批次的进度条信息中，向用户展示从批次创建时刻开始累计的实时等待时间，例如“已等待 2分35秒”。

## 展示与数据

- 仅状态为进行中的批次显示等待时间：`queued`、`generating_patterns`、`compositing`、`generating_titles` 和 `settlement_pending`。
- 等待时间以批次既有的 `created_at` 为起点；前端每秒重新计算并格式化为中文分钟、秒钟。
- 信息显示在进度条右侧的完成、失败和百分比统计之前，格式为“已等待 2分35秒 · 完成 2 款 · 失败 38 款 · 100%”。
- 批次结束后不显示“已等待”，保持原有完成、失败和百分比统计；不将已完成批次的总耗时伪装成仍在等待。

## 范围与兼容性

- 不新增 API 字段、数据库迁移或服务端计时任务；继续使用当前批次响应中的 `created_at`。
- 新增独立的纯函数处理持续时间格式化和展示资格，避免页面组件包含状态判断逻辑。
- 页面使用本地每秒时钟只驱动活动批次的文本刷新；现有轮询与批次进度计算逻辑不变。

## 验收

- 创建不足一分钟的活动批次显示类似“已等待 35秒”。
- 活动批次在页面停留期间每秒更新一次展示值。
- 已完成、部分失败和失败批次不显示“已等待”。
- 无效或未来的创建时间安全显示为“已等待 0秒”。
- 现有进度百分比、完成数、失败数及移动端布局保持可用。
