# 图搜重新执行按钮悬浮设计

## 目标

在核价流程的“货源关联”区域，移除“待图搜 N 个 SKC”状态文案。保留原位置的图搜操作；当“重新图搜”随内容滚动而被顶部栏遮挡时，提供一个从页面底部浮出的同功能按钮，使用户无需返回图搜区域顶部即可再次执行搜索。

## 范围

- 仅修改 `SourcingPanel` 的界面和交互状态。
- 不改变图搜请求、候选结果、按钮禁用条件或后端接口。
- 不修改全局的返回顶部箭头。

## 交互设计

1. 移除标题操作区的“待图搜 N 个 SKC”元素，并随之移除仅为该文案传递的 `sourceCount` 属性。
2. 标题操作区继续展示既有图搜按钮：首次搜索为“执行图搜（N）”，已有结果时为“重新图搜”，执行期间为“图搜执行中…”。
3. 仅在已有搜索结果、标题栏的“重新图搜”按钮已被顶部固定区域遮挡、且该操作本身可显示时，显示右下角浮动的“重新图搜”按钮。
4. 浮动按钮位于返回顶部箭头左侧，避免遮挡；视觉采用现有蓝绿渐变、阴影及显示/隐藏的上浮过渡。
5. 浮动按钮调用与标题按钮相同的 `onStart`，并复用同一 `busy` 与可执行条件。原按钮重新可见时，浮动按钮立即收起。

## 实现设计

- 在 `SourcingPanel` 内为标题按钮建立 ref 和 `isRefloatVisible` 状态。
- 同时监听窗口和 `.content-card` 的滚动与窗口尺寸变化。每次更新时读取原按钮的可视位置；其底部越过顶部栏的安全边界，即判定为被遮挡。
- 使用 `preview` 与现有禁用规则保护浮动入口，避免在首次执行按钮或无可重搜项目时展示无法操作的“重新图搜”。
- 补充独立的 `pv-source-refloat-button` 样式，保留键盘焦点样式并在窄屏下调整位置与尺寸。

## 验收标准

- 页面不再出现“待图搜”及 SKC 数量文案。
- 图搜结果存在时，下滚至原“重新图搜”按钮被顶部栏遮挡，右下角回顶箭头旁出现可用的“重新图搜”。
- 滚回原按钮可见位置后，浮动按钮消失。
- 点击任一入口仅触发一次原有图搜操作；忙碌中两个入口都不可重复触发。
- 在窗口滚动与应用内容容器滚动两种场景中均可正确切换。
