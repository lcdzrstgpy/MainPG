# 产品处理时长优化方案 B 设计

- 日期：2026-08-13
- 状态：用户已批准方案方向，等待书面规格复核
- 目标分支：`codex/product-processing-duration-optimization`
- 适用代码：MainPG `dev@445cf44`
- 实施边界：本设计不降低图片模型档位、图片尺寸、OCR、商品身份、标题或导出质量门

## 1. 背景与基线

最近一次真实本地任务为任务 5，共 4 件商品：

| 指标 | 基线 |
| --- | ---: |
| 批次总耗时 | 670.359 秒 |
| 首件完成 | 约 339 秒 |
| 第二件完成 | 约 390 秒 |
| 第三件完成 | 约 396 秒 |
| 最后一件完成 | 约 671 秒 |
| 成功 | 4/4 |

文本组合和尺寸缓存最晚在任务开始后约 114 秒落盘。第一件仍需约 225 秒才完成，最后一件又多等待约 332 秒。最后一件记录了 `four_grid:chinese_repaired`，说明额外执行了一次完整 2K 图片修复。

四件商品都来自 `cbu01.alicdn.com`，每件有 8 张来源图。当前流程会在视觉识别、四宫格生成、OCR 修复和本地详情图合成之间重复下载图片；其中四宫格参考图串行读取，单个远程地址存在最多三个 30 秒下载变体。任务结束后数据库中已有 67 张来源图处于本地 `ready` 状态，但主处理链没有优先复用这些本地文件。

当前代码还有四个观测缺口：

1. `finish_task()` 会把全部 item 的 `updated_at` 重写为同一个任务结束时间。
2. 没有保存 item 的阶段开始、结束和等待时间。
3. 文本客户端丢弃响应模型和 request ID，不能对齐中转站实际路由。
4. 图片重试没有完整执行 `image_stop_after_billable_failure` 等已保存配置。

## 2. 目标与非目标

### 2.1 性能目标

基于相同输入、同一 `gpt-image-2-2k` 模型、相同质量门：

- 4 件基准批次总耗时目标不超过 360 秒。
- 首件完成目标不超过 180 秒。
- 相同条件下端到端 P95 至少下降 35%。
- 来源图远程下载次数不超过实际缺失的唯一 URL 数。
- 详情图本地合成不得下载刚刚生成或上传的四宫格图片。
- 健康任务中，每件商品默认只有 1 次 2K 四宫格生成；只有原始生成图未通过 OCR 时才允许修复调用。

上述数值是放行目标，不是未验证的交付承诺。达不到时不以关闭质量门、降为 1K 或减少来源证据换取达标。

### 2.2 质量目标

- 图片请求模型继续固定为 `gpt-image-2-2k`，请求尺寸继续为 `2048x2048`。
- 保持每件商品 4 张独立轮播图、1 张四宫格汇总图、1 张详情图。
- 轮播图继续输出 800×800，商品完整、结构、颜色、材质、数量和主要细节不得改变。
- 保留视觉主体识别、目标语言校验、OCR 中文检测和修复兜底。
- TEMU 英文标题的生成、校验和选择逻辑不因本次优化降级。
- 图片文字必须为清晰、拼写正确的英文，不允许中文、乱码、裁字或文字覆盖商品。
- 不跨商品或跨任务复用生成图片。
- 不减少来源参考图证据，不使用旧生成图替代本次新生成图。

### 2.3 非目标

- 不切换到 1K 模型。
- 不增加额外付费文本调用。
- 不重写整个产品处理模块或引入新的任务队列基础设施。
- 不改变店小秘字段、SKU 数量、类目、属性或导出合同。
- 不部署、不推送到生产，也不触发真实 provider，除非后续获得单独授权。

## 3. 选定方案

采用方案 B，由五个互相独立、可分别关闭的改造组成：

1. 任务级来源图片包和请求合并。
2. 媒体字节全程内存传递。
3. 2K 无营销文字画面加本地确定性英文排版。
4. 安全的阶段并行和按错误类型重试。
5. 阶段计时、真实模型和尝试记录。

优化后的主链：

```text
预检
  -> 准备 ReferenceImageBundle
  -> 视觉识别
  -> 生成标题、描述与规格翻译
  -> 并行执行：尺寸重量 / 2K 四宫格生成
  -> 原始四宫格 OCR
  -> 必要时 2K 修复（复用 ReferenceImageBundle）
  -> 内存拆分四宫格
  -> 本地英文排版
  -> 使用内存分图合成详情图
  -> 六张图片并行发布
  -> 最终语言、图片和导出质量门
```

## 4. 来源图片包

### 4.1 数据结构

新增任务级 `TaskReferenceStore` 和 item 级 `ReferenceImageBundle`。Store 以规范化 URL 合并同一任务中的下载；Bundle 是某一商品按原顺序选择出的参考图视图，不会把另一商品的不同 URL 当成可复用来源。每个成员至少包含：

```python
ReferenceImage(
    source_url: str,
    local_path: Path,
    content_type: str,
    filename: str,
    sha256: str,
    origin: Literal["local-library", "draft-file", "remote"],
)
```

来源图使用已验证的内容寻址本地文件，调用阶段按需打开；不让大批任务把全部来源图字节长期常驻内存。Bundle 不保存模型生成图片，也不允许用相似 URL 或相似图片跨商品猜测复用。

### 4.2 获取顺序

对每个来源 URL：

1. 查询 `product_processing_source_images` 中已验证的 `local_path`。
2. 检查草稿自身的托管文件路径。
3. 仅在本地不可用时进行安全远程下载。
4. 对同一 URL 合并同时发生的下载请求。
5. 最多并行准备四张被图片模型实际使用的参考图。
6. 某张失败时按原有顺序尝试下一张来源图，不能降低最终参考图数量要求。

远程下载继续保留 URL 安全校验、响应类型、图片魔数、大小、重定向和超时边界。缓存键必须包含规范化 URL；缓存内容只在当前任务生命周期内有效。

### 4.3 复用边界

同一个 Bundle 同时提供给：

- 视觉主体识别的数据 URL 构造。
- 图片编辑 multipart 文件读取。
- OCR 修复的再次请求。
- 图片相似性或来源证据检查。
- 来源图库持久化。

修复阶段直接复用 Bundle，不允许再次访问 `cbu01.alicdn.com`。

## 5. 媒体内存流水线

### 5.1 新返回合同

四宫格阶段不再只返回已发布 URL，而是先返回内部对象：

```python
GridBuildResult(
    original_grid: GeneratedMedia,
    carousel_parts: list[GeneratedMedia],
    summary: GeneratedMedia,
    ocr_status: str,
    repair_count: int,
)
```

本地详情图直接读取 `carousel_parts[*].content`，不下载 COS URL，也不读取刚刚落盘的临时文件。

### 5.2 发布顺序

完成本地排版和详情图合成后，将以下 6 个对象一次性交给发布器：

- 四张轮播图。
- 一张四宫格汇总图。
- 一张详情图。

发布器使用有界线程池并行上传。任一上传失败时，保持现有“整组回退本地托管路径”的语义，不返回一半 COS、一半本地的混合组。

### 5.3 输出兼容

对外结果字段保持不变：

- `carousel_image_paths`
- `grid_image_summary_path`
- `detail_image_paths`

店小秘工作簿和前端无需理解新的内部媒体对象。

## 6. 本地确定性英文排版

### 6.1 生成职责分离

模板 A 的图片模型只负责：

- 商品身份与细节。
- 四个既有场景角色。
- 光线、材质、背景和构图。
- 每个 panel 内预留明确的安全排字区域。

模型提示词禁止新增营销文字、标题、徽章和标签，避免生成乱码或中文。商品本体和包装仍按既有商品真实性合同处理。

### 6.2 文案来源

不增加新的 AI 调用。排版内容只使用现有结果：

- 标题：已经通过 TEMU 标题校验的 `optimized_title`，提取可放入 panel 的短商品名。
- 卖点：已经生成的 description 要点和 `listing_prompt_context()` 中的来源可验证属性。
- 尺寸：只有来源数据存在明确尺寸时才允许显示。
- 场景短语：只有已有上下文能够直接支持时才显示；没有证据时留白。

任何无法回溯到现有标题、描述或来源事实的短句直接丢弃，不为凑满条数编造文字。

### 6.3 排版规则

- 在每个原始约 1024×1024 panel 上绘制，再统一缩放为 800×800。
- 使用固定、可随安装包发布的 SIL OFL 字体，并随仓库保留许可证。
- 文字区域、最大宽度、最大行数、字号下限和行距均由模板定义。
- 使用 Pillow 真实测量字体边界，禁止文字越界、裁切或重叠。
- 文本颜色按背景局部亮度在深色与浅色主题间确定性选择，并保持最低对比度。
- 排版无法安全放入时减少次要卖点，仍失败时该 panel 保持无文字，不移动或遮挡商品。
- 模板 B 保持现有无文字视觉方向，不强制增加排版。

### 6.4 OCR 顺序

1. 对模型原始 2K 四宫格执行 OCR。
2. 检出中文时继续走现有 2K 修复兜底，但复用来源图片包。
3. 修复通过后拆分和本地排版。
4. 对最终轮播图和详情图执行一次中文复验。

本地英文排版不会生成中文，因此最终中文只能来自模型画面或商品本体，原有质量门仍能拦截。

## 7. 阶段并行

### 7.1 保持顺序的阶段

以下依赖不改变：

- 视觉主体识别先于最终标题。
- 最终标题先于图片提示词格式化。
- OCR 通过后才能拆分和发布。
- 所有媒体与语言质量门通过后才能导出。

### 7.2 可以并行的阶段

最终标题生成后，同时启动：

- 产品尺寸和重量补缺。
- 2K 四宫格生成。

图片提示词不读取 `_generate_size()` 的估计结果；尺寸 panel 只使用来源明确尺寸，因此两者没有数据依赖。

本地拆图、排字和详情合成仍在单个商品内部顺序执行，避免嵌套线程池放大 CPU。上传使用独立有界池。

### 7.3 资源边界

- 外层商品并发继续由 `max_parallel_drafts` 控制。
- 来源下载与图片 provider 请求使用不同的资源限制。
- 图片 semaphore 只包围真正的 provider 请求，不在远程下载时占用图片生成 seat。
- 不把并发数字直接调大作为性能方案。

## 8. 重试和模型健康

### 8.1 图片错误分类

| 错误 | 行为 |
| --- | --- |
| 本地文件损坏、参考图不可解析 | 换下一张来源图，不调用 provider |
| HTTP 400/401/403/404 | 不重试同一请求，立即记录配置或参数错误 |
| HTTP 429 | 按 Retry-After 或有界退避重试 |
| HTTP 5xx、连接建立失败 | 在 `image_retry_attempts` 预算内重试 |
| 请求已发送但响应结果未知 | 执行 `image_stop_after_billable_failure`，禁止无证据盲重放 |
| OCR 未通过 | 只允许现有最大修复轮数，不扩大预算 |

没有可靠幂等键时，“已发送但结果未知”不能被当作普通网络失败，否则可能重复计费和重复生成。

### 8.2 探活

保留 `POST /product-processing/ai/ping` 手动接口。可以增加后台 TTL 健康快照，但不得在每件商品关键路径同步调用 `/models`。健康快照只用于提前显示配置故障和控制熔断，不替代真实请求结果。

### 8.3 实际模型记录

文本和图片尝试记录：

- requested model
- selected fallback candidate
- provider response model（存在时）
- provider request ID（存在时）
- latency
- status class
- retry reason

不得记录 API key、Authorization、完整提示词、图片字节或供应商响应正文。

## 9. 阶段计时与进度

item 固定阶段：

```text
preflight
reference_prepare
subject_identity
combined_text
size_estimation
grid_generation
grid_ocr_repair
local_media_build
publish
export_ready
```

任务结果保存每个阶段的：

- queued_at
- started_at
- finished_at
- duration_ms
- attempt_count
- requested_model
- response_model
- outcome

数据库迁移在 `product_processing_task_items` 上新增可选字段：

- `current_stage`
- `stage_started_at`
- `stage_timings_json`
- `provider_attempts_json`

旧代码忽略这些字段仍能读取任务。`finish_task()` 不再覆盖已经完成 item 的 `updated_at`，使第一件和最后一件完成时间可信；只给尚未写入终态时间的兼容旧 item 补写结束时间。

前端第一版只需显示当前阶段、已运行时长和最近进展，不需要新建复杂监控页面。

## 11. 测试设计

### 11.1 单元测试

- 同一 URL 在视觉、生成和修复阶段只下载一次。
- 本地图库命中时远程请求为零。
- 四张不同 URL 并行下载的墙钟时间接近最慢单张，而不是四张之和。
- 参考图失败时按原始顺序补位，最终 Bundle 顺序稳定。
- 详情图只读取内存媒体字节，不访问 HTTP 或 COS。
- 400/401/403 不重试；429、5xx 和连接失败按预算重试。
- outcome unknown 遵守 `image_stop_after_billable_failure`。
- 排版不越界、不裁字、不覆盖安全区外区域。
- 无证据文案被丢弃，不产生新卖点。
- OCR 修复仍只在中文命中时发生。
- `finish_task()` 保留 item 真实完成时间。

### 11.2 集成测试

使用假的文本、图片和下载 provider：

- 四件商品完整通过标题、尺寸、四宫格、OCR、详情和发布流程。
- 正常商品每件只有一次图片调用。
- 一件中文命中商品只有一次额外修复调用。
- 生成结果仍为 4 张轮播、1 张汇总、1 张详情。
- 模拟慢下载时验证请求合并和墙钟时间。
- 模拟慢尺寸调用时验证它与图片生成重叠。
- 旧开关关闭时保持当前调用顺序和结果字段。

### 11.3 图片确定性测试

保存不含敏感数据的固定四宫格 fixture：

- 验证分隔线检测与四格顺序。
- 验证输出全部为 800×800。
- 验证字体边界、对比度、行数和 JPEG 编码。
- 验证同一输入的本地排版字节稳定。
- 验证详情图直接使用相同的分格像素。

### 11.4 真实小样本验收

真实 provider 验收必须另获授权。冻结不少于 20 件商品，覆盖长条商品、透明材质、金属、毛绒、多规格、带来源文字和无文字商品。

新旧结果盲评：

- 商品身份与结构。
- 颜色、材质和数量。
- 构图与商业质感。
- 英文文字清晰度与拼写。
- OCR 中文残留。
- 分割后四张独立可用性。
- TEMU/店小秘输出兼容性。

任一错误 SKU、商品变形、中文残留或文字遮挡均阻止启用 `local_grid_typography_v1`。

## 12. 性能验收

分两层证明：

### 12.1 离线确定性基准

使用固定延迟假的 provider 和已保存媒体响应，证明：

- 下载请求合并有效。
- 下载从串行变为有界并行。
- 尺寸与图片阶段发生重叠。
- COS 回下载为零。
- 本地拆图、排版、详情合成总耗时保持在秒级。

### 12.2 真实批次基准

使用相同商品集合、同一配置和同一模型，分别记录：

- time to first progress
- time to first completed item
- end-to-end batch wall time
- 每阶段 p50/p95
- provider attempt 数
- 远程来源下载数
- OCR 修复率
- 质量门通过率

完整方案放行要求：

- 4 件基准批次不超过 360 秒。
- 首件不超过 180 秒。
- 相同样本 P95 至少下降 35%。
- 标题、图片、SKU 和导出质量指标不下降。

## 13. 实施顺序

### 阶段一：只增加事实观测

- 阶段计时与真实 item 完成时间。
- 模型、request ID 和重试原因记录。
- 不改变调用顺序和输出。

### 阶段二：无输出变化的运输优化

- ReferenceImageBundle。
- 本地库优先和下载请求合并。
- 并行下载。
- 媒体内存传递和六图并行发布。
- typed retry。

使用录制响应证明输出字段和本地图片处理等价。

### 阶段三：本地排版

- 模板 A 改为无营销文字并预留安全区。
- 本地英文排版。
- 最终 OCR 复验。
- 功能开关默认关闭，完成盲评后再启用。

### 阶段四：阶段并行

- 标题完成后并行尺寸和2K出图。
- 使用阶段计时证明真实重叠。
- 不扩大外层商品并发。

## 14. 回滚

- 所有数据库变化只新增可选字段或表，不删除旧结构。
- 每个优化点有独立 feature flag。
- 关闭全部新开关即恢复旧下载、旧媒体和旧排字路径。
- 任务绑定创建时的合同版本，处理中不热切换。
- 新结果字段只作为附加诊断，旧前端和旧导出仍可读取。
- 不修改已有任务结果或历史生成图片。

## 15. 预期收益与风险

| 改造 | 预期收益 | 主要风险 | 控制方式 |
| --- | --- | --- | --- |
| 来源图 Bundle | 消除重复远程下载和防盗链等待 | 错误复用图片 | 仅任务内、URL与摘要绑定 |
| 并行下载 | 最多四张等待从求和变为取最大值 | 瞬时请求增多 | 每商品最多4、全局 external I/O 限流 |
| 内存详情合成 | 消除上传后回下载 | 内存占用增加 | 单商品对象、完成后释放 |
| 本地排版 | 清晰文字并降低OCR重绘率 | 覆盖商品或版式僵硬 | 安全区、文字测量、无字回退、盲评 |
| 阶段并行 | 隐藏尺寸模型延迟 | 嵌套并发膨胀 | 独立资源限制，不提高商品并发 |
| typed retry | 减少无意义长尾和重复计费 | 过早停止可恢复错误 | 只停止确定不可重试或 outcome unknown |

方案 B 的主要性能收益来自删除重复工作，不依赖更便宜或更低质量的模型。最大的产品行为变化是“模型排字改为本地排字”，因此它必须作为最后一个独立开关，通过真实图片盲评后才能默认启用。
