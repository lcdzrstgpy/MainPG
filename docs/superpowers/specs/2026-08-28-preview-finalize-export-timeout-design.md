# 产品预检最终导出卡死修复设计

## 背景

产品处理任务在最终预检阶段会先将选中的图片发布到 COS，再生成店小秘导入表格。任务 #54 已完成 10 张图片发布，但在最终表格生成前的公网链接校验中长期停留在 `publishing`。现有校验对每张已发布图片再次执行同步 DNS/公网地址解析；本机代理或 DNS 回退阻塞时，后台线程会持续续租，前端只能无限显示 100%。

## 目标

- 已由发布流程确认并持久化为 `published` 的图片可以直接用于最终 xlsx。
- 最终导出仍拒绝空值、非 HTTPS 或未发布的图片链接。
- 链接解析暂时异常不能让最终导出后台任务无限停留在 `publishing`。

## 方案

在 `PreviewImageService.run_finalize` 中，将 `asset_urls` 作为可信的已发布最终图片集合传给导出行构造逻辑。该集合仅来自成功发布的 `PreviewImagePublication` 记录，且发布流程已执行 COS/公共图床信任校验。

导出阶段校验改为两层：

1. 校验最终图片值非空、为 HTTPS URL，且对应快照资产来自本次成功发布的可信集合。
2. 不在 xlsx 生成的同步后台线程中再次进行 DNS 或 DoH 解析。

原有来源链接、手工输入链接和图片发布阶段的网络安全校验保持不变。此变更只覆盖已经完成受控发布、将要写入最终表格的资产 URL。

## 失败处理

- 如果快照中缺少成功发布 URL，任务继续以 `publish_failed` 结束并保留明确错误。
- 所有必要 URL 都已发布时，xlsx 写入后标记 `completed` 并提供下载链接。
- 后续可单独增加任务级超时保护；本次不改变线程、租约或重试语义。

## 测试

新增回归测试，注入一个会抛出或阻塞的 URL 解析器，并证明：受控发布的 HTTPS 图片仍可生成最终工作簿。现有测试继续覆盖缺失或不安全最终图片导致失败的场景。

## 范围

仅修改产品处理的预检最终导出服务及其测试；不修改 POD、多线程调度、COS 发布协议、前端交互或任务数据库结构。
