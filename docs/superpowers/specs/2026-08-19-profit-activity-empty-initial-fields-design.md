# 利润活动初始字段空置设计

## 目标

利润活动页面首次进入时，单品利润表单不再预填示例数值，活动申报门槛也不再使用 8 元 / 20% 的系统预设。用户明确保存过的活动门槛继续跨页面加载回显；恢复默认设置改为清空门槛。

## 页面行为

### 单品利润

- 商品 ID、售价、成本、重量 KG 初始均为空。
- 商品 ID 的“支持 SKU、SKC 或 SPU”及其他必填占位提示保留。
- 入库成功后的表单清空行为保持不变。
- 四项必填数据未填写完整时，不触发利润预览，也不能入产品库。

### 活动申报门槛

- 后端设置新增 `activity_threshold_configured` 布尔标记。
- 标记为 `false` 时，活动最低实际利润和活动最低利润率显示为空。
- 用户填写两个合法门槛并点击“保存设置”后，数值与 `activity_threshold_configured=true` 一起持久化；后续进入页面自动回显。
- 用户点击“恢复默认设置”后，后端保存两个数值为 0 并设置 `activity_threshold_configured=false`，前端立即清空两个输入框。
- 两个门槛任一为空或无效时，不允许保存设置、产品过滤或生成下载可申报产品，且显示明确提示；空白不能静默转换成 0。

## 数据模型与迁移

- `ProfitSettings`、数据库 ORM、API 设置模型和设置响应增加 `activity_threshold_configured`。
- 新建数据库的活动门槛数值默认 0，配置标记默认 `false`。
- 旧数据库增加该标记列并迁移现有数据：
  - 旧值恰好为 8 元和 20% 时，视为旧系统预设，改为 0 / 0，并标记为未配置。
  - 其他旧值视为用户配置，保留数值并标记为已配置。
- 旧库无法区分“系统预设 8/20”和“用户手工保存恰好 8/20”；按已确认规则统一视为旧系统预设并清空。

## 数据流与安全

页面加载设置时，费率字段继续按现有逻辑提取；两个活动门槛仅在 `activity_threshold_configured=true` 时转换为展示字符串。保存门槛必须显式发送配置标记。恢复操作发送未配置标记和 0 值，不保留隐藏的 8/20。

前端操作守卫阻止空门槛进入过滤流程；后端过滤入口也校验配置标记，避免绕过页面直接调用接口时使用未配置门槛。

## 不在范围内

- 不调整页面布局、标签、占位提示、站点费率字段或产品资料导入流程。
- 不改变已保存产品的售价、成本、重量或历史过滤结果。
- 不新增前端测试框架或其他运行时依赖。

## 验证

- 前端回归测试先验证现有示例值和 8/20 回填会导致失败，再验证六个字段的空白初始行为。
- 后端测试覆盖新设置默认未配置、保存后回显、恢复后清空以及旧数据迁移。
- 过滤服务测试覆盖未配置门槛时拒绝执行。
- 运行相关 Python 测试与前端生产构建，确认类型、迁移和打包无回归。
