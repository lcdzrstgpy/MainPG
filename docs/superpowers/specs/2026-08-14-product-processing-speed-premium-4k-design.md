# 产品处理提速与精品 4K 四宫格设计

## 目标

在不降低现有标题、描述、尺寸、侵权、OCR 与预审质量合同的前提下，同时提升普通与精品处理速度。删除任务页无业务意义的“单图×4 / 双图×2 / 四宫格×1”选择，普通处理固定一次 2K 四宫格，精品处理固定一次 4K 四宫格并本地拆成四张高清独立图。

## 用户流程

- 草稿池继续由用户逐商品勾选“精品”；未勾选即普通。
- 任务页不再显示或要求选择单次生图数量。
- 普通商品：一次 2K 四宫格，按现有质量门拆分；只有失败槽才允许 1K 定向补图。
- 精品商品：一次 `gpt-image-2-4k`、`4096x4096` 四宫格；精确中心拆分为四张约 `2048x2048` 图片，不缩到 800。
- 精品布局失败最多整体重试一次；仍失败时沿用现有来源图回退与人工预审，不回退到四次 1K。

## 性能架构

1. 文本模型首次路由探测只短暂阻塞同批请求；健康线路不再由首个慢请求串行堵住全批。
2. 同批模型连续超时、429 或 5xx 时进入短期冷却，后续商品沿现有 fallback 顺序跳过失败线路。
3. 普通与精品生图均在结构化文本通过后立即进入共享图片执行通道，同时并行尺寸和规格补全。
4. 来源图片下载采用现有线程安全 single-flight 缓存，并在文本阶段后预热图片生成所需参考素材。
5. OCR 运行时在远程生成等待期间预热；四格 OCR/编码使用本地并行处理。
6. 已完成阶段保存可恢复证据；失败重试优先复用已验证的文本和本地图片，不重复远程付费调用。
7. 前端继续显示阶段进度和耗时，不通过提高轮询频率制造“更快”假象。

## 图像质量合同

- 精品源图必须为正方形且至少 3840 像素；否则不作为高清四宫格成功结果。
- 分隔线必须位于中心容差内，四格不得跨区延伸，商品主体保留安全边距。
- 四格输出使用高质量 JPEG（quality 95、4:4:4）或等价无明显损失编码。
- 四张轮播图保留高清尺寸；仅四宫格汇总缩略图可缩放为 800。
- 现有 OCR、显著 AI 文字和来源图回退合同继续生效。

## 兼容与边界

- `image_generation_count` 后端字段暂时保留用于读取历史任务；新前端不再展示或依赖它，并将新任务固定为普通四宫格策略。
- 不改变用户此前要求保持不动的阶段缓存作用域和缓存策略。
- 不真实调用付费模型；本轮以契约测试、合成四宫格测试和前端构建验证。
- 不部署、不上传官网安装包、不推送分支，除非用户后续明确要求。

## 验收

- 任务页不再出现“单次生图”模块。
- 普通商品主生图一次 2K；精品商品主生图一次 4K。
- 精品成功结果包含四张约 2048 方图，中心分隔明确、互不串格。
- 健康模型首批文本请求可并发，不再等待首请求完整返回。
- 同批确认失败的模型不会被每个商品重复等待。
- 聚焦后端测试和前端 build 通过。
