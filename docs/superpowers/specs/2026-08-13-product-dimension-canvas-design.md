# 产品尺寸画布设计

日期：2026-08-13

状态：交互与技术方向已批准，等待书面设计复核

适用项目：MainPG 本地工作台产品处理、预检与最终版导出

## 1. 背景

现有产品处理存在两个不同问题，不能继续通过增加图片提示词解决：

1. 四宫格第 4 格允许图片模型绘制尺寸图。图片模型可能生成错误数字、单位、箭头或错位标注，结果无法可靠修正。
2. 当前 `SIZE_PROMPT` 生成的是物流包裹长、宽、高和重量，不是商品本体尺寸。把这些数值用于商品尺寸图会形成确定性的业务错误。

现有预检页已经能够展示来源图、主图、轮播图、详情图及长宽高，也能保存图片覆盖。但图片覆盖以完整数组保存，缺少稳定图片角色和版本冲突保护。批量尺寸图若继续按数组序号回写，容易在缺序、人工编辑或历史任务中覆盖错误图片。

因此新增独立的“尺寸画布”：图片模型只提供干净素材，数值、箭头、文字和最终合成由确定性程序完成。

## 2. 目标

### 2.1 核心目标

- 只使用商品本体尺寸制作尺寸图。
- 支持从预检页单商品送入，也支持从已完成处理任务批量导入。
- 支持选择来源图、AI 主图和四宫格分图作为底图。
- 用户可修改并确认商品本体长、宽、高。
- 用户选择长、宽或高后，在画布拖动两点创建双箭头尺寸线。
- 最终图片由后端按原始像素和语义标注高清渲染，不使用浏览器截图。
- 支持缺序处理、跳过、断点恢复、部分交回和批量交回。
- 审核页收到持久通知；用户接受后只更新目标尺寸槽位，其余图片不变。
- 单个与批量流程使用相同数据模型和回写合同。
- 尺寸画布不增加产品处理主链的模型调用和等待时间。

### 2.2 成功标准

- 100 条乱序、跳过、部分完成的商品回写零串图。
- 接受尺寸图后，只改变对应商品的尺寸槽位。
- 修改尺寸数值后，全部绑定标注同步更新。
- 输出尺寸图至少为 `2000×2000`，数字、单位和箭头清晰。
- 单商品操作无需重新上传表格或手工复制数据。
- 页面刷新、切换标签或异常关闭后能够恢复草稿。
- 不产生新的文本或图片 AI 调用。

## 3. 非目标

首版不做以下功能：

- 不让图片模型生成数字、箭头、单位或尺寸文字。
- 不根据商品照片比例猜测真实尺寸。
- 不把物流包裹尺寸自动转换成商品本体尺寸。
- 不从最终 Excel 重新反查商品。最终表格可能按 SKU 展开为多行，不适合作为身份来源。
- 不首发服装尺码表、多规格尺寸矩阵或复杂工程制图。
- 不自动提交店小秘或进行任何平台写入。
- 不替代预检页；尺寸画布只生产待审核图片变更。

## 4. 已选方案

采用“前端语义 SVG 编辑 + 后端高清确定性渲染 + 持久任务与变更集”。

### 4.1 未选择的方案

#### 纯前端 Canvas 导出

优点是开发快。缺点是远程图片跨域、浏览器截图清晰度、字体一致性、批量恢复和图片版本控制不可靠，因此不采用。

#### 全自动模板生成

优点是吞吐高。缺点是复杂商品的方向、起止点和留白难以可靠判断，仍会产生人工无法接受的标注位置，因此不作为唯一模式。

### 4.2 吸收的自动化能力

- 自动选择电商默认样式。
- 自动对比色。
- 自动预加载当前商品和下一商品。
- 自动保存。
- 可选“尺寸标注预备图”作为默认底图。
- 保留人工拖动端点、文字和目标槽位的最终控制权。

## 5. 业务口径

### 5.1 商品本体尺寸与物流包裹尺寸分离

新增独立的商品本体尺寸合同：

```text
physical_dimensions
├─ length
├─ width
├─ height
├─ unit
├─ provenance
├─ evidence_ref
└─ confirmed_at
```

现有 `product_dimensions` 在兼容期继续表示物流包裹尺寸，并逐步改名为 `shipping_package_dimensions`。它继续用于店小秘物流字段，但不进入尺寸画布。

### 5.2 本体尺寸来源状态

- `source_confirmed`：来源属性中存在明确商品尺寸，允许绘制。
- `manual_confirmed`：用户修改并明确确认，允许绘制。
- `unconfirmed`：可保存草稿，不可完成或交回。
- `package_estimate`：物流包裹估算，明确禁止用于尺寸图。

每个长、宽、高字段分别保存数值和证据状态。不能因为其中一个字段可信就默认其他字段可信。

### 5.3 本体尺寸采集

产品处理阶段只增加本地、确定性的来源属性解析，不增加模型调用：

1. 从结构化来源属性、明确单位字段和已捕获规格中提取。
2. 保留原始证据文本与来源字段引用。
3. 多组尺寸、含糊尺寸或规格冲突时标记 `unconfirmed`。
4. 没有可靠证据时留空，由用户在尺寸画布确认。

## 6. 导航与页面结构

### 6.1 侧边栏

新增可见一级入口“尺寸画布”，与“产品处理”并列。独立入口用于批量导入、继续历史草稿和查看待交回结果。

预检页每张商品卡右侧新增“添加尺寸图”。点击后创建或复用单商品画布任务，并打开尺寸画布标签页。重复点击不得创建重复任务。

### 6.2 桌面布局

```text
┌ 素材图：来源图 / AI 主图 / 四宫格分图 ─ 商品本体尺寸：长 / 宽 / 高 ┐
├ 工具栏 ─────────────┬──────────────────┬ 商品队列 ┤
│ 选择 / 撤销 / 重做   │                  │ 12 / 80  │
│ 长 / 宽 / 高 / 自定义│     尺寸画布     │ ● 已完成 │
│ 线色 / 字色 / 样式   │  拖动两点画箭头  │ ◐ 编辑中 │
│ 适应 / 缩放 / 重置   │                  │ ○ 待处理 │
├─────────────────────┴──────────────────┴──────────┤
│ 回写位置：轮播第4张      自动保存       完成并下一条 │
└──────────────────────────────────────────────────┘
```

### 6.3 顶部素材与尺寸区

- 素材缩略图显示来源角色：原图、AI 主图、四宫格 1–4、上传图。
- 点击缩略图切换画布底图，不改变回写目标槽位。
- 长、宽、高显示数值、单位和来源状态。
- 未确认使用警示色；确认后变为可绘制状态。
- 修改已绑定的尺寸字段后，所有对应标注文字自动刷新。
- 素材原始分辨率过低时显示质量警告。

### 6.4 工具栏与画布

首版工具：

- 选择与移动。
- 长、宽、高和自定义尺寸线。
- 撤销、重做、删除。
- 缩放、适应画布、重置视图。
- 自动对比色及黑白两种明确样式。
- 文字位置和箭头端点拖动。

绘制方式：

1. 选择一个已确认尺寸，例如“长 10 cm”。
2. 在画布拖动起点和终点。
3. 创建双箭头、尺寸文字和语义绑定。
4. 用户可移动端点和文字，不直接编辑渲染后的文字内容。

标注坐标使用相对画布的 `0–1` 归一化数值，确保不同显示尺寸和最终输出分辨率一致。

### 6.5 右侧商品队列

队列状态：

- 待处理。
- 编辑中。
- 待补尺寸。
- 素材失败。
- 已完成。
- 已交回。
- 回写冲突。
- 已接受。
- 已跳过。

只有鼠标位于右侧队列区域时，滚轮才切换商品。页面其他区域滚动不会误切。页面同时提供上一条、下一条按钮和键盘方向键。

切换商品前不弹出阻塞确认框；自动保存完成后切换。保存失败时停留当前商品并显示可重试错误。

## 7. 单商品流程

1. 用户在预检商品卡点击“添加尺寸图”。
2. 前端按 `workspace_id + task_id + task_item_id + product_draft_id` 幂等创建画布项。
3. 尺寸画布打开该商品，并加载素材元数据。
4. 用户选择底图，确认或修正商品本体尺寸。
5. 用户绘制一条或多条尺寸线。
6. “完成并下一条”运行本地校验并提交后台渲染。
7. 渲染成功后项目进入“已完成”，但不改变预检数据。
8. 用户点击“交回审核”，创建待接收变更集。
9. 审核页接受后，目标尺寸槽位更新。

## 8. 批量流程

### 8.1 导入

尺寸画布点击“导入已完成任务”，选择任务及商品范围。系统直接读取产品处理任务和预检数据，不重新解析 Excel。

导入预检分组：

- 可直接制作：素材可用且本体尺寸可信。
- 待补尺寸：本体尺寸缺失、不完整或冲突。
- 已有尺寸图：用户选择保留、重做或跳过。
- 素材不可用：允许后续重新选择或上传。

用户可只导入其中一部分商品。缺序导入不会压缩或重排身份。

### 8.2 编辑

- 元数据一次加载，高清图片按需加载。
- 自动预加载当前商品和下一商品。
- “完成并下一条”连续处理。
- 未完成项目可以跳过，稍后恢复。
- 批量状态按项目持久化，一条失败不阻塞其他项目。

### 8.3 批量交回

- 只交回已完成项目。
- 未完成项目保留在原批次。
- 后端异步渲染和发布，页面持续显示完成数、失败数和剩余数。
- 第一张完成后即可在审核变更集中查看，不必等待整批完成。
- 同一项目、同一画布版本使用幂等键，重复点击不重复渲染或回写。

## 9. AI 图片阶段调整

### 9.1 四宫格第 4 格

移除图片模型生成尺寸数字、箭头和单位的职责。第 4 格改为“尺寸标注预备图”：

- 商品完整、清晰、比例不变。
- 使用适合标注的正视、侧视或俯视构图。
- 四周预留安全空间。
- 禁止数字、单位、尺寸线、箭头和尺寸文字。
- 无法形成合适视图时生成普通干净补充图。

这不会增加图片调用；仍是一张 2×2 四宫格后本地拆分。

### 9.2 图片角色

新任务输出图片清单：

```text
carousel.hero
carousel.detail
carousel.lifestyle
carousel.dimension_background
grid.summary
```

历史任务按既有固定顺序建立兼容角色；第 4 张映射为 `dimension_or_extra`，用户开始尺寸制作后才明确升级为 `dimension_slot`。

## 10. 素材与目标槽位分离

尺寸画布必须区分：

- `selected_source_asset_id`：用于制作尺寸图的底图。
- `target_slot_id`：审核接受后要更新的轮播槽位。

选择来源原图或第 1 张 AI 图作为底图，不得覆盖该来源图片。默认目标为尺寸槽位：

1. 新任务使用 `carousel.dimension_background`。
2. 历史任务默认使用第 4 张轮播图，界面明确展示目标。
3. 不足 4 张时，在第 4 位插入尺寸图。
4. 已存在正确尺寸图并选择“保留”时，不创建图片变更。

主图和其他槽位只有在用户明确更改目标时才能被替换。

## 11. 数据模型

### 11.1 `dimension_canvas_batches`

保存批次级状态：

- `id`
- `workspace_id`
- `source_task_id`
- `status`
- `total_count`
- `completed_count`
- `failed_count`
- `created_at`
- `updated_at`

### 11.2 `dimension_canvas_items`

保存商品画布状态：

- `id`
- `batch_id`
- `workspace_id`
- `task_id`
- `task_item_id`
- `product_draft_id`
- `skc`
- `source_preview_revision`
- `selected_source_asset_id`
- `target_slot_id`
- `physical_dimensions_json`
- `annotations_json`
- `canvas_settings_json`
- `state`
- `render_revision`
- `render_asset_id`
- `error_code`
- `error_message`
- `created_at`
- `updated_at`

唯一约束覆盖 `workspace_id + task_id + task_item_id + product_draft_id`，保证单商品入口和批量入口复用同一项目。

### 11.3 `dimension_canvas_assets`

保存素材身份与快照：

- `id`
- `workspace_id`
- `item_id`
- `role`
- `source_url`
- `managed_path`
- `content_hash`
- `width`
- `height`
- `content_type`
- `availability`

客户端不能提交任意远程 URL 要求后端抓取。素材必须来自当前任务、受管上传或已登记资产 ID，避免跨域和任意网络访问风险。

### 11.4 `dimension_canvas_change_sets`

保存待审核变更：

- `id`
- `workspace_id`
- `source_task_id`
- `status`
- `item_count`
- `accepted_count`
- `conflict_count`
- `idempotency_key`
- `created_at`
- `accepted_at`

变更项保存商品身份、基础预检版本、目标槽位、旧资产 ID、新资产 ID、尺寸快照和渲染版本。

### 11.5 预检版本

给预检覆盖增加单调递增 `preview_revision`。标题、描述、核心字段或图片槽位发生保存时递增。

画布导入记录基础版本。审核接受变更集时：

- 版本一致：允许原子应用。
- 版本不一致但目标槽位未变：允许展示无冲突合并建议。
- 目标槽位或尺寸已变：标记冲突，禁止静默覆盖。

## 12. 图片槽位补丁

现有 `carousel_images` 完整数组覆盖保留兼容读取，但尺寸画布使用结构化槽位补丁：

```json
{
  "slot_id": "carousel.dimension_slot",
  "base_asset_id": "asset-a8f",
  "replacement_asset_id": "asset-f31",
  "base_preview_revision": 7
}
```

导出最终版时：

1. 读取生成结果的基础图片角色清单。
2. 应用已接受的槽位补丁。
3. 保持未修改槽位原顺序。
4. 保持 `grid.summary` 在最终轮播中的既有位置。
5. 再生成店小秘表格。

该结构避免当前完整数组覆盖导致四宫格总览丢失或其他图片被重排。

## 13. 前端状态与通知

### 13.1 自动保存

- 编辑动作进入本地即时状态。
- 采用短防抖后台保存。
- 保存期间继续允许画布操作。
- 每次保存携带项目版本；旧响应不得覆盖新状态。
- 网络或服务失败时保留本地状态并显示重试。

### 13.2 持久通知

尺寸画布交回后，后端创建工作区通知。通知包含：

- 变更集 ID。
- 来源任务。
- 完成、失败和冲突数量。
- 创建时间。
- 打开审核的动作。

`WorkspaceShell` 在页面可见、窗口重新获得焦点或定时轻量查询时刷新通知；页面隐藏时停止轮询。同一浏览器内同时发送即时事件，减少等待。

审核页显示“尺寸画布返回 N 项”。用户可以查看前后图片、尺寸与目标槽位，并执行：

- 接受全部无冲突项目。
- 单项接受。
- 拒绝单项。
- 打开冲突处理。

## 14. 渲染管线

### 14.1 输入

- 受管素材快照。
- 商品本体尺寸快照。
- 归一化标注。
- 画布裁切、适应和背景设置。
- 渲染样式版本。

### 14.2 处理

1. 验证素材哈希和尺寸。
2. 按画布设置将素材放入 `2000×2000` 输出画布。
3. 按最终像素坐标绘制双箭头、线条、文字和必要描边。
4. 使用项目内固定字体，禁止依赖未知系统字体。
5. 输出无损编辑母版。
6. 输出质量 95 的商用 JPEG。
7. 校验解码、尺寸、非空白和文字边界。
8. 保存受管资产并按现有媒体发布方式生成可导出 URL。

### 14.3 质量规则

- 数值从结构化字段格式化，不经过 OCR 或生成模型。
- 默认单位为 `cm`，统一小数格式并去掉无意义末尾零。
- 箭头和文字不能超出安全边距。
- 文字不得覆盖关键商品区域；首版由用户调整，自动对比色只负责可读性。
- 低分辨率素材允许继续，但必须显示警告。
- 上传或发布失败时保留本地渲染结果，可单项重试，不重新编辑。

## 15. API 设计

建议新增路由前缀：`/api/product-processing/dimension-canvas`。

核心接口：

- `POST /batches/import-task`：按已完成任务和选择范围创建批次。
- `POST /items/import-preview-item`：预检页幂等创建单商品项目。
- `GET /batches`：查询历史批次。
- `GET /batches/{batch_id}`：获取队列、统计和项目摘要。
- `GET /items/{item_id}`：获取素材、尺寸、画布和版本。
- `PATCH /items/{item_id}`：版本化自动保存。
- `POST /items/{item_id}/complete`：校验并提交渲染。
- `POST /items/{item_id}/retry-render`：复用画布数据重试渲染或发布。
- `POST /batches/{batch_id}/submit-review`：为已完成项目创建变更集。
- `GET /change-sets/{change_set_id}`：获取审核差异。
- `POST /change-sets/{change_set_id}/accept`：批量接受无冲突项目。
- `POST /change-sets/{change_set_id}/items/{item_id}/accept`：单项接受。
- `POST /change-sets/{change_set_id}/items/{item_id}/reject`：单项拒绝。
- `GET /notifications`：获取工作区待接收通知。

所有写接口限定当前工作区，并使用项目版本或幂等键。

## 16. 错误处理

### 16.1 可恢复错误

- 素材暂时下载失败。
- 本地渲染失败。
- 媒体发布失败。
- 自动保存暂时失败。

处理方式：保存当前草稿与错误码，允许单项重试，不影响批次其他项目。

### 16.2 需要用户处理

- 商品本体尺寸缺失或未确认。
- 多规格尺寸冲突。
- 目标槽位在审核期间被修改。
- 素材已变化或哈希不一致。
- 标注越界或不存在有效尺寸线。

处理方式：阻止完成或接受，展示明确商品、字段和解决动作。

### 16.3 不允许的降级

- 不使用物流包裹尺寸替代商品尺寸。
- 不让模型补猜缺失尺寸。
- 不因发布失败而覆盖原审核图片。
- 不因某一项失败而把整批标记成功或失败。

## 17. 并发、幂等与恢复

- 自动保存携带 `item_revision`，后端只接受预期版本。
- 前端采用 latest-wins，旧保存响应不得回写新状态。
- 完成渲染使用 `item_id + render_revision` 幂等。
- 交回审核使用批次、完成项目集合和渲染版本生成幂等键。
- 接受变更集按商品原子执行；一条冲突不阻止其他无冲突项目。
- 服务重启后，编辑草稿保持不变；运行中的渲染项目恢复为可重试，不自动产生重复发布。

## 18. 性能预算

- 100 商品元数据导入：目标不超过 3 秒。
- 已缓存商品切换：目标低于 300ms。
- 未缓存素材首次可编辑：正常本地或网络条件下目标低于 2 秒。
- 画布拖动：目标 60fps。
- 自动保存：不阻塞交互。
- 本地 `2000×2000` 渲染：排除远程下载和发布，P95 目标低于 1.5 秒/张。
- 批量并发：默认 2–3，按本机资源固定上限，不无限并发。
- 首张完成图：目标 5 秒内出现。
- 100 张正常网络批量完成：目标 3 分钟内。

性能策略：

- 批量导入不预下载全部高清素材。
- 只预加载当前项和下一项。
- 素材按内容哈希缓存。
- 相同渲染版本复用结果。
- 渲染和发布异步执行，用户可以继续编辑或切换模块。

## 19. 主题与响应式

- 页面复用现有 `classic`、`sunset`、`violet`、`diamond` 主题变量。
- 不在尺寸画布 CSS 中硬编码品牌色。
- 工具按钮、队列状态、警告、弹窗、选中态和焦点态均使用主题语义变量。
- 主题切换只影响操作界面，不影响导出商品图片。
- 桌面优先；窄屏时右侧队列收为抽屉，顶部素材区横向滚动，画布保持可缩放。
- 不允许页面级横向溢出。

## 20. 兼容与迁移

- 新表通过独立数据库迁移创建，不修改历史任务结果。
- 现有 `preview_overrides_json` 保持读取兼容。
- 新尺寸画布写结构化槽位补丁，不回写完整图片数组。
- 历史任务首次导入时构造图片角色兼容视图，不重写历史 JSON。
- 现有物流字段导出行为保持不变。
- 产品处理提示词只移除 AI 尺寸文字职责，不增加调用次数。

## 21. 测试与验收

### 21.1 后端合同测试

- 商品本体尺寸与物流尺寸严格隔离。
- 单项和批量导入复用同一项目。
- 100 条乱序、跳过和重复 SKC 时按稳定身份回写。
- 结构化槽位补丁只改变目标槽位。
- 四宫格总览和其他图片保持不变。
- 预检版本一致、可合并和冲突三种路径。
- 自动保存版本冲突及旧响应禁止回写。
- 渲染、发布和交回幂等。
- 部分失败不影响其他项目。

### 21.2 渲染测试

- 归一化坐标在不同预览尺寸下输出一致。
- 长、宽、高数值更新后文字同步。
- `2000×2000` 输出可解码、非空白。
- 数字、单位、双箭头完整且未越界。
- 中文商品数据不会污染尺寸文字。
- 低分辨率素材显示警告，但渲染不伪造细节。
- 固定字体在不同 Windows 环境输出一致。

### 21.3 前端测试

- 素材选择与目标槽位相互独立。
- 点击尺寸后拖动两点创建语义标注。
- 撤销、重做、删除和端点拖动。
- 自动保存恢复。
- 右侧区域滚轮切换，画布区域不误切。
- 部分批次交回。
- 通知、差异预览、批量接受、单项拒绝和冲突展示。
- 四套主题及桌面、窄屏布局。

### 21.4 业务验收样本

- 至少 100 个不同品类商品。
- 包含缺尺寸、单字段尺寸、多规格冲突、低分辨率素材、历史任务和已有尺寸图。
- 人工确认所有完成图数值等于确认后的结构化字段。
- 回写后逐项比较图片列表，除目标槽位外零变化。
- 无新增付费模型调用记录。

## 22. 实施分层

实现计划应拆为四个可独立验证的阶段：

1. 数据合同与迁移：本体尺寸、图片角色、预检版本、画布表和槽位补丁。
2. 单商品闭环：预检入口、画布编辑、后端渲染、单项交回与接受。
3. 批量闭环：任务导入、右侧队列、自动保存、并发渲染、持久通知和部分接受。
4. 兼容与质量：历史任务映射、四主题、性能预算、100 商品乱序验收。

每个阶段必须保持产品处理原流程可用。尺寸画布为可选后处理模块，未使用时不得改变现有最终版导出。

## 23. 停止条件

出现以下任一情况时停止实施并回到设计或数据核对：

- 无法可靠区分商品本体尺寸和物流包裹尺寸。
- 现有任务无法提供稳定的 `task_item_id + product_draft_id` 身份。
- 槽位补丁会改变未选择图片或四宫格总览。
- 渲染需要新增模型调用才能达到基本可用。
- 100 商品乱序测试出现任意串图。
- 自动保存存在旧响应覆盖新状态。
