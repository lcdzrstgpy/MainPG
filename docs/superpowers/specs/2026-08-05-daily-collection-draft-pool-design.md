# 每日采集草稿池分流设计

**状态：已确认**
**范围：采集入库至产品处理；不包含点小蜜上架。**

## 目标

将每日采集结果统一写入一个物理草稿池，并以来源视图区分网页手动采集与万邦 API 采集。两类草稿复用同一套去重、图片同步和产品处理能力。

## 范围内流程

```text
Temu / 1688 网页手动采集
  -> 网页手动草稿视图
  -> 产品处理

万邦 API（关键词 / 参考图 / 1688 链接图搜）
  -> API 草稿视图
  -> 产品处理
```

点小蜜上架及其状态、接口、文件格式均不在本次变更范围内。

## 数据模型

`product_processing_drafts` 保持为唯一物理草稿表。草稿来源由既有的 `source_type` 字段标识：

| source_type | 含义 | 写入时机 |
| --- | --- | --- |
| `web_manual_capture` | Temu 或 1688 网页手动采集 | 插件当前页、批量采集或 `temu_link_capture` 成功后 |
| `onebound_api` | 万邦 API 采集 | 万邦 API 返回候选后立即入库 |

保留 `source_ref` 作为规范化来源链接，`selection_run_id` 仅用于 API 候选批次追溯。平台、采集模式和原始供应商图片 URL 保存在草稿原始载荷中；例如平台为 `temu` / `1688`，模式为 `keyword` / `image` / `1688_link`。

草稿去重继续基于工作区和候选标识；插件草稿使用平台与规范化来源链接生成稳定候选标识，API 草稿沿用每日选品候选标识。重复写入返回原草稿而不创建第二条记录。

## 入库适配

### 网页手动采集

`/plugin/product-capture/draft` 将插件产品转换为 `web_manual_capture` 草稿。

`temu_link_capture` 成功回传至 `/plugin/result` 后，服务端从结果中的已规范化产品载荷创建同类型草稿，并使用同一来源标识去重。命令结果仍保留用于采集状态和排障，但不再是唯一落点。

### 万邦 API 采集

关键词、参考图和 1688 链接图搜生成的每个候选立即创建或更新 `onebound_api` 草稿，并带有对应 `selection_run_id`。`daily_selection_runs` 只保存采集批次、筛选依据和审计信息；它不是另一套候选实体或草稿池。

用户在 API 草稿视图勾选商品后进入产品处理。现有确认动作如保留，只表示草稿已被选择进入产品处理，不能决定是否创建草稿。

## 图片策略

图片不以数据库 Blob 形式保存。每个草稿保留：

- 原始主图与详情图 URL，作为来源证据和重新同步依据；
- 受控文件存储中的本地路径或资产引用；
- 同步状态：`pending`、`ready`、`failed`；
- 失败原因和可重试信息。

草稿创建成功后异步同步主图及详情图。页面和产品处理优先使用已落盘的受控图片；同步未完成时显示“同步中”，失败时显示“待补齐”并允许重试。图片同步失败不得回滚已创建草稿，也不得阻塞其他草稿处理。

## 产品处理界面与接口

产品处理模块注册到本地应用，并提供草稿列表读取接口的 `source_type` 筛选。前端提供三个来源视图：

- 全部草稿；
- 网页手动采集；
- 万邦 API 采集。

每条草稿显示来源标签、平台、来源链接、API 采集模式（如适用）和图片同步状态。无论来源，用户进入产品处理后的操作和处理任务完全一致。

## 错误处理与可观测性

- 插件会话失效、采集失败或结果不完整：命令显示失败原因，不创建不完整草稿。
- 草稿创建成功但图片同步失败：保留草稿和原始 URL，标记失败并可重试。
- 重复来源或重复候选：返回已有草稿及其当前图片状态。
- API 草稿写入失败：采集批次保留失败原因，已写入的其他草稿不回滚。

## 验收标准

1. Temu 和 1688 网页采集成功后可在“网页手动采集”视图看到草稿。
2. 万邦 API 的关键词、参考图、1688 链接图搜结果会立即进入“万邦 API 采集”视图。
3. 两个视图的数据来自同一张物理草稿表，跨来源去重和产品处理规则一致。
4. 每个草稿保留来源图片 URL，并显示本地图片同步状态；图片同步失败可单独重试。
5. 本次没有新增或修改点小蜜上架功能。
