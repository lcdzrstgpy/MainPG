# 积分扣费逻辑整理 + 价格倍率功能设计（2026-09-09）

## 一、现有扣费链路（客户端上报 → 服务器计费）

```text
用户工作台客户端（wh_local.remote_client）
   │ ① POST /api/customer/billing/batch/freeze   （冻结 N × 每链接价值，锁定积分）
   │ ② 客户端直连第三方 AI 处理（灰度直连 / 网关代理）
   │ ③ POST /api/customer/billing/batch/settle   （上报每条链接的子项状态）
   ▼
服务器计费服务（8011 customer-auth，wh_local.billing / pod_billing）
   │ 按「服务器已存定价」计算实扣：成功全额、拦截按比例、无返回全退
   │ 扣 费：钱包 points_balance −= 实扣；释放剩余任务锁定 locked_points −= 冻结
   ▼
customer-auth.sqlite3
   billing_wallets / billing_batch_freezes / billing_batch_items /
   billing_point_ledger / billing_pricing_rules / billing_pricing_items /
   billing_multiplier_rules（新增）/ billing_multiplier_changelog（新增）
```

- 计费只认**服务端定价**（`billing_pricing_rules` + `billing_pricing_items`），客户端只上报
  子项状态（success / intercept / no_return），不能自报金额。
- 冻结（预扣）：按 `每链接价值 × 链接数` 锁定到钱包 `locked_points`；余额不足 402。
- 结算：按冻结时 `rule_version` 的子项单价计算，成功全额、intercept 按
  `intercept_refund_ratio` 部分退、no_return 全额退；重试溢价 10 积分/链接（额外扣费）。
- TTL 兜底：2 天未结算的批次由服务端清扫（退回 85%，15% 留存）。

### 定价结构（基准价）

| 计费口径 | 基准 | 说明 |
|---|---|---|
| **AI 处理**（product_processing） | 单条链接 35~45 积分（默认 45，子项合计） | 子项：title / description / product_dimensions / four_grid / detail_images 各自定价，按子项状态折算 |
| **POD 定制**（pod_random_v1） | 单款式 40~50 积分（服务器随机） | 图片（四宫格）为计费锚点；标题免费；付费重试按款式价 |

## 二、价格倍率（单条价值可调）设计

管理员可在后台 **「积分与消费 → 价格倍率」独立页面**直接设置两套口径的**单条价值**：

- AI 处理：`单条商品链接价值`（整数积分，如 48 = 45 基准 × 107%）
- POD 定制：`单款式价值`（整数积分，如 60 = 45 基准中值 × 133%）

### 存储

```sql
billing_multiplier_rules (category='ai'|'pod')
  points_per_unit     INTEGER   -- 单条价值（积分）；NULL = 基础定价（保持默认行为）
  multiplier_percent  INTEGER   -- 派生倍率 %（= round(单条价值 × 100 / 基准)），用于图表与审计
billing_multiplier_changelog
  category/before_percent/after_percent/before_points/after_points/changed_by/change_reason
billing_batch_freezes.multiplier_percent / points_per_unit   -- 冻结时快照列
```

### 计费规则（关键）

1. **冻结时快照**：`freeze` 时把当时的倍率/单条价值写入冻结记录；`settle` 按快照结算。
   → 调整倍率只影响**之后新冻结**的任务；已冻结任务按冻结时倍率结算，不会出现
   结算金额超出冻结上限的竞态，也杜绝中途调价套利。
2. **固定单条价值模式**（points_per_unit 非空）：
   - AI：每条成功链接固定扣 X 积分；拦截/无返回按子项基准占比（最大余数法）精确分摊
     后按比例退款，分摊总和恒等于 X × 链接数。
   - POD：每款式固定 X 积分（不再随机 40-50）。
3. **基础定价模式**（points_per_unit = NULL，默认）：维持现有行为
   （AI 按子项定价、POD 随机 40-50）；若曾通过倍率%调整，再按倍率缩放。
4. **倍率% 与单条价值互转**：输入倍率时 `单条价值 = round(基准 × %/100)`；
   输入单条价值时 `倍率 = round(价值 × 100/基准)`。恢复基础定价（reset）= NULL + 100%。
5. 旧版单次 reserve/settle 链路（`_pricing`）：reserve 时按当前倍率缩放并写入事件
   `server_pricing` 快照，结算按快照执行，口径一致。

### 生效范围与提醒

- 页面明示：调整只对新冻结任务生效；已冻结任务按冻结时快照结算。
- 每次调整必须填写原因，写入 `billing_multiplier_changelog` 审计（不可删改）。

## 三、后台页面（价格倍率调整 / 可视化）

导航：`💰 积分与消费 → 价格倍率`（`/admin/` 8012）

- 两个大卡片（AI 处理 / POD 定制）：当前单条价值、基准价值、派生倍率、
  更新时间/操作人/变更原因；快捷倍率按钮（80%~120%）、单条价值输入、
  「应用」「恢复基础定价」。
- 折线图：倍率历史走势（Chart.js，AI/POD 双系列）。
- 基准定价预览：AI 子项表 + POD 款式口径（默认 vs 当前）。
- 变更记录表：时间 / 类别 / 单条价值（前后）/ 倍率（前后）/ 操作人 / 原因。
