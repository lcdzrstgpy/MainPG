# 轮播图导出回退源图 · 探针结论

日期：2026-09-11
范围：`web-frontend` / `local-runtime`（分支 `bigdogbujiao`，HEAD `79169529`）

## 一、怎么跑的

- 探针：`outputs/probe_export_carousel_fallback.py`（纯函数探针，不碰 DB），直接调 `workbooks._dxm_single_export_row`。
- 列索引：8=预览图，18=`*轮播图`，19=`*产品素材图`。
- 运行时：项目内置 `local-runtime/python-runtime/python.exe`（系统 Python 3.13 无 fastapi，跑不起来）。
- 原始输出留存：`outputs/probe_out.txt`。

## 二、唯一出口

导出时「轮播图」列只有**一条**路径会落到来源原图 —— `domain/workbooks.py:398-404` 的 `else` 分支。命中需同时满足：

1. 无 `image_slot_overrides`（非新版尺寸画布单槽覆盖）
2. `_http_urls(carousel_images)` 为空
3. `_http_urls(carousel_image_paths + grid_image_summary_path)` 为空 —— 生成图不存在，**或全是本地/相对路径**（COS 未配置）

该分支一次性决定三列：

| 列 | 取值 |
|---|---|
| `*轮播图` | `_http_urls(source_image_urls)` → 来源原图 |
| `*产品素材图` | 来源详情图首张 |
| 预览图 | `image_url`（若为 http），否则来源首图 |

## 三、三组实测

| 场景 | 轮播图 | 素材图 | 预览图 | 判定 |
|---|---|---|---|---|
| A 显式清空 `carousel_images: []` | 来源原图 ×2 | 来源详情图 | generated-main.jpg | ❌ 回退 |
| B 保留 1 张 | published.png | published.png | published.png | ✅ |
| C 无预检覆盖 | 来源原图 ×2 | 来源详情图 | generated-main.jpg | ❌ 回退 |

**A 与 C 输出完全一致** → 空数组被当成「未设置」。

## 四、代码层面两处不对称

1. **carousel 缺存在性语义**：`workbooks.py:389 elif override_carousel:` 与 `image_slots.py:57 if isinstance(legacy, list) and legacy:` 都是真值判断，`[]` 直接穿透到下一档。
   对照组：`detail_images` 有存在性判断 —— `workbooks.py:409-413` `if "detail_images" in preview_overrides`，注释明确写着「Presence is semantic：显式空数组表示操作员删光了，绝不能复活旧值」。
2. **写入侧会丢弃空数组**：`service.py:4145-4148 _clean_preview_overrides` 对 `carousel_images` / `detail_images` **一视同仁**地过滤空值，`if values:` 才写入。所以 `detail_images` 的存在性判断在 API 路径上其实打不到（键根本落不了盘），A 组只能来自历史遗留 JSON。

## 五、A 路径当前不可达（重要）

- v2 manifest 模型 `domain/preview_images.py` 的 `__post_init__`：carousel 为空且有 main 时强制 `carousel = (main,)` → **UI 层无法表达「轮播图清空」**。
- 预检/入库导出路径 `preview_image_service.py:1551-1572` 会把 manifest 物化成 legacy http URL，并 `require_final_public_image_urls()` **fail-closed 抛错**，不会静默降级。
- 当前 UI 提交的是 `image_manifest_v2`（`PreviewDesiredState.image_manifest_v2` 为必填），legacy 三字段仅作兼容读取。

结论：**A 属「死代码级」语义缺口，不是线上可复现 bug。**

## 六、线上真实缺口 = C 组

生成图全是本地路径（COS 未配置 **且** 未设 `WH_MEDIA_BASE_URL`）+ 无预检覆盖 → 直接导出任务结果时静默回退来源原图：

- `four_grid` 仍是 `success`、对外 `image_ai_failed=false`
- 计费按成功**全额扣**，但用户拿到的是来源原图（无标记、无退款）
- `service.py:7122 _note_media_unconfigured()` 全仓仅此一处定义、**无人调用**（死代码）

与 2026-09-10 排查的「路径 3」结论一致，本次由探针复现确认。

## 七、一个未验证的残余

物化路径（`preview_image_service.py:1551-1572`）里 carousel 可能为空（main 走 `_source_main_fallback` 来源兜底），此时若落到 `workbooks` 的 `else` 分支，轮播图会取来源原图。需补 case D 才能确认。

另：该 `else` 分支的预览图取 `image_url`（生成主图），不一定等于来源图 —— 判断「是否泄露来源」时只看轮播图 / 素材图两列更准确。

## 八、建议（待确认，未改任何代码）

| 优先级 | 动作 | 说明 |
|---|---|---|
| 高 | `else` 分支回退时把 `four_grid` 置为 `source_fallback` | 复用现有 `batch_billing.py:185-190` 的 no_return 退费 + 前端「只看失败」筛选闭环，解决「静默」 |
| 中 | 把 `_note_media_unconfigured()` 接到「网格产图后拿不到 http(s)」的分支 | 当前是死代码，用起来即可提示该场景 |
| 低（不建议） | 给 carousel 补存在性判断以对齐 detail_images | UI 已无法产生空数组，改动只有回归风险、没有收益；除非要兼容历史草稿 |

C 组的根因是部署配置（COS / `WH_MEDIA_BASE_URL` 未配），代码侧只能「让静默变显式」，无法凭空产出可访问 URL。
