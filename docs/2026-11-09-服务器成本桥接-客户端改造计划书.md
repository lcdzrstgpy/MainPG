# 服务器成本桥接 · 客户端店铺数据板块改造计划书

- 日期：2026-11-09
- 范围：工作台客户端 ↔ 采集服务器（`/opt/wh-collector`）
- 本轮目标：**只打通桥接链路并做小范围测试**，不做利润核算、不打包客户端
- 相关现状依据：客户端店铺数据板块 `web-frontend/src/modules/order_profit/`，本地服务 `local-runtime/wh_local/modules/order_profit/`

## 1. 目标与边界

| 项 | 内容 |
|---|---|
| 业务目标 | 已签收订单只缺「成本」一项；由客户端使用者为绑定店铺的链接填写成本，回传服务器，服务器后续可据此核算单笔实际利润 |
| 本轮交付 | 服务器成本 API + 客户端绑定/拉数/填成本/提交的最小闭环（测试环境） |
| 明确不做 | 利润计算、成本历史版本、客户端打包发布、断网离线、权限分级 |
| 数据原则 | 客户端**不再直采**，展示数据一律来自服务器；客户端只负责「绑定 + 展示 + 填成本 + 提交改动」 |

## 2. 现状与差距

- 客户端「店铺数据管理」有 6 个子板块（经营概览、订单列表、账户资金、数据采集、入库记录、店铺账号），数据由浏览器插件上报到本地 runtime（`/api/order-profit`），**与采集服务器没有连接**。
- 客户端已有账号绑定能力：以**手机号**为唯一键（`repository.py` UNIQUE(workspace_id, phone)），店铺以 `shop_name` 建店，带 `store_code`/`mall_id`。
- 采集服务器已有：`accounts`（账号+店铺）、`snapshots`（每轮订单列表）、`order_details`（申报价/回款/物流/图片），账号 id 为 UUID。
- 差距：① 两侧账号体系没有映射；② 服务器没有绑定/成本存储与接口；③ 客户端没有「从服务器拉数」的通道。

## 3. 桥接架构（建议）

```
客户端 UI（店铺数据新板块）
   ↓ /api/bridge/*（本地 runtime）
local-runtime 转发模块（持有 bridge key，不向前端暴露）
   ↓ HTTP（服务器内网/白名单）
采集服务器 /api/bridge/*（绑定、拉数、成本读写）
   ↓
sqlite: bridge_bindings / item_costs + 既有 snapshots / order_details
```

要点：前端不直连采集服务器；密钥与 base url 放在 `wh_local/config.py`，与现有 `remote_client.py`、`team_store/client.py` 的做法保持一致。

## 4. 数据模型（服务器新增）

```sql
CREATE TABLE bridge_clients (      -- 测试期最简身份
    client_id TEXT PRIMARY KEY,
    label TEXT,
    created_at TEXT NOT NULL
);

CREATE TABLE bridge_bindings (
    client_id TEXT NOT NULL,
    account_id TEXT NOT NULL,      -- 对应 accounts.id
    created_at TEXT NOT NULL,
    PRIMARY KEY (client_id, account_id)
);

CREATE TABLE item_costs (
    account_id TEXT NOT NULL,
    skc_id TEXT NOT NULL,          -- 商品链接（SKC）
    unit_cost REAL NOT NULL,       -- 单件成本
    currency TEXT NOT NULL DEFAULT 'CNY',
    updated_by TEXT,
    updated_at TEXT NOT NULL,
    PRIMARY KEY (account_id, skc_id)
);
```

成本口径暂定 **按 SKC（链接）单件成本**；若后续要按规格（SKU）细化，`item_costs` 再加 `sku_id` 维度即可，不影响接口形态。

## 5. 接口契约（MVP）

| 方法 | 路径 | 用途 | 关键字段 |
|---|---|---|---|
| GET | `/api/bridge/accounts` | 列出服务器已有账号（供客户端选择绑定），手机号脱敏 | `account_id, shop_name, phone_tail, site, last_captured_at` |
| POST | `/api/bridge/bindings` | 客户端绑定账号 | `client_id, account_ids[]` |
| GET | `/api/bridge/bindings?client_id=` | 回显已绑定店铺 | 同上 |
| GET | `/api/bridge/items` | 拉取绑定店铺的链接级数据 | 入参 `client_id, account_ids, status, date_from, date_to, page, page_size`；出参按「店铺 + SKC」聚合：`goods_name, image_url, skc_id, sku_id, 单量, 申报价合计, 回款合计, 最新状态, 最近下单时间` |
| GET | `/api/bridge/costs?client_id=` | 回显已填成本 | `account_id, skc_id, unit_cost, currency, updated_at` |
| POST | `/api/bridge/costs` | 提交改动（只传变动项） | `client_id, account_id, items:[{skc_id, unit_cost, currency}]`，返回 `applied, skipped` |

约定：
- 鉴权用共享头 `X-Bridge-Key`（测试期），服务端未配置密钥时仅允许 localhost。
- 所有写接口幂等：同一 `account_id + skc_id` 覆盖更新。
- 拉数接口按 `page_size<=200` 分页，避免大店一次返回过多。

## 6. 客户端改造（删繁留简）

新板块只保留 5 个能力，其余子板块先隐藏（验收后再删代码，降低回滚成本）：

1. **店铺绑定**：展示服务器账号列表（店铺名/尾号/站点/最近采集时间），勾选后绑定；已绑定店铺可解绑。
2. **数据拉取**：按绑定店铺拉链接级数据，默认只拉已签收（成本缺口最大的部分），手动切「全部」。
3. **筛选**：店铺多选 + 状态（待发货/已发货/已签收/已取消）+ 下单日期区间 + 关键字。
4. **成本填写**：表格内直接编辑单件成本，记录 dirty 状态，支持批量填充同值。
5. **数据提交**：只提交 dirty 行，按店铺分组调用 `/api/bridge/costs`；成功后清 dirty，失败按行提示。

展示分组：`店铺 → 链接（SKC）` 两级，状态以标签形式落在每行；点击链接可展开订单明细（复用服务器 `order_details`）。

## 7. 实施阶段与验证点

| 阶段 | 内容 | 验证 |
|---|---|---|
| P0 | 服务器新增 3 张表 + `/api/bridge/*`，用 curl 跑通 | 绑定 1 个账号 → 拉数 → 提交成本 → 回显一致 |
| P1 | local-runtime 新增 `modules/bridge`（配置 base/key，转发接口） | 前端接口 200，密钥不出现在浏览器请求 |
| P2 | 客户端新板块（绑定/列表/筛选/成本/提交），旧板块隐藏 | 4 个服务器账号均能绑定并拉到数据 |
| P3 | 联调测试（不打包，本地 vite 起前端） | 见第 8 节验收 |

## 8. 测试验收标准

1. 绑定：4 个店铺全部可绑定；解绑后列表立即消失。
2. 拉数：YWHYTWO（527 单）分页拉全，条数与服务器链接聚合数一致（±0）。
3. 筛选：状态与日期组合结果与服务器 SQL 直查一致（抽 3 组）。
4. 成本提交：修改 5 行 → 只发 5 行；重复提交同一行不产生重复记录；回显正确。
5. 失败恢复：断网/500 时提示明确，dirty 状态不丢，可重试。
6. 数据隔离：未绑定客户端拿不到任何店铺数据。

## 9. 待确认（需要产品/业务拍板）

1. **绑定认证**：测试期用共享 `X-Bridge-Key` 是否可接受？正式期是否要求客户端登录账号（复用工单/授权体系）？
2. **成本口径**：按 SKC 单件成本，还是按 SKU 规格？币种统一人民币还是按店铺站点币种？
3. **成本生效范围**：改成本是否只影响之后的订单，还是允许回算历史已签收订单的利润？
4. **多客户端**：同一服务器账号被多个客户端绑定时，成本以谁为准（后写覆盖 / 只读共享）？

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| 采集服务器无鉴权，暴露成本数据 | 只开 `/api/bridge/*` 且校验 key；nginx 层限制来源 IP |
| 客户端拉数触发服务器压力 | 读接口只查 sqlite + 分页；不触发采集 |
| 成本覆盖历史数据 | P1 只做当前值；版本表留到利润核算阶段 |
| 旧板块删除造成回滚困难 | 先隐藏 tab，验收后再清理代码 |
