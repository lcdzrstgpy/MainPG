# 打包机依赖：必须装 PySide6

> 适用范围：给 MainPG Windows 客户端打包的环境。
> 最后更新：2026-10-21（起因：1.5.8 安装包双击后没有启动卡片）

## 一句话

**打包机、用打包时那个 Python，必须先装 PySide6。** 没装不会让打包失败，但打出来的包
启动时没有卡片画面，用户双击后要白等 2.5 秒才看到浏览器弹出。

## 怎么装

用**跑 PyInstaller 的那个 Python**（不是系统里随便哪个 python）执行：

```bat
python -m pip install PySide6
```

如果机器上有多个 Python，先确认你用的是哪个：

```bat
python -c "import sys; print(sys.executable, sys.version)"
```

输出的路径，应该和你打包命令用的是同一个。

## 怎么验证（**这一步不能省**）

```bat
python -c "from PySide6 import QtWidgets; print('ok')"
```

- 打印 `ok` → 可以打包
- 报 `ModuleNotFoundError` / `DLL load failed` → **别打包**，先修环境

只 `import PySide6` 是不够的。启动卡片实际用的是 `QtWidgets`，它要连 `Qt6Core.dll`、
`Qt6Gui.dll`、`Qt6Widgets.dll` 和 `shiboken6` 一起装载成功才算数。

## 不装会怎样

| 层面 | 现象 |
|---|---|
| 打包过程 | 不报错，照常出包（PyInstaller 对缺失的 import 不报错） |
| 打包日志 | 会打印 8 行 `[workbench.spec] !! PySide6 不可用 ...`，**看到 `!!` 就是没装** |
| 用户端 | 没有启动卡片，双击后白屏等 2.5 秒，然后浏览器才弹出 |

## 打完包自检

1. 打包日志里应该有这一行（不是 `!!` 开头的告警）：
   ```
   [workbench.spec] PySide6 6.x.x 可用（python 3.x.x，QtWidgets 装载成功），启动卡片随包分发
   ```
2. 装到干净机器上双击，确认：
   - 0.5 秒内出现启动卡片（田野背景 + 「界野电商平台」）
   - 有进度条在走、阶段文案在换
   - 后端就绪后卡片淡出，浏览器自动打开
3. 如果卡片没出现，让用户把 `%APPDATA%\MainPG\runtime.log` 发过来，
   里面会有 `启动卡片不可用，回落为延迟开浏览器（原因：...）` 和完整堆栈。

## 常见坑

- **装错 Python**：`pip install` 装进了 A 版本，打包用的是 B 版本 → 白装。用上面的
  `sys.executable` 确认。
- **多版本共存**：用 `python -m pip`（带 `-m`），别直接敲 `pip`。
- **PySide6 版本与 Python 版本不匹配**：`.pyd` 是按 Python 版本编译的（cp311/cp312）。
  换 Python 后必须重装 PySide6。
- **只验证了 `import PySide6`**：会漏掉 Qt DLL / shiboken 的问题，必须验证
  `from PySide6 import QtWidgets`。

## 背景

启动卡片（`local-runtime/launcher/splash_qt.py`）用 PySide6 做桌面浮窗，是启动期间
唯一可见的反馈。它的素材（61 帧田野动画）和模块本身都已经打进包了，**唯一的外部依赖
就是 PySide6 的二进制**，只能靠打包机装。

1.5.8 的安装包里 `PySide6/`、`shiboken6/` 文件都在、`launcher.splash_qt` 也在，
但在用户机器上 `from PySide6 import QtWidgets` 仍然失败，导致卡片静默降级。具体原因
受限于当时没有日志（已修：现在会写 WARNING + 堆栈），需要在打包机侧按上面的验证步骤
确认后再打一版。
