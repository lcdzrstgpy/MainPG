# 本地素材库

在项目的「素材」页展开「本地素材库」，可上传自己的商品图、实拍视频和 B-roll，反复用于该项目的镜头。

## 使用

1. 点击「上传素材」。每次最多 12 个文件，每个不超过 80MB；支持 MP4、WebM、MOV、M4V、JPG/JPEG、PNG、WebP。
2. 上传过程中显示进度和文件检查状态，可以取消上传，或只重试未完成项。相同内容重复上传会复用已有文件，保留已编辑的名称与标签。
3. 点击「名称与标签」整理素材。名称和标签参与搜索与自动配画面；最多 12 个标签，每个 32 字以内。可按图片/视频筛选、按上传时间或名称排序，列表每页显示 12 项。
4. 选择分镜后点击「用于该镜」，将素材设为当前版本。旧候选仍保留，可在质量台切回；合成读取当前选中的版本。
5. 点击「用本地素材补齐空镜」，仅从本项目素材中匹配画面，不调用模型或联网素材源。已选中的完成素材、等待中与生成中的任务，以及商品原图镜头会跳过。失败记录和未选中的历史版本不会阻止补齐。

单镜头的「上传素材/替换素材」也支持上述图片和视频，并自动存入本地素材库。GIF、SVG、BMP 仍使用原有的单镜头图片上传流程，不进入素材库。

## 存储与接口

- 文件位于 `APP_DATA_DIR/uploads/<projectId>/materials/`；未配置数据目录时使用项目的 `data/`。名称和标签保存在同目录的 `.clipforge.json` 元数据文件中，不修改原始媒体内容。
- 新上传文件先流式写入临时文件，按实际字节限制大小，经媒体探测检查格式、尺寸和视频时长后，以内容哈希命名保存。请求取消或失败会清理本次临时文件。
- 手动放入目录的旧图片和视频仍可读取并添加名称、标签；没有元数据时按原文件名搜索。符号链接、临时文件和自动提取的尾帧不列入素材库。
- `GET /api/project/<id>/materials` 返回素材及预览地址；`PATCH` 接收 `{ name, originalName, tags }`，其中 `name` 为返回的实际存储文件名。
- `POST` 推荐每次发送一个文件：`Content-Type: application/octet-stream`，`X-File-Name` 为 URL 编码的原文件名，请求体直接使用文件字节。成功返回 `materials` 和 `duplicate`。
- 兼容旧的 multipart `files` 字段（1–12 个文件，合计不超过 80MB）。部分文件校验失败时返回 HTTP 207，分别列出已保存的 `materials` 和失败的 `errors`；调用方应检查两者后再重试。

上传、标注和仅本地补齐不会产生模型费用。素材不足或画面不合适时，可补充素材后重新选择镜头。
